## 0. 一句话结论

**骨架是有的（统一变更通知 + 区域订阅 + 缓存优先 + 60 秒兜底），但四处漏水**：① **默认首页整块显示示例数据且永不刷新**；② 变更通知**一轮最多 200 条却把游标直接跳到最新编号 → 批量操作时静默漏刷**；③ **2.5 秒抑制窗口会吞掉真实的同任务后台变更**；④ **60 秒无条件全量刷新所有已打开页面**（慢机器上就是周期性卡顿）。此外**前端零自动化测试**，这是大修最大的风险。

## 3. 漏刷 / 重复刷风险（大修要对着改的地方）

**漏刷（4 处）**
1. **游标跳号（最严重）**🔍：`limit=200` 但 `cursor` 直接取 `MAX(id)` → 1.5 秒内产生 >200 条变更时，第 200 条之后的**永久跳过**（只能等 60 秒兜底）。
2. **2.5 秒抑制窗口吞事件**🔍：客户端自己写完后 2.5 秒内，**同一任务**的真实后台变更被丢弃。
3. **页面隐藏期间完全不轮询**🔍：最小化期间只靠恢复时补拉一次。
4. **区域白名单是硬编码**🔍：task_center 不收 `material_changed`/`release_changed`；analytics 不收账号/剧集变更。

**重复刷（4 处）**
1. **60 秒无条件全量刷新所有已打开页面**🔍（`dataRefreshCoordinator.ts:63-65`）。
2. 一次写入被多个页面各自全量读取（Header + 生产中心 + App）。
3. `origin:'client'` 即时通知 + 迟到 >2.5 秒的数据库"回声" = 刷两次。
4. 生产中心自身 5 秒详情轮询叠加 60 秒兜底。
5. （审计补充）生产任务摘要接口**内部会做目录遍历 + 逐文件 `is_file()`**（`server/v2_file_service.py:2811,2669-2674,2693`），并不是轻量接口，却被 5 秒/60 秒反复调用。

## 6. 可疑点排序（审计给出，按"最可能让用户觉得刷新/加载有问题"）

1. 🔍 **默认首页的"昨日总营收 / +18.4%"是 mock 求和且永不刷新**。
2. `App.tsx:62,65`：工作台排期/剧集预测是写死数组，只在本地追加、**从不从后端读回** → 与生产中心必然对不上。
3. 🔍 **游标跳号漏刷**（见 §3-1）→ "明明干了活界面不变"。
4. 🔍 **2.5 秒抑制窗口**（见 §3-2）→ "刷新不及时"。
5. 🔍 **大面积空 catch**（`Header.tsx`、`ProductionCenter.tsx`、`dataChangeFeed.ts`）→ 服务抖动时**界面无任何提示**。
6. 🔍 **5 秒详情轮询 + 60 秒全员全量 + 摘要接口其实做文件遍历** → 慢机器上"一直转圈"。
7. `revenueAnalyticsService.ts:85`（in-flight 请求**不区分筛选条件**）→ 快速切时间范围/剧场时，可能把旧范围数据贴到新筛选下。
8. `AssetsCenterView.tsx:99-102` 收到 `resource_changed` 又去调 `GET /production-resources`，**没有 Header 那样的 10 秒防抖** → 理论上会自激刷新。
   （**2026-09-18 沙箱实测旁证**：单次打开资源页面稳态写 0 条，未复现自激；但若存在"探测始终不成功"的资源，理论上仍可能自激——**未验证**。）
9. `assetsCenterService.ts:143` + `ViralAssetsTab.tsx:762`：爆款资产恒为空，空态却提示"调整筛选条件"。
10. `AssetsCenterView.tsx:258-266,277`：生产资源/爆款资产**只写本地 state**，切页签即丢。
11. `App.tsx:93` + `ScheduleModal.tsx:91,112`：工作台剧集列表只在启动时读一次 → "安排今天"看不到新剧集。
12. `DataAnalyticsView.tsx:38-42`：切顶层页签会卸载组件 → 回来时筛选被重置（看起来像"刷新失败"）。
13. `DataAnalyticsView.tsx:62`：微信指数子页不参与统一刷新订阅。
14. `SettingsView.tsx:107-129`：设置只读一次、不订阅刷新；与 `App.tsx:121` 各读一份 → 改完不同步。

## 7. 大修时怎么用这份文档

1. **先对照规则**：把本文 §2/§3 与 `docs/功能档案/04-跨模块规则/数据与刷新.md` §11（统一通道 + 四层读取 + 各模块精准刷新）、§12（频率与并发）逐条对照，产出"规则 vs 现状"缺口表。
2. **按规则 §13 的施工顺序推进**（不要跳步）：统一变化消息 → 生产中心按任务更新 → 任务中心按 task_id → 资料中心按对象 → 收益中心按范围 → **把各页重复的计时器收拢到统一缓存层** → 做重启/切页/任务执行/失败恢复/服务断开的验收。
3. **每阶段用规则 §14 的 8 个问题自查**（打开页面是否先见旧内容、失败是否保留旧数据、改一个对象是否只更新该对象…）。
