# V3 数据分析模块｜给 GPT / Gemini 的沟通方向

请根据配套的 `V3分析底座-原始数据样例.json` 理解短剧推广运营系统的数据，再自行设计一个专业、实用的数据看板界面。

这份文件只说明业务背景和数据事实，不规定页面布局、卡片数量、颜色、图表类型或交互方案。请先分析原始数据的真实字段和粒度，再决定哪些内容适合放在首页、哪些内容适合下钻。

## 业务背景

这是短剧推广运营系统。账号来自视频号平台，数据由小V猫从视频号官方后台获取并保存到 V3。账号会频繁新增和退出，账号不是长期经营资产，但也不要把整个页面做成账号生命周期看板。

剧场收益来自各剧场自己的查询方式。不同剧场返回的数据不一致：有的按日期返回明细，有的只有月份累计金额，有的能返回视频/剧名/播放，有的只能返回金额。已结算月份不进入当前收益分析。

## 必须尊重的数据事实

- 视频账号日数据和视频作品日数据是两个不同数据粒度。
- 视频作品原始返回中的 `title` 当前为空或 null，不能生成作品标题、集数标题、台词标题或剧名标题。
- 视频作品里的 `account` 是投放账号，例如“某某短剧”；界面需要按投放账号理解和呈现。
- `post_id` 是平台作品记录 ID，只能作为记录标识。
- 不要把账号播放和作品播放相加。
- `record`、`zero`、`missing`、`failed` 必须保持不同含义。
- 收益的 `day`、`month_cumulative`、是否有明细、是否已结算必须保持不同口径。
- `simulation_ui` 是为了做界面演示的模拟收益和模拟视频结构，必须和 `xiao_v_cache` 的已保存小V猫快照区分。
- `legacy_v2` 历史收益不能直接当成当前真实收益。

## 希望界面帮助回答的问题

请从数据本身判断适合回答哪些问题，重点围绕：

- 所有账号昨日和一段时间内的整体表现
- 流量、涨粉、互动之间的变化
- 昨日收益、本月当前可计收益及变化
- 不同剧场收益的来源和返回粒度
- 每个投放账号表现最好的作品记录
- 全部投放账号的作品记录排名
- 哪些数据完整，哪些数据缺失、失败或明确为 0
- 点击一个账号、作品记录或剧场后，应该还能看到哪些原始字段和趋势

## 交付方式

请先输出：

1. 你从原始数据中识别出的数据实体和字段
2. 你认为首页应该回答的核心问题
3. 首页、分析页、详情页之间的信息分层
4. 一张页面线框或界面草图
5. 每个图表和指标使用了哪些原始字段

确认数据理解正确后，再生成 UI。不要为了让页面看起来完整而补造作品标题、剧名、投放关系或收益明细。
