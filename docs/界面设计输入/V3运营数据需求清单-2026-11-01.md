# V3 运营数据需求清单

日期：2026-11-01。状态：需求讨论稿。

本稿按现有经营总览、账号矩阵、账号优化、作品表现、数据导出及资料中心梳理需要的数据，不由已有采集接口反推需求。先明确字段、用途、粒度、关联和缺失处理，再决定获取方式。本次不改程序、数据库、采集任务或正式功能规则，也不执行清库。

## 一、三类数据分开列

1. **原始事实**：账号总量、每天的流量、作品指标、收益金额、平台作品分析等。需要保留它实际代表的对象、日期、范围及原文。
2. **本地档案与关联**：剧场、账号归属、业务状态，以及平台作品和本地文件/剧集的对应关系。这些不应由外部昵称、分组或文件名猜出来。
3. **计算结果**：收益等级、阶段、视频流量标签、各类比例、排名和汇总，由前两类计算，不作为需要外部提供的原始字段。

下文“首批必需”表示现有界面正常工作需要这个数据项；缺失时应明确未知，不能为了凑齐界面填模拟值。“可后补”表示不阻塞首批接入，真实结果如果已经包含，仍应保留。

## 二、首批需要的数据

### 1. 剧场档案

粒度：一个剧场一份档案。

| 字段 | 用途与约束 |
|---|---|
| V3剧场ID、剧场名称 | 关联账号、作品和收益；改名不应导致历史记录丢失关联 |
| 启用/停用状态 | 剧场筛选与启用剧场数量 |
| 默认分成比例、税率 | 保留现有资料中心档案；不因此擅自再次扣减外部已经结算过的收益 |

剧场名称不能替代唯一ID。先不把查询地址、接口类型、登录方式列为本轮数据需求结论，后续确定采集方案时再补来源配置。

### 2. 账号档案与身份对应

粒度：一个V3账号一份档案。

| 字段 | 用途与约束 |
|---|---|
| V3账号ID | 所有经营记录的内部关联标识 |
| 视频号ID、平台账号唯一标识 | 分别保存实际含义，不预设不同来源中的账号ID必然相同 |
| 外部工具账号标识（存在不同标识时） | 对应到同一个V3账号，不能用昵称关联 |
| 昵称、头像 | 账号显示；保留更新时间，头像可有本地缓存 |
| 所属剧场ID | 用户已确认：同一个视频号固定属于一个剧场，不发生正常业务换绑；后续作品、流量及收益通过账号唯一标识关联，不按昵称猜归属 |
| 账号业务状态 | 正常、观察、限流、二限、实名、封禁、停用、注销 |
| 可确认的起用/试投起点 | 为试投观察提供依据；未知时留空，不拿导入时间冒充 |

“账号业务状态”和“平台登录是否有效”分开。登录失效不自动等于封禁、停用或注销。

2026-11-01逐项确认：用户明确同一视频号不会从一个剧场换到另一个剧场，因此本需求不设计常规跨剧场迁移。只读核对当前39个账号：昵称及视频号ID均非空、视频号ID无重复、所属剧场均有效；29个账号有可用本地头像，其余保留无头像状态。这一步确认已有档案及业务关系，没有锁定编辑界面、修改账号或写入经营数据。

后续追查发现，以上只说明字段和关联在结构上完整，尚不能证明账号当前剧场归属符合真实业务。此前视觉替换工具`tools/bind_operations_visual_assets.py`为了保留模拟剧场分布，会更新部分真实账号的剧场ID。当前101条制作任务均可对应账号，100条可对应同剧场剧集，1条不一致：账号“嘟嘟优米”当前为爱看剧场，其旧任务“三万六的宴一元结全家脸都绿了”对应剧集档案为青柠剧场。昵称/ID/头像可复用，现有剧场归属需先按真实业务核准，不能依据旧任务或模拟分布自动调整。当前优先确认账号库归属是否已被人工校准；未改业务库。

用户随后明确：“不用管”“真实运行的时候不会的”。因此以上开发模拟/旧记录冲突只保留为调查说明，不继续追查、清理或要求人工核准，也不作为当前需求的阻塞。正式运行按用户确认的固定归属关系设计；本地现有档案字段和关联能力可复用，不把测试内容的实际值当成正式业务依据。

### 3. 账号当前总量快照

粒度：一个账号在一个更新时间的总量。

| 首批必需字段 | 用途 |
|---|---|
| 账号ID、快照时间 | 说明这份总量截至何时 |
| 官方总视频数 | 昵称下方“视频”；不能用本地已取得作品条数替代 |
| 关注者总数 | 昵称下方“关注者”；与净增关注分开 |

可后补：官方累计总播放等平台确实提供的总量。不能把一段时间合计或当前已保存记录之和直接称为官方全部历史总量。

### 4. 账号每日数据

粒度：一个账号 × 一个统计日，统计日按北京时间。

| 首批必需字段 | 用途 |
|---|---|
| 账号ID、统计日 | 昨日四项、区间汇总和趋势 |
| 当日新增播放 | 账号区间播放、收益与播放趋势 |
| 当日净增关注 | 昨日净增关注、区间新增关注；允许负数 |
| 当日新增爱心 | 昨日新增爱心、账号互动明细 |
| 当日新增评论 | 昨日新增评论、账号互动明细 |
| 数据更新时间、是否已确认/完整 | 判断昨日是否真正更新，不把请求成功直接当作数据已发布 |

可后补：当日关注者总数、新增关注、取关、转发、点赞、收藏、主页访问。爱心和点赞必须先明确各自含义；来源只提供其中一项时，另一项留空，不互相填充。

历史播放若由日记录合计，必须同时知道已保存日期范围与缺失日期；缺一段历史不能靠平均值补齐，也不能冒称完整历史播放。

### 5. 作品基础资料

粒度：一个账号发布的一条平台作品。

| 字段 | 用途与约束 |
|---|---|
| V3作品ID、所属账号ID | 本地关联 |
| 平台作品唯一标识 | 反复更新同一作品；外部工具记录ID、平台ID或导出ID不同则分别保存并建立对应 |
| 实际发布时间 | 发布作品数量、作品时间筛选、观察12小时/24小时等规则 |
| 平台发布状态 | 区分已发布、排期、删除等实际返回状态；排期作品不提前算已发布 |
| 平台封面、观看/分享地址 | 真实封面和作品定位；失效与未返回要能区分 |
| 平台标题/描述（允许为空） | 原样保留；不存在时不生成剧名代替 |

视频时长、原始发布时间格式等有返回时保留。作品从一次返回中消失，不能直接推断已删除，需有明确状态或覆盖证据。

### 6. 作品累计表现快照

粒度：一条作品 × 一个指标更新时间。

首批必需：作品ID、账号ID、指标更新时间，以及**累计播放量、完播率、爱心数、评论数、转发数、点赞数**。

用途：作品卡片、表格、详情、排序与流量标签。数据必须说明是累计值；选某个发布时间区间，表示筛选该区间发布的作品，不代表这些累计指标全发生在该区间内。

完播率需明确单位是0—1还是0—100，以及分母口径；没有值不能显示0%。作品累计播放不能与账号当日新增播放混加。视频观察期判断同时需要实际发布时间和有效指标更新时间。

可后补：平均观看时长、收藏、作品带来的关注、播放时长等。

### 7. 账号收益与统计周期

粒度：一个账号 × 一个剧场 × 一个明确的收益统计周期。

| 字段 | 用途与约束 |
|---|---|
| 账号ID、剧场ID、来源记录标识 | 关联、去重、追溯 |
| 收益所属日或周期起止 | 能按日才按日；月累计、区间合计、截至某日累计分别保存 |
| 周期类型及日期精度 | 不把月累计拆成每天，不把读取当天当成收益所属日 |
| 收益金额、币种 | 使用可精确到分的金额；缺失不补0 |
| 来源金额的业务含义 | 广告收益/佣金、预计/已确认、是否已扣分成税费等已知含义；不重复折算 |
| 数据是否已发布/确认、数据截至日 | 支撑待更新/已更新及延迟出数 |
| 实际查询时间、查询结果与原因 | 保留最近一次尝试，并与最后成功金额分开 |
| 结算状态（能够确认时） | 历史成绩保留及后续对账；未知状态不能擅自写成未结算或已结算 |

收益延迟到下午或更晚才发布，不影响其所属日期。历史总创收必须去除日/月/累计重叠；若只能取得部分历史，要保留覆盖范围或明确的初始累计依据。区间创收、历史总创收与可提现金额不能互相冒用。

### 8. 作品优化原始通知

粒度：一条作品的一次可识别的平台通知/分析记录及其后续变化。

| 字段 | 用途与约束 |
|---|---|
| 账号ID、作品ID或可对应的异常作品标识 | 精确定位；无法对应时保留未关联记录 |
| 平台“作品分析”完整原文 | 五类暂行标签映射的依据；不能用分类模板覆盖原文 |
| 优化建议、平台处理结果原文（有则保留） | 与作品分析分开，不混成同一字段 |
| 原通知时间（有则保留）、首次发现时间、最近核对时间 | 通知发生时间与系统发现时间分开 |
| 当前是否仍有效/已解除/未知（能确认时） | 未再次返回不自动等于解除 |
| 优化检查结果是否完整 | 未获取不等于没有优化，不能默认健康 |

当前映射标签仍为多次发布、引导优化、羊头链接、未挂链接、原创优化，匹配不上为待归类。映射规则应留版本及依据，原文修订后可以重新归类。当前一作品一个展示标签的安排保留，同时记录原文更新历史；重复查询同一通知不增加优化作品数。

平台明确提供严重程度时才记录，未提供为未知/未判定，不由简化标签推测。发现时播放量只有当时有效快照可用才保存，不能用后来上涨后的累计播放倒填。

### 9. 平台作品与本地发布记录的关联

粒度：一次本地发布与平台最终作品的对应。

用户逐项确认：同一部剧不会同时出现在多个剧场，因此剧集主档固定归属一个剧场，保留已有剧集ID、剧名、所属剧场及封面关联，不设计一部剧跨多个剧场的正常业务关系。2026-11-01只读检查现有568条剧集档案：名称均非空、剧场关联有效、同剧场及跨剧场均未发现重复剧名，外部目录关联也未发现同一来源剧集绑定多个剧场。现有282张可用封面可沿用；没有封面的档案继续保留缺失状态。本次只确认需求和检查数据，未修改档案或媒体。

用户进一步确认：同一个本地成片不会发到不同账号，因此本地成片固定归属一个账号。软件已有同一成片发多份的能力，每次发布应保留独立记录，不能把同一文件名当成单条平台作品的唯一标识。只读盘点的3份发布执行文档中，部分旧记录仅有视频路径而没有成片ID，后续需要核对关联，不能把提交状态或计划时间当成真实发布成功与实际发布时间。

首批需要建立：**账号ID、平台作品标识、本地成片ID/文件名、剧集ID/剧名、切片编号、发布任务/发布记录标识、关联是否已确认及确认依据**。平台标识尚未返回时，先保留待关联，取得可靠对应后补齐。

用途：让真实作品继续显示软件里的文件名、剧名和资料库封面。关联不明时，先用平台封面和作品标识，不随机套剧集，不按昵称或相近发布时间强行匹配。切片编号不自动等于原剧第几集，原剧集数需有独立依据。

## 三、可后补的数据

| 类型 | 内容 | 为何不阻塞首批 |
|---|---|---|
| 单作品每日流量 | 作品ID、统计日、当日新增播放及互动、更新时间 | 用于未来按某日分析一条作品及完整日趋势；不能由不连续累计快照差值冒充官方日值 |
| 剧场收益明细 | 收益日/周期、账号、剧名、平台作品ID、明细收益及来源提供的播放指标 | 支持按剧/按作品对账；不能假定所有剧场都有。来源已提供时应原样保存 |
| 明细播放字段说明 | 视频播放、剧集播放各自原始含义 | 先保留来源字段，当前不将剧集播放用于账号/作品主指标 |
| 更丰富的作品内容信息 | 时长、描述、挂载信息等 | 有则保留，不能根据暂行优化标签推导视频一定挂了什么链接 |
| 账号复用轮次 | 使用轮次、开始/结束时间、是否重置成绩 | 只有明确有同账号再次开跑业务时再定；当前不按掉线、停用或跨月自动开新轮 |
| 人工处置记录 | 关联作品/优化记录、处置状态、处理时间、备注 | 后续若保留处置操作，需要由本系统保存；它不是平台采集结果，点击成功提示不能替代持久化记录 |

## 四、每类数据共同需要的记录信息

这些是数据可靠性需求，不是采集方式的决定：

- **来源与原始内容**：数据来自哪里、原始返回/原文是什么，发生字段变化时可核对；不保存不必要的登录密钥。
- **对象、业务日期与取得时间**：是哪一个账号/作品、属于哪一天/哪个周期、什么时候取得、覆盖截至哪里。
- **缺失与完整程度**：已确认有数、明确为零、尚未发布、无记录、失败、仅有旧数据分别记录。数值为空与0必须分开。
- **本次结果与最后成功记录**：失败、等待更新不能抹掉已确认成绩；允许来源后续回补修正，保留变化依据。
- **去重与覆盖范围**：同账号同日/同作品同份快照不会因重复取得而被重复累加；范围缺天、列表缺页、账号缺失应能查明。
- **身份关联质量**：已对应、待对应、冲突分开；不能为了界面完整而生成未经确认的对应。

## 五、不需要额外采集的计算结果

| 界面结果 | 依赖数据/现行口径 |
|---|---|
| 启用剧场数、关联/可用账号数 | 资料档案及业务状态；可用账号排除封禁/封号、注销、停用，列表实际条数另计 |
| 矩阵区间创收、日均、历史总创收 | 账号收益及真实周期、覆盖范围、去重和结算口径 |
| 矩阵区间播放、历史播放 | 账号日播放与已保存日期范围，不把作品累计播放当账号日播放 |
| 发布作品数、发布账号数 | 已发布作品的实际发布时间及账号，账号数去重 |
| 万播收益RPM | 相同账号、相同有效日期范围的收益和播放；缺少对应粒度时不能生成日RPM |
| 账号收益等级 | 已确认累计及试投依据：SS>5000，S为2000—5000，A为500—不足2000，B为200—不足500，C不足200且完成观察，否则待评 |
| 运营阶段 | 可确认日收益、相邻日记录、历史有效产出、试投起点和账号业务状态 |
| 待更新/已更新/查询失败 | 目标统计日是否已确认、本次查询结果及最后成功日期，不单凭请求是否成功 |
| 视频流量标签 | 累计播放、发布时间和有效快照时间；现行12小时观察、24小时低播、3万小爆等规则 |
| 优化量/率、原创优化率 | 已归类原文及作品清单；优化作品去重，总分母按相同发布范围；原创只计原创优化，不合并多次发布 |
| 高危/关注/健康与排序 | 既有比例规则及同范围指标；20%归健康，50%归高危 |

账号昵称、头像、总量、业务状态、收益等级等可以更新，但历史记录须继续通过稳定ID关联。注销的展示排除规则、停用/封禁的历史保留规则沿用现有约定。

## 六、下一步边界

先把这份需求清单核定，再逐项列出“现在哪里有真实数据、含义是否已确认、还缺什么”，最后讨论获取方式、频率、权限、失败重试及接入顺序。当前已有代码和历史缓存只用于后续能力核对，不作为强制沿用旧方案的理由。

本稿没有发起外部平台获取，没有启动采集，没有清理模拟数据，也没有改变正式统计规则。后续实测若发现某项取不到，应保留缺失并单独决定显示方式，而不是重新造数补齐。
