# V3 工作台 UI 字段盘点与获取来源

创建日期：2026-11-01；更新：2026-11-02。状态：字段盘点转入小 V 猫采集联调。

本稿以当前 V3 首页工作台 `src/components/cockpit/` 已挂载的界面、抽屉、导出和数据模型为范围，先列出界面实际使用的字段，再盘点每个字段应从哪里获取。此稿不改 UI、数据库或采集任务；“已有”只表示代码或本地表中存在，不能代表已经完成真实数据验收。

前一阶段的边界（已由2026-11-02后续授权调整）是：先确认官方后台是否存在对应字段，以及字段所在的大致页面或区域；暂不判断小 V 猫或其他采集工具是否能获取，也暂不设计接口、分页、频率和落库方式。采集方案放到官方字段目录核定之后。

下方旧表中的“来源/获取方式”列目前只保留已有线索，均不视为采集方案结论；本阶段以“官方字段目录”部分为准。

## 最新执行口径与已验证取数（2026-11-02）

用户明确：单篇视频页面的日期用于筛选显示哪些视频；账号资料卡视频数与视频数据总数口径一致，不同截图来自不同账号。用户后续要求直接查既有文档/工具并开始采集，已从字段讨论转入真实采集联调。

首轮已调用小 V 猫账号统计刷新及全部作品同步，范围仅当前4个登录有效且能对应V3档案的账号；未同步作品分日明细，未修改V3业务数据库。独立入口为 `tools/collect_v3_account_data.py`，结果及限制见 `docs/事项档案/2026-11-02-V3小V猫数据采集首轮联调.md`。

实际验证的关键映射：账号视频数=`total.postCount`，关注者总数=`total.fans`；账号每日播放=`daily.view`，新增关注=`daily.fansAdd`，净增关注=`daily.fansNet`，减少关注=`daily.fansReduce`，爱心=`daily.like`，评论=`daily.comment`。作品当前指标为播放=`view`、完播率=`fullView`、爱心=`love`、评论=`comment`、转发=`forward`、点赞=`like`。账号每日与单条作品的英文互动字段命名不同，不能混用。

用户指定的“查询小V猫作品优化详情”会话已读取；已将其验证的官方只读详情接口封装为 `VcatClient.optimization_detail`。本轮4条异常作品的分析原文与建议读取成功。保留账号UID、异常作品exportId及原始通知标识；不把通知uniqueId猜成平台postId，不按同一分钟发布时间猜对应。

下方保留先前盘点过程；其中“暂不采集”和尚未确认的获取方式，以本节及本次联调事项中的实际结果为准。

### 收益数据单独盘点

当前工作台需要的是：收益对应账号、所属剧场、收益所属日期或周期、金额，以及数据是否已更新/查询是否成功的依据。具体页面和字段还没在本轮截图中确认，不能默认从视频号上述页面取得，也不能把不同剧场的收益强行当成同一种日收益。作品级收益和结算详情不自动列为本轮必需。

### V3 本地已有或需要保留的关联

这些用于让工作台对应到真实业务，不向官方要求提供 V3 内部字段：

- 剧场 ID/名称/启用状态，账号 ID/所属剧场/业务状态：沿用资料中心档案。
- 本地成片 ID、文件名、剧集 ID/剧名、切片编号、剧集封面：由制作记录及档案提供；外部发布且未关联的作品不编造这些值。
- V3 发布记录与平台作品的明确对应：决定是否计入 V3 优化率。
- 被优化作品的历史记录、已明确删除的状态或删除记录：删除后继续计入历史；未查到作品本身不足以证明删除。
- V3 首次发现优化的日期、数据读取时间、成功/失败/缺失状态：由 V3 记录，不冒充官方业务日期或数值。

优化率、原创优化率、互动率、播放标签、收益等级/阶段、区间汇总和每万播收益等由原始字段计算，不另行索要官方字段。严重程度只在有可靠官方依据时显示，暂不作为必需字段；发现时播放量不作为本轮新增采集要求。

### 先不列入必需的额外字段

平均播放时长、账号日点赞/分享、流量来源拆分、设为铃声/状态/朋友圈封面、企业链接与通讯录互动数据，以及每条作品每天按来源拆分的历史明细，先放在可选目录。官方有这些字段，不代表当前工作台就要采集。

每日关注字段的位置已由用户确认：视频数据→数据详情的每日表，无需转到关注者数据页寻找。用户暂认为“关注”表示新增关注；这是暂定解释，不等于已确认与首页“净增关注”口径一致。接下来逐项核定作品指标、优化与收益，本轮不进入采集工具实现。

## 一、先固定的业务口径

- 作品播放量使用每条作品当前累计播放量。
- 账号日流量使用界面已经显示的四项：净增关注、新增播放、新增爱心、新增评论。
- 账号全部作品可以从小 V 猫获取，具体调用方式尚未定；作品来源不限于 V3。
- 是否通过 V3 发布，以 V3 发布记录与平台作品的明确关联为准，不能按昵称、文件名或相近时间猜测。
- 被优化后删除的作品保留历史记录，并计入 V3 发布作品的优化率。
- 优化率只统计通过 V3 发布的作品；视频流量、账号单日流量统计账号全部作品。

用户提供的官方后台账号资料卡截图显示：账号昵称下方有“视频 99”“关注者 1041”。这两个字段不能只按 V3 当前字段名称猜测，必须分别核对官方后台位置、读取动作和返回字段：

### 1.2 官方字段目录的盘点顺序

先按官方后台页面顺序确认字段，不讨论采集实现：

1. 账号资料卡：视频、关注者、视频号 ID、昵称、头像、认证/账号状态。
2. 账号数据或运营数据页：账号日播放、净增关注、爱心、评论，以及官方统计日期。
3. 作品列表/作品详情页：作品 ID、发布时间、作品状态、累计播放、完播率、爱心、评论、转发、点赞、封面和链接。
4. 作品分析/异常作品页：优化分析原文、平台处理状态、通知时间、作品是否仍存在或已删除。
5. 收益或结算页：收益日期/周期、金额、结算状态、作品或剧集明细。

每个字段先标记为“官方明确存在”“官方当前未看到”或“位置待确认”。只有这份目录核定后，才进入第二阶段的采集工具盘点。

## 五、当前本地来源和真实缺口

当前数据库中已经有以下规范表，但内容混有模拟和缓存证据，不能直接当成真实业务全集：

- `v3_video_accounts`：账号快照；当前没有规范的总视频数列。
- `v3_video_account_daily`：账号日流量结构已经存在。
- `v3_video_posts`：作品累计表现结构已经存在，但没有 V3 发布来源字段。
- `v3_video_post_punishments`：优化通知结构已经存在，但部分记录无法直接对应作品。
- `v3_revenue_account_periods`、`v3_revenue_details`：收益周期和明细结构已经存在，剧场口径不同。
- V3 本地账号、剧场、剧集、制作、发布记录：可以提供稳定档案和 V3 来源关联，但平台作品最终 ID 与本地发布记录的对应仍需核实。

当前小 V 猫适配器已经登记的只读能力包括账号列表、账号统计、账号统计刷新、作品列表、作品详情、作品日数据、作品统计、作品趋势和作品同步状态。这些只是后续采集阶段的能力线索；当前先完成需要哪些字段及官方位置的核定，不能据此提前查询接口或确定采集范围。

对当前本地 `v3_publish_documents` 做了只读盘点：3 份 `publish_execution` 文档共 24 条发布条目，其中 4 条状态为 `success`、18 条为 `uncertain`、2 条为 `canceled`；24 条都有 `local_id`、提交结果和远端状态，但只有 6 条有 `video_id`，这 6 个值当前也没有直接匹配到 `v3_video_posts.post_id`。因此“有 V3 发布记录”目前只能证明本地曾提交或尝试提交，不能直接证明已经拿到对应的平台作品，也不能直接把它们计入 V3 作品分母。下一步需要用小 V 猫作品查询结果核对 `video_id`、远端任务 ID、平台作品 ID 的实际含义，并为无法确认的条目标记待关联。

## 六、后续采集阶段的逐字段核验（字段范围确认后再进行）

1. **先盘点账号与作品身份**：账号 ID、UID、平台作品 ID、V3 发布记录 ID、本地成片 ID；先解决同一作品如何唯一识别。
2. **再盘点作品当前累计表现**：发布时间、发布状态、累计播放、完播率、爱心、评论、转发、点赞、快照时间。
3. **再盘点优化通知历史**：原文、作品关联、首次发现、重复通知去重、删除后如何继续保留。
4. **再盘点账号日流量**：四项 UI 字段、统计日、完整性、昨日与最近可用日的判断。
5. **最后按剧场盘点收益**：每个剧场单独确认查询方式、日期精度、是否有作品明细和结算状态。

每一项盘点都记录：真实字段名、返回样例、对象粒度、业务日期、取得时间、覆盖范围、失败/缺失状态、去重键、与 V3 档案的关联方式。没有确认的字段保留为空或未知，不用模拟值补齐。
