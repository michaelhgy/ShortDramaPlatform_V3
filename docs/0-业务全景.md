# 业务全景（说明书）

> **这份是干什么的**：讲清"这门生意整体怎么跑"——生意模式、角色分工、软件有哪几块、不能破的硬规矩。
> **什么时候看**：**每次开新会话第一份读它**，读完再干活；改某个功能前回来对一遍。用户口述的业务规则以本文为准。详细规则不在本文重复，只写"去哪份看"；**本次改写的完整原文**见 `docs/archive/业务全景-全文底稿-2026年9月19日.md`。
> 一句话：在**微信视频号**发短剧视频，视频挂载**剧场小程序**；观众点进去看短剧，在剧里看到**广告**，账号产生**广告流水**，用户拿其中 **40%~50%**。

---

## 1. 这门生意

| 项 | 结论（出处：用户口述 2026-09-18） |
|---|---|
| 收益来源 | **广告流水分成**——不是播放量、不是拉新注册、不是充值分成 |
| 分成比例 | 用户拿 **40%~50%**；收益平台：青柠 / 顶好 / 触摸 / 花生，定时任务自动采集（`v2_revenue_service`） |
| 用户的角色 | **做短剧推广的（推广方 / 分发侧）**，不是做短剧的（版权方 / 做剧侧）。→「机构授权」「自营账号」「版权方」「小程序开发者」**都不是用户的位置**（用户当场纠正；三角色对照见 `docs/6-视频号算法与短剧分发机制.md` §0） |
| 一次性准备 | 开通视频号 → 实名认证 → 报白（剧场-小程序）→ 小程序里有可挂载的短剧 |

```
【选品】选剧 → 找素材 → 把素材传进软件
【生产】素材入库 → 做模板 → 模板 + 原素材 合成 → 剪映导出成片
【发布】小v猫（外部软件）批量发布到视频号
【收钱】观众刷到 → 点链接看短剧 → 剧中插广告 → 广告流水 → 分用户 40%~50%
```

### 1.1 能挂哪些剧 + 挂不挂链接

| 结论 | 说明 |
|---|---|
| **能挂哪些剧 = 小程序说了算** | 报白后小程序给出一批**可挂载的剧**，只能在这批里选。→"选剧"分两层：小程序给一批 → 用户从这批里挑。**改任何"选剧 / 剧集清单"功能都要记得这个上游限制** |
| **同一个剧可能挂也可能不挂** | 发布时可能一半挂链接、一半不挂，也可能全挂，**不固定** |
| **挂链接的** | 直接点进小程序看剧 |
| **不挂链接的** | 靠**封面 / 简介 / 话题**引导观众去"**主页置顶**"看剧 |

- 不挂链接那类，**内容有可能不是这部剧**，但封面和话题仍用这部剧（用户自述"挂羊头卖狗肉"）。
- **这是刻意的经营策略**：不要"顺手纠正"它，也不要拿它做"数据一致性"的理由去改。

### 1.2 谁做什么

| 环节 | 谁做 |
|---|---|
| 开通视频号 / 实名 / 报白 | **用户**（一次性），软件不参与 |
| 选剧（只能从小程序给的那批里挑）、找素材、把素材传进软件 | **用户手工** → 🎯 **自动化候选** |
| 做模板 `template_engine`；成片合成 `final_engine`；剪映导出（模拟键鼠 `v2_exporter`，**高危区 + 产能瓶颈**） | 软件 |
| **发布视频** | **用户手工 + 小v猫**——**外部软件，不在本项目里**（本软件只登记 `publish_records`） |
| 盯收益 | 用户 |

- **产品方向（用户原话）**："**目的是能软件做的尽量改到软件做。**"→ 仍手工的**选剧、找素材、传素材**是明确的自动化候选，排期优先考虑。
- **产能**：瓶颈在剪映导出，约 **1~2 分钟出一个视频**（用户口述），整条线产出上限由它决定。
- **电脑**：现在只有用户自己 **1 台**；软件做好后**要给别的电脑用且不断更新新版本** → 见 §5。

## 3. 硬规矩（不能破的）

1. **状态由后端算，前端只显示**；前端不许自己判断任务是什么状态。
2. **数据只有一个来源**：不许界面直连示例数据 / 绕过 service 层。
3. **成片必须经过人工检查**才算数（`awaiting_human_check`，是流程正式一环，不是可选动作）。
4. **文件清理看"发没发布"**：删除剧集（未发布）vs 立即清理（已发布），保留期 24 小时 / 7 天 / 永久三档（`docs/功能档案/04-跨模块规则/文件与资源生命周期.md`）。
5. **改数据库结构必须把 `SCHEMA_VERSION` 加 1**（否则老库升不上来；生产库当前 `user_version = 4`）。
6. **新的界面元素必须复用现有的**，不许自创 UI 体系（`docs/功能档案/04-跨模块规则/界面与开发规范.md`）。
7. **一次只开一个 V2**：打包版和源码版**用同一个数据库**，双开不报错但会互相打架（已装守卫）。
8. **改代码必须同步改文档**，同一个提交。
9. **扫描 / 模板 / 成片 / 导出 / 收益**五环的规矩见 §4 表格第 4 列。

## 4. 核心链路：软件一天在干什么

```
①爆款素材  →  ②模板草稿  →  ③成片草稿  →  ④剪映导出  →  ⑤小v猫发布  →  ⑥收益采集
  素材库       生成剪映草稿     +原素材合成     模拟键鼠/UIA    外部软件      定时抓取
```

| 环节 | 软件里的位置 | 干什么 | 硬规矩 |
|---|---|---|---|
| ① 素材 | `素材扫描` / `materials` | 把爆款素材扫进库、算特征 | 扫进"已使用"目录的素材**不要搬回去** |
| ② 模板 | `template_engine` | 生成剪映草稿（轨道 T01/T02/T03/T09/T10/T11） | 总时长**固定 180 秒**，代码强校验（`docs/功能档案/02-执行器/模板生成器.md`） |
| ③ 成片 | `final_engine` | **模板 + 原素材** 合成 | 结构只有 4 种插片组合；"一爆款一成片" |
| ④ 导出 | `v2_exporter` + `windows_automation` | 模拟键鼠操作剪映导出 | **高危区 + 产能瓶颈**（1~2 分钟/条）；防误触保护（输入租约 + 双 ESC）；不可变 Export Attempt |
| ⑤ 发布 | **小v猫**（外部软件） | 批量发到视频号 | **不在本软件里**；发布前 vs 发布后清理规则不同 |
| ⑥ 收益 | `v2_revenue_service` | 定时采集四个平台收益 | **抓公开网页，站点改版即失效**（长期风险） |

### 4.1 「模板 → 成片」怎么合的

**一句话：模板当"外框"铺满全片，中间挖个洞，把爆款塞进去。**

```
① 模板草稿（180 秒，T01 决定中央窗口的位置和大小）↓ 剪映导出
② 模板 mp4  ← 落在「模板目录\日期-账号-剧集-模板.mp4」↓
③ 成片草稿生成器（final_engine）：把模板 mp4【循环铺满】整个成片（音量 0）
   · 用反转蒙版在【中央挖掉一条整宽横带】   · 把【爆款】放进挖出来的窗口   · 加中插 / 尾插
   · 加 6 张真人图片（2×3 排布，透明度 0.02，肉眼几乎看不见）
   · 加 2 个画面特效 + 调色 + 账号名 + 两条合规提示 + BGM   ↓ 剪映导出
④ 成片 mp4  ← 这才是拿去发布的
```

| # | 规则 |
|---|---|
| 1 | **模板 = 包装外框。** 它自带的**照片墙、贴纸、祝福语/引导语**最后**以像素形式**留在成片的**上下两条边**里——成片**不重建这些轨道**，只把模板那段 mp4 当图层铺上去 |
| 2 | → **改照片墙 / 改贴纸 / 改文案 = 改「模板」，不是改「成片」** |
| 3 | 模板中央窗口里原本的内容在成片里**看不见**（那条横带被整宽挖空） |
| 4 | **成片自己的文字只有 3 条**：账号名、"影视效果请勿模仿"、"内容由AI制作" |
| 5 | **缺模板 mp4 直接报错**——模板是成片的**硬前置**，不是可选项 |
| 6 | **两步产物**：先出**剪映草稿**（引擎自己**不渲染 mp4**），再由导出队列驱动剪映导出 mp4；`render_finished_video_ffmpeg.py` 那个 ffmpeg 直渲脚本**不在生产链路**里 |

## 5. 素材从哪来

数据盘 `D:\短剧推广运营系统` 五个目录：`生产文件\`（按日期分：任务目录、素材、成片、草稿）、`内容资产\`（可复用的内容素材）、`生成资源\`（引流视频、BGM、真人图片…）、`剧集资料\`（剧集原始资料）、`系统数据\`（数据库、配置、缓存）。能不能删见 `docs/archive/文件地图.md`。

| 素材 | 从哪来 | **用在哪** | 备注 |
|---|---|---|---|
| 爆款素材 | 用户收集的短剧切片 | **成片**（挖出的窗口里） | 软件扫描入库；"一爆款一成片" |
| 中插 / 尾插 | `生成资源\引流视频\`，文件名以"中插"/"尾插"开头 | **成片** | 序号最大的一条默认被选中；**2026-09-18 起可指定** |
| BGM | `生成资源\BGM` + 剪映补充脚本 | **成片** | 自动补充**当前写死关闭** |
| 剧照（照片墙 10 张） | **从该剧集的原始素材里抽帧 + 选人** | **模板**（最后留在成片上下边框） | 规则见 `docs/功能档案/02-执行器/模板生成器.md` §4 |
| 真人图片（6 张） | `生成资源\真人图片\` | **成片** | **2×3 排布、透明度 0.02、肉眼几乎看不见**；和照片墙**是两套东西**，改照片墙时不要碰它。**用户 2026-09-18 确认用途：规避平台检测 / 防搬运**（评估见 `docs/6-视频号算法与短剧分发机制.md` §11.6；**AI 不擅自改，是否保留由用户决定**） |
| 花字（祝福语 / 引导语）、贴纸（16 条） | 剪映素材面板同步 | **模板** | 见下"剪映那套" |
| 画面特效 | 内置池（27 个全局选 2、13 个真人选 1） | **成片** | |

**剪映那套**：草稿要在**剪映 5.9** 里打开，用到的花字、贴纸、特效、模板**都来自剪映自己的素材库**。现在有贴纸皮肤、花字库、特效池几个零散的同步逻辑，但**"怎么更新、更新什么、怎么选用"对用户不透明**——用户原话："这些素材本质上还是剪映里面来的，但是我要怎么告诉脚本要用哪些，这个更新逻辑没跑通。"

## 6. 收益、数据、多台电脑
| 项 | 结论 |
|---|---|
| 收益来源 | 青柠 / 顶好 / 触摸 / 花生（定时任务自动采集）。**抓公开页面，网站改版就失效** |
| 微信指数 | V2 内置版在数据分析页跑；另有**独立项目** `D:\wxindex-drama-analysis`（采集环境未验证：mitmproxy 证书、系统代理、微信窗口自动化）。两套并存、各自独立 |
| 小v猫发布助手 | 代码在 GitHub 私有仓库，**本机无副本**，2026-09-17 决定暂缓 |
| 多台电脑（**确定要走，不是可选项**） | 用户 2026-09-18 明确**软件做好后要给别的电脑用，而且要不断更新新版本**；现在**看不出某台电脑装的是哪一版**（版本号写死为 "V2"，exe 属性里版本是空的）→ **"版本号 + 分发方式"是确定要走的一步**，建议尽早定（`docs/7-多机部署现状.md`） |

**已知的坑和待办**：**不在这里重复写**，统一去 `docs/2-待做需求清单.md`（唯一出处）。当前最大的两件：#6 **剪映素材更新机制**（未调研、还没出方案）、#3 **贴纸轨道**（用户说"没思路，先放着"）。
**等级 1、待目视验收**：§4.1 全部是从代码读出来的，**还没有人肉眼核对过成片草稿**——建议做一次"生成成片草稿 → 在剪映里看一眼"的目视验收，升级到等级 3。

## 7. 我（AI）不能碰什么

| 不许做 | 为什么 |
|---|---|
| 不许猜。结论必须有出处（代码 `文件:行号` / 用户原话），两者都不是就是猜测，**必须标 ❓ 并问用户** | 猜错的返工代价远超省下的 token |
| 不许改 `D:\短剧推广运营系统`（真实业务数据，**默认只读**）；不许碰 `D:\ShortDramaPlatform`（V1，已停用） | 一个是真实生产数据，一个业务已迁 V2 |
| 不许"顺手纠正"不挂链接那类的"挂羊头卖狗肉"策略，也不许拿"数据一致性"当理由改它 | §1.1，那是刻意的经营策略 |
| 不许擅自改真人图片（6 张）的存废 | 是否保留**由用户决定** |
| 不许在没有授权时删除 / 归档任何东西 | 宁可归档，不可删除 |
| 不许在根目录直接跑 `pytest server/tests`（不带隔离） | 会触碰生产库，见 `docs/3-验证基线.md` |
| 不许启动长期目标的自动推进（goal 模式连续跑） | 用户明确表示这让他失去掌控、看不懂进度 |
