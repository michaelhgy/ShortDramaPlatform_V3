## tools/ 目录详解：你该双击哪一个？

> 2026-09-17 体检（引用关系已核实）。**日常只需要 `start_v2_desktop.bat`，其余不用记。**

| 文件 | 是什么 | 谁在用 |
|---|---|---|
| ⭐ **`start_v2_desktop.bat`** | **日常启动入口**：双击即起（V2 服务 8782 + 前端 3000 + 窗口） | 你；README、术语对照表等 5 份文档都指向它 |
| `run_v2_desktop_restart.py` | 上面那个 bat 的实际调用者：先清掉残留进程再重启 | 被 `start_v2_desktop.bat` 调用 |
| `run_v2_desktop.py` | **正式版入口**（加载已构建的前端），**打包成 exe 用的** | `packaging/v2_portable.spec`（打包）+ 2 个后端测试 + 微信指数抓包 |
| `run_v2_desktop_test.py` | 开发用窗口（起 Vite 开发服务器 + pywebview 窗口，1440×920） | 被 restart 调用；见 `docs/Desktop_Test.md`、`docs/UI迁移规则.md` |
| `run_v2_file_service.py` | 只启动后台数据服务（8782），不弹界面 | 被 restart / test 调用（内部依赖） |
| `run_v2_final_generation.py` | 🔧 手工调试：给指定素材排队生成成片（需传 ID） | 备用，日常不用 |
| `run_v2_real_export.py` | 🔧 手工调试：跑一次真实剪映导出（需传任务 ID 与草稿路径） | 见 `docs/V2视频导出器设计.md`；备用 |
| `verify_v2.py` + `一键验证.bat` | 一键验证（后端测试 + 前端类型检查，自带隔离） | 见 `docs/验证基线.md` |
| `verify_photo_prep_real.py` | 🔍 **只读**验证：拿真实素材真跑一次剧照准备，逐张打印尺寸/比例/正面分/脸宽/闭眼度/演员序号，并输出成品拼图 | 排查"照片墙选图/报错"时用 |
| `verify_delivered_identity.py` | 🔍 **只读**验证：对**最终交付的 10 张图**复核有没有重复画面/重复演员（不看清单，看成品） | 怀疑"照片墙里有同一人"时用 |
| `probe_candidate_density.py` | 🔍 **只读**诊断：**候选密度扫描** —— 多密的采样才够凑 10 张可用剧照 | **改候选数量前必看** |
| `probe_photo_wall_thresholds.py` | 🔍 **只读**诊断：脸宽下限 / 正面门槛 的参数扫描 | **改门槛前用它定值** |
| `probe_face_pose.py` | 🔍 **只读**诊断：用关键点算"正对镜头"的分布（yaw/pitch） | 改正面门槛前先看分布 |
| `probe_expression_verify.py` | 🔍 **只读**诊断：把闭眼度/张嘴度最高最低的帧出图，核对指标判得准不准 | 改表情门槛前用它核对 |
| `probe_face_identity.py` | 🔍 **只读**诊断：人脸识别相似度分布（同一演员 vs 不同演员能否分开） | 改身份阈值前的依据 |
| `probe_face_detection.py` | 🔍 **只读**诊断：人脸检测在真实素材上的单帧耗时与命中率 | 换素材/换机器时复测性能 |
| `probe_face_coverage.py` | 🔍 **只读**诊断：扫整批素材，统计"可用人物剧照"的覆盖率与总耗时 | 判断采样参数该不该调 |
| `compare_photo_wall_crop.py` | 🔍 **只读**诊断：同一批候选帧，**老选图 vs 新选图**并排出图 | 给用户看效果对比 |
| `__pycache__/`（4 个 .pyc） | Python 自动生成的缓存 | 🟢 可再生、不进 git，**不用管** |
| `tmp_taskcenter_zip_0827/`（3 个文件） | 2026-08-26 的临时打包副本（内容与 `src/components/taskcenter/` 重复） | 🟡 疑似垃圾，**未清理**（按铁律：宁可归档不删除） |

> ⚠️ 最容易混淆的一对：`run_v2_desktop.py`（**正式版 / 打包用**）与 `run_v2_desktop_test.py`（**开发测试用**）——名字像、用途完全不同。
>
> ⚠️ **写诊断脚本的纪律（2026-09-18 踩过两次）**：
> ① 诊断必须**调用真实流程的函数**（如 `photo_prep.account_day_video_sources`），
> **不要自己复刻一遍取数逻辑**——我曾自己拼路径，得出与真实流程相反的结论，白改一轮。
> ② 造样本数据时，"必须互不相同"的字段（画面指纹、身份向量）要**真的不同**；
> 我曾用 `seed % 4` 造身份，导致"8 个人"实际只有 4 个，又白查半天。

## V2 运行期护栏（2026-09-18 新增，见 `docs/决策日志.md`）

| 位置 | 是什么 | 什么时候会遇到 |
|---|---|---|
| `server/runtime_guard.py`（**单实例守卫**） | 启动前用"连接探测"判断 8782 是否已被占用，已占用就**明确拒绝启动** | 重复双击启动时，会看到"已经有一个「短剧推广运营系统 V2」在运行…只允许开一个" |
| 同上（**写锁监视器**） | 守护线程：只在"写锁被连续占住约 7 秒以上"时把现场写进日志；**空闲时零输出** | 平时感知不到 |
| `%LOCALAPPDATA%\ShortDramaPlatformV2\logs\write-lock-watchdog.log` | 监视器日志（上限 1MB，超了只留尾部）；内容含各线程调用栈 + "最近一次是谁在写库" | 排查"卡住/转圈"时把它给我 |
| 环境变量 `V2_WRITE_LOCK_WATCHDOG=0` | 关掉监视器（`..._INTERVAL` / `..._STRIKES` 可调灵敏度） | 一般不用 |
