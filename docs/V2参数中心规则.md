# V2 参数中心规则

> 建立：2026-09-18。**本文是"参数中心"这个页面的产品与工程规则唯一出处。**
> 背景：用户 2026-09-17 提出"设置页里'系统设置'（装完不动）和'生产参数'（经常要调）混在一起"，
> 想新增一个页签专门放**可调参数**；2026-09-18 用户拍板**页签名 = 参数中心**、位置 = **资料中心之后**。
> 本页只放**已经确认要做的参数**；还在收集中的候选参数见 `docs/待做需求清单.md` 第 4 项。

## 一、定位与边界

- **参数中心的职责**：只放**用户经常要调的"生产参数"**。
- **不放**：装完机就不动的系统设置（数据盘、剪映路径、AI 模型等）**仍留在系统设置页**。
- **分批原则（用户 2026-09-17 明确）**：**不搬旧东西**。每确认一个参数才做一栏，
  界面**按"参数组"注册**，以后加参数是往注册表里加一项，**不重排页面**（避免"建了又搬"）。
- **UI 约束**：遵循 `docs/UI迁移规则.md`——**复用现有 UI 元素**（设置页的卡片 / 行内编辑 / 增删 / 上下移写法），
  **不引入新组件库、不另起配色与间距**。参数中心是**新页面**，不套用 `docs/UI界面基线.md` 里 AI Studio 的既有页面结构。

## 二、页面布局

**导航顺序**：`工作台 / 生产中心 / 数据分析 / 资料中心 / 参数中心`
（入口：`src/components/Header.tsx`；路由分支：`src/App.tsx`）

**页面结构**：页头（标题 + 一句话说明）→ **参数组卡片，一栏一组**。
每张卡自带「保存并生效」按钮，**不做整页大保存**（理由：这里都是"经常要调"的参数，独立保存不会误伤别的参数）。

## 三、已确认的参数组

### 3.1 文案（祝福语 / 引导语）

| 项 | 规则 |
|---|---|
| 对应轨道 | `T10_TEXT_BLESSING`（祝福语）、`T11_TEXT_DRAMA_PROMPT`（引导语），详见 `docs/V2模板草稿轨道规则.md` |
| 池语义 | 生成时从池里**随机挑一句**（保留"每次不同"的感觉） |
| 字段缺失 / 不存在 | 用**内置默认池**（`template_copy.py` 的 `DEFAULT_*`，各 10 条） |
| **空池（`[]`）** | **不生成该条文案轨道**（草稿里必须不存在该轨） |
| 非数组 | **明确报错**，不静默放行 |
| 字数 | 不再限制 6–9 字；超出原档位时按**最接近的字数档位**取字号 |
| 数据位置 | 数据库 `v2_settings` 的 `template_copy`；**由服务端同时写出** `系统数据\模板文案.json` 供生成子进程读取 |

> ⚠️ **单一数据源约定**：界面读写数据库；生成子进程读 `模板文案.json`。
> 服务端在写入时**同时更新两处**，避免"界面看到的值"和"生成实际用的值"不一致。

### 3.2 成片插片（中插 / 尾插）

**用户需求原文与拍板（2026-09-17 / 2026-09-18）**：
中插、尾插**各自可要可不要**；默认用**最新序号**，但可以**手动改成指定某一条**。

**四种组合与成片主轨结构（2026-09-18 用户确认）**：

| 中插 | 尾插 | 成片主轨 | 说明 |
|---|---|---|---|
| 要 | 要 | `爆款 0–120s → 中插 → 爆款剩余 → 尾插` | 现状行为，不变 |
| 不要 | 要 | `爆款整条 → 尾插` | **爆款不拆段**（用户 2026-09-18 明确："爆款不用再剪成2段"） |
| 要 | 不要 | `爆款 0–120s → 中插 → 爆款剩余` | 中插仍然分段插入 |
| 不要 | 不要 | `爆款整条` | **用户 2026-09-18 确认允许，且不需要弹窗提醒** |

**选素材规则**：

- **"跟随最新序号"（默认）**：每次生成时重新在 `生成资源/引流视频/` 里找**序号最大**的那一条（动态跟随）。
- **"指定某一条"**：锁定该文件；**文件被删或改名 → 生成时明确报错，不静默换别的**。
- **序号排序**按 `service.natural_key`（自然序，`中插10` > `中插9`），扩展名不限（`.mp4` / `.mov` 都算）。
- ⚠️ **易错点**：目录里序号是**跨扩展名**占用的（如 `中插01.mp4` / `中插02.mov` / `中插03.mov`），
  所以界面上必须显示**序号 + 文件名 + 时长 + 体积**，否则选错看不出来。

**与"素材太短自动跳过中插"的优先级（用户 2026-09-17 拍板）**：

> **人工设置优先于自动判断。** 只有用户**没设过**时，才走"素材太短自动跳过中插"的自动逻辑。

**两层配置**：

| 层级 | 位置 | 状态 |
|---|---|---|
| 全局默认 | 参数中心「成片插片」卡 | ✅ 本批实现 |
| 任务级覆盖 | 生产任务界面（"日期-账号-剧名"卡片）的「跟随全局默认」开关，关掉才展开单独设置 | ⏳ 引擎与接口已就绪，界面待做 |

- 覆盖层级 = **生产任务级**：设一次，该任务下所有成片都听它的（用户 2026-09-17 确认）。
- 任务级字段为空 = 跟随全局（与 `production_tasks.final_video_manual_check` 同一模式）。
- 现阶段可用接口：`POST /api/v2/production-tasks/{id}/insertion-strategy`，body `{"strategy": {...}}`；
  传 `{"strategy": null}` = 清除覆盖、回到跟随全局。

## 四、工程约束

- **改 DDL 必须把 `SCHEMA_VERSION` 加 1**（硬性，见 `docs/V2开发规范.md`）。
  本批新增 `production_tasks.midroll_endroll_strategy` → `SCHEMA_VERSION` 由 1 改为 **2**。
- **引擎缺件语义要改**：现在是"中插、尾插都必须有，缺一条直接报错"
  （`server/final_engine/runner.py`：`缺少可用的中插或尾插视频`）。
  改造后：**不要的那一条不参与检查**；要的那一条找不到素材才报错。
- **成片结构校验要同步扩展**：`server/final_engine/jianying59_final/composition.py` 的 `validate_plan()`
  现在**只认两种** role 序列，必须扩展到上表四种，否则新组合会被校验拒掉。
- **参数传递链**：`final_engine/runner.py` → `run_jianying_composition_batch.py` →
  `generate_jianying59_composition_draft.py` 的 `--midroll` / `--endroll` 目前是**必填**，
  必须改成可选，且**允许只给一条**。

## 四之二、实现清单（2026-09-18 完成，供后续维护对照）

**数据与接口**

| 位置 | 内容 |
|---|---|
| `v2_settings.template_copy` | 文案池的**权威值**（`{"blessing": [...], "drama_prompt": [...]}`） |
| `系统数据\模板文案.json` | 由服务端**派生写出**的副本，供模板生成子进程读取；用 `os.replace` 原子替换 |
| `v2_settings.midroll_endroll_strategy` | 全局插片默认；`None` = 用户从未设置过 |
| `production_tasks.midroll_endroll_strategy` | 任务级覆盖（JSON 文本）；空串 = 跟随全局 |
| `GET /api/v2/engine-parameters` | 返回两个参数组的**生效值** + 内置默认池 + 是否已自定义 |
| `POST /api/v2/engine-parameters` | 按参数组局部提交；载荷里没出现的组保持原值 |
| `POST /api/v2/production-tasks/{id}/insertion-strategy` | 任务级覆盖；`{"strategy": null}` = 清除覆盖 |

**界面**

- `src/components/parameters/ParameterCenterView.tsx`（新页面）
- `src/components/parameters/CopyPoolEditor.tsx`（文案池行内编辑器，独立组件）
- `src/utils/naturalCompare.ts`（素材序号自然排序；与后端 `natural_key` 语义对齐）
- `src/api/v2EngineParameters.ts`（数据接口层）
- 导航入口：`src/components/Header.tsx` 的 `#nav-parameters`；路由：`src/App.tsx` 的 `activeTab === 'parameters'`

**引擎**

- `server/final_engine/runner.py`：新增 `_pick_insertion()` / `resolve_insertion_media()`；
  `--midroll` / `--endroll` 为 `None` 时**不传该参数**。
- `server/final_engine/jianying59_final/composition.py`：`_main_sections()` 支持四种组合；
  `validate_plan()` 接受四条合法 role 序列；`decisions.midroll.status` 新增 `disabled_by_user`。
- `server/final_engine/scripts/run_jianying_composition_batch.py`：新增 `insertion_arguments()`；
  成片时长预算只扣**本次真要用的**插片素材。
- `server/final_engine/scripts/generate_jianying59_composition_draft.py`、
  `generate_composition_from_detection_reports.py`：插片参数改为可选、允许只给一条。

**未改（刻意保留）**：`server/final_engine/scripts/generate_base_composition_draft.py`、
`generate_composition_from_detection_reports.py` 里那条旧的 ffmpeg 分支脚本
（`run_ffmpeg_composition_batch.py`、`render_finished_video_ffmpeg.py`）仍要求两条都给。
它们**不在 V2 正式链路**上（正式链路是剪映 5.9 原生草稿），属于诊断/历史入口，不动它们降低回归风险。

## 五、验收标准

| 阶段 | 验收方式 | 证据等级 | 状态 |
|---|---|---|---|
| 文案卡 | 改祝福语 → 保存 → 服务端读到的值变了；后端测试覆盖 5 种池语义 | 2 | ✅ 2026-09-18 |
| 插片卡（界面） | 关掉尾插 → 界面结构预览同步变化 | 1–2 | ✅ 2026-09-18（等级 2：类型检查 + 隔离环境端到端） |
| 插片卡（引擎） | **四种组合各真跑一次成片**，检查产出草稿里中插/尾插轨真的按设置出现或消失 | **3** | ⏳ **待实机跑** |
| 任务级覆盖 | 单个任务覆盖后，只影响该任务下的成片 | 3 | ⏳ 接口/引擎就绪，界面待做 |

- ✅ **2026-09-18 已做的等级 2 验证**：在后端测试里用隔离工作区跑通"保存文案 → 落盘 `模板文案.json`"、
  "关掉尾插 → 引擎返回 `(中插, None)`"，并断言正式链路三个脚本的插片参数**不是必填**（防回归）。
- ⚠️ **"两个都不要"这一组合**：主轨只剩爆款一条，而模板视频**循环铺满**成片全长 →
  **代码层面不会报错，但最终画面效果未实机确认**。首次实机跑通前，此组合按"未验证"对待。
