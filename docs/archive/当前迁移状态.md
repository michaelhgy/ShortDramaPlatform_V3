## 当前架构结论

- API 层已统一在 `src/api`，请求由 `src/api/client.ts` 处理。
- 已存在的模块 service 为收益 `src/services/revenueAnalyticsService.ts`、生产中心 `src/services/productionService.ts`、资料中心空数据边界 `src/services/assetsCenterService.ts` 与任务中心空数据边界 `src/services/taskCenterService.ts`；通用 `mockServices.ts` 仅用于显式 Mock 模式。
- 已存在的适配层为收益 `src/adapters/revenue.ts`、状态 `src/adapters/status.ts` 与生产中心 `src/adapters/production.ts`。
- 页面组件没有直接导入 `*MockData.ts`；资料中心和任务中心已通过专属 service 取得 Mock 或空数据。工作台与探索工作台仍使用通用 `mockServices.ts`，后续迁移必须改为各模块专属 service，避免 Mock 入口长期承担业务编排。
- 生产中心已接入只读 service；资料、设置与仪表盘调用目前仍只是预留，在页面和 service 未接入前不可视为功能已完成。

## 下一阶段顺序

1. 资料中心：从剧场/账号开始，开放 V2 新建、编辑与状态管理。

4. 任务中心、工作台、系统设置：分别先接入只读真实状态，最后才讨论可写操作。
