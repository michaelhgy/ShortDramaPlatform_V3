## 修改原则

- 不复制 V1 旧前端页面；只按模块复用已验证的后端能力。
- 未经单独授权，不修改 V1、SQLite 结构、文件规则或剪映代码。
- **数据库结构变更必须同步 `SCHEMA_VERSION`（硬性）**：`server/v2_file_service.py` 里任何 DDL 改动（建表 / 建索引 / 建触发器 / ALTER TABLE）之后，**必须把 `SCHEMA_VERSION` 加 1**。
  - 原因：`_initialize_connection()` 用 `PRAGMA user_version` 标记"结构已就绪"，版本一致时会**完全跳过**整套 DDL；忘记加 1 会让改动**静默不生效**（最难查的一类问题）。
  - 背景：这套 DDL 每次执行都要抢数据库**最高级写锁**；在繁忙的库上抢不到就会一直等到 30 秒超时。2026-09-17 的"启动慢 / 刷新卡 / database is locked"故障就是这个原因。
- V2 文件系统与资源生命周期以 `docs/功能档案/04-跨模块规则/文件与资源生命周期.md` 为准。
- 先阅读目标页面、对应 service（服务层）、adapter（适配层）与 V1 API 合同，再进行最小修改。
- 新页面或共享改动必须执行 `npm run lint`；涉及构建时执行 `npm run build`。
- 构建通过不代表 pywebview（Windows 桌面窗口容器）、剪映或真实媒体流程已经验收；这些需另行说明验证边界。
