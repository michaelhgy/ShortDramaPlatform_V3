# 业务资料模块接入审计

## 结论

资料中心的产品规则以 V2 UI 为准。V1 仅复用数据校验、关系保护、批量事务和历史名称的技术思路；V2 不读取或写入 V1 数据库。

接入范围按依赖顺序为：剧场 → 子剧场 → 账号 → 剧集。四项完成后才允许创建生产任务。

## V2 已定义的规则

| 对象 | V2 UI 已明确的字段与行为 | 后端规则 |
|---|---|---|
| 剧场 | 名称、默认分成、默认税率、启用/停用；支持单个和批量录入 | 名称唯一；分成和税率为 0–100；删除前检查子剧场、账号、剧集和后续业务关联 |
| 子剧场 | 所属剧场、名称、分成、是否覆盖剧场默认值、启用/停用 | 名称在同一剧场内唯一；一旦已有账号绑定，不可更换所属剧场；不可删除 |
| 账号 | 昵称、账号 ID、剧场、子剧场、状态、报白时间、注册时间、备注 | 昵称和账号 ID 唯一；只能选择启用的剧场和子剧场；子剧场必须属于所选剧场；已有业务关联不可删除 |
| 剧集 | 所属剧场、当前剧名、历史剧名；支持新增、批量录入、改名、将历史名设为当前名和删除错误历史名 | 一部剧全系统只能属于一个剧场；当前剧名和历史剧名都不得被其他剧集使用；改名时旧当前名自动保留为历史名；有生产、发布、收益或素材关联时不可删除 |

## V1 可复用的技术，不继承其产品流程

| V1 能力 | V2 处理 |
|---|---|
| 剧场、子剧场、账号和剧集的唯一性校验 | 复用校验思路，在 V2 SQLite 重新实现 |
| 子剧场归属校验、停用对象禁止继续新增关联 | 按 V2 的中文状态和字段重新实现 |
| 删除前检查关联数据并返回原因 | 复用“先检查、后删除”的安全原则；V2 返回 V2 页面文案 |
| 剧集历史名称与改名事务 | 复用“当前名与历史名分离”的数据结构；按 V2 的改名交互实现 |
| 批量导入 | V2 采用“先完整校验，再一次性写入”；错误时整批不落库 |

## 不从 V1 直接带入的规则

- V1 的旧状态英文值、旧排期和收益字段不作为 V2 数据合同。
- V1 按“剧场内当前剧名唯一”的做法不能直接复用；V2 必须按“全系统一部剧只属于一个剧场”校验。
- V1 的旧数据不迁入 V2。
- V1 的绝对路径、文件目录和剪映业务不在本模块接入。
- UI 不得自己生成临时 ID、临时成功记录或模拟导入结果。

## 实施批次与验收

### 批次 A：剧场

- 列表、单个新增、批量导入、编辑、启停、安全删除。
- 已开始：真实列表、单个新增、批量导入。
- 验收：重复名称整批不写入；关闭软件后数据仍存在。

### 批次 B：子剧场

- 列表、单个新增、批量导入、编辑、启停、安全删除。
- 验收：绑定账号后不可更换剧场或删除；其他可编辑字段可保存。

### 批次 C：账号

- 列表、单个新增、批量导入、编辑、状态修改、安全删除。
- 验收：不能选择停用或不匹配的剧场/子剧场；已有生产或发布关联的账号不可删除。

### 批次 D：剧集

- 新增、批量录入、剧名和历史名管理、安全删除。
- 验收：改名后历史名可查；历史名可用于后续素材与收益匹配；有业务关联不可删除。

## 当前需要产品确认的事项

已确认：一部剧只能属于一个剧场，不允许同名剧集存在于不同剧场，也不允许将同一剧集重复归属到多个剧场。

后续所有会改变产品规则的事项（归属、状态、删除、文件生命周期、发布和收益）必须先向产品确认；不得按 V1 习惯或技术默认值推断。
