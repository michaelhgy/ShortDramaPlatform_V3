# 多机安装与版本管理

> 本文记录当前正式的多机安装方式、已验证范围和使用边界。

## 当前正式安装版

- 版本：`2026.09.21`
- 安装文件：`packaging\output\installer\ShortDramaPlatform_V2_Setup_2026.09.21.exe`
- 安装方式：双击安装程序，按中文向导完成安装；默认安装到当前 Windows 用户目录，并创建桌面和开始菜单快捷方式。
- 卸载方式：Windows“已安装的应用”，或开始菜单中的“卸载短剧推广运营系统 V2”。

本机已验证完整路径：安装程序成功 → 安装目录生成 → 软件启动 → 后台服务返回正常 → 卸载成功。验证使用独立测试数据目录，没有接触真实业务数据。

安装包已经包含 Python、前端页面、FFmpeg、照片墙所需模型和 MediaPipe 运行组件；目标电脑不需要另装 Python 或 Node。

## 目标电脑仍需准备

- Windows 10/11 64 位系统；
- WebView2 运行环境（多数 Windows 10/11 已自带）；
- 剪映 5.9，以及在软件设置中选择正确的剪映程序和用户数据目录；
- 使用本机 AI 时，按功能需要安装并配置 Ollama 和对应模型；
- 每台电脑的数据默认各自保存，不会自动和其他电脑合并。

## 当前验收边界

- 已确认：安装、启动、后台服务、卸载。
- 已确认：照片墙所需的两个模型和 MediaPipe 文件已经进入安装包。
- 尚未确认：另一台干净电脑的首次安装、剪映真实导出、Ollama 本地识别和整条生产流程。
- 因此当前安装包可用于另一台电脑做首次验收，但还不能把跨机器剪映生产称为正式验收完成。

## 更新规则

- 新版本继续使用日期版本号，例如 `2026.09.21`。
- 升级前先停止正在执行的任务和软件，再运行新的安装程序覆盖安装。
- 真实业务数据不放进安装包，升级不得删除业务数据。
- 每台电脑记录当前安装版本；确认新版本正常后，再清理旧安装包。

## 2026-09-17 历史盘点

## 你的原话

> "做好的软件需要给到别的电脑使用，因为一台电脑是没有办法负荷的。"

## 盘点到的事实

### 现有的构建产物

| 位置 | 日期 | 说明 |
|---|---|---|
| `D:\V2_PackagingOutput_R12` | 09-05 | 较早的一次打包产物 |
| `D:\V2_PackagingOutput_R13` | 09-05 | 稍后的打包产物 |
| `D:\ShortDramaPlatform_V2\packaging\output` | 09-07 | 当前工作区里最近一次的打包产物 |
| `D:\V2_ReleaseTest_R18` | 09-07 | **最新**，含可直接分发的压缩包 `ShortDramaPlatform_V2.7z`（376 MB） |

> 从命名看，R12 → R13 → R18 是第 12、13、18 次发布。**但"R几"目前只存在于文件夹名字里。**

### 已经有的好机制 ✅

每个打包产物里都带一个 `build-metadata.json`，记录：

```json
{
  "product": "ShortDramaPlatform V2",
  "version": "V2",
  "git_commit": "48f0398be00f859c1aeff769d6ded86e6150a5f2",
  "built_at_utc": "2026-09-07T05:58:56+00:00",
  "build_mode": "PyInstaller onedir"
}
```

也就是说：**每一次构建其实都有精确身份**（对应哪个代码版本 + 什么时候构建的）。这比很多项目做得好。

### 缺的三样 ⚠️

| 缺什么 | 后果 |
|---|---|
| **可读的版本号**——metadata 里的 `version` 写死是 `"V2"`，区分不了 R12/R13/R18 | 你没法一眼说出"这台电脑装的是哪一版" |
| **exe 的文件版本信息**——查过了，`FileVersion` / `ProductVersion` 全是空的 | 在 Windows 里右键看属性、或在程序列表里，都看不到版本 |
| **软件内部查看版本的地方**（疑似没有） | 坐在那台电脑前，也不知道它跑的是哪一版 |

**合起来的结果：等你把新版本发到别的电脑之后，没有任何方便的办法确认那台电脑到底更新了没有、版本对不对。** 这正是"版本地狱"的开端。

## 我还没搞清、需要你回答的关键问题

这几个问题的答案决定了多机部署该怎么做：

1. **一共几台电脑在实际使用？** 分别在谁手里？
2. **数据是各存各的，还是要汇总到一起？**
   - 各存各的 → 你这边看不到别的电脑的进度和收益
   - 要汇总 → 需要共享数据库或同步机制（复杂得多，但现在就要定）
3. **新版本你现在是怎么发过去的？**（U盘拷贝？网盘？微信传？）
4. **别的电脑上装的，是哪一个包？**（R13？R18？还是更早的？）
5. **那些电脑上有没有正在跑、还没做完的任务？**（升级会不会打断）

## 建议（待你批准后再做，不急）

1. **给每次发布起一个能看懂的版本号**，例如 `V2.2026.09.07` 或继续沿用 `R19`，并写进打包元数据、exe 版本信息、以及软件里的"设置 → 关于"。
2. **建一张"发布记录"表**（就是一个中文文档）：哪台电脑、什么时候装的哪个版本、装的什么路径。这样版本不一致时能立刻发现。
3. **明确数据归属**（回答问题 2）：各存各的还是汇总——这是架构决策，越早定越省事。
4. **打包时自动把版本号显示在标题栏或设置页**，让人一眼能看到。

## 风险提示

- **版本不一致**是这套系统未来最可能造成"数据损坏"的原因之一（数据格式变了、旧版软件读新数据，或反过来）。
- 目前**无法从一台电脑上判断它装的是哪一版**，所以这个问题一旦发生，排查会非常困难。
- 这个问题的解决成本**随电脑数量增长**：2 台时手工管也行，5 台以上就必须有机制。
