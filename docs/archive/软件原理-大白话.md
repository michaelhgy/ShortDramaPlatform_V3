# 这个软件是怎么工作的（大白话原理）

> **建立：2026-09-18。给非技术用户看的。**
> 为什么要有这份：用户原话——"**你都不跟我讲原理，我都搞不懂你在干嘛，
> 前端和后端到底是怎么回事，刷新和读取又是什么**"。
> 不懂原理就没法做决策，所以这份要讲清楚最基本的几件事。

---

## 一、软件分成两半：前端 和 后端

| | 是什么 | 你见过吗 |
|---|---|---|
| **前端** | 你**看到**的那一半 —— 窗口里的画面、任务卡、按钮 | ✅ 天天看 |
| **后端** | 你**看不到**的那一半 —— 一个在后台默默跑的程序 | ❌ 看不见 |
| **数据库** | 所有数据真正存放的地方（一个文件，在你的 D 盘） | ❌ 看不见 |

### 打个比方：一家餐厅

| 软件里的东西 | 相当于餐厅里的 |
|---|---|
| **后端** | **后厨** —— 做菜、管食材、决定菜好了没有 |
| **数据库** | **冷库** —— 所有食材都在这，后厨说了算 |
| **前端** | **大堂** —— 菜单、餐桌、你眼睛看到的一切 |
| **执行器**（模板/成片/导出） | **三个厨师**，各管一道工序 |

**关键点**：

- **前端自己不存数据**，它只是"显示"和"接收你的点击"
- **所有事实都在后端 + 数据库**里
- 前端要显示什么，**必须去后端要**

> 这条是这个项目一直强调的规矩：**"后端是业务事实的唯一来源，前端只负责显示，不自己猜状态。"**

---

## 二、什么是「读取」

你打开生产中心，**前端会去后端问一句**：

> "现在有哪些生产任务？分别是什么状态？"

后端从数据库里查出来，**把结果送回来**，前端把它画成一张张卡片。

**这个过程就叫「读取」。**

（就像服务员跑到后厨问"今天有什么菜"，然后回来告诉你。）

---

## 三、什么是「刷新」

问题在于：**数据会变。**

- 你点了「扫描素材」→ 数据库里的素材数量变了
- 后厨的「模板生成器」跑完了 → 模板状态从"生成中"变成"已生成"
- 收益定时采集跑完了 → 收益数字变了

**但前端不知道。** 它手里还是刚才那份数据。

**所以它得再去问一次 —— 这就是「刷新」。**

---

## 四、那现在的毛病在哪？（4 条）

### 毛病 1：问得太少

现在前端**每隔 60 秒**才把所有页面重新问一遍。

所以你干了活，界面上的数字不动 —— **因为它还没到下一次问的时间**。

> 你"**切来切去**"，其实就是在**逼它重新问一次**：
> 因为切页签会把整个页面拆掉重建，重建时必然会重新问一次。
> **这是现在最主要的刷新手段** —— 这本身就是不正常的。

### 毛病 2：问的方式乱

| 谁 | 多久问一次 |
|---|---|
| 变更通知 | **1.5 秒** |
| 生产中心（选中的那部剧） | **5 秒** |
| 所有已打开页面（整块重问） | **60 秒** |
| 微信指数 | **1.5 秒**（一次问 4 个） |
| 参数中心 / 设置页 | **从不**（只能手动或切页签） |

**一共 8 套，各问各的，互不通气。**

### 毛病 3：问了不告诉你结果

如果后端没回答（程序卡了、服务没启动），前端**什么都不说** ——
数字就那么停着，**你分不清是"没变化"还是"没问到"**。

代码里管这叫"静默失败"。

### 毛病 4：问回来了，就把整面墙重画一遍

106 张任务卡**全部重新画**。

**这就是你说"以前很卡、页面经常闪"的原因。**

---

## 五、我在改什么（就四件事）

| 改什么 | 现在 | 改成 |
|---|---|---|
| **多久问一次** | 最坏 60 秒（或靠切页签） | **每 3 秒** |
| **谁来问** | 8 套各问各的 | **一个地方统一问** |
| **问不到怎么办** | 一声不吭 | **明确告诉你"数据暂时读不到，显示的是上次的"** |
| **问回来之后** | 无条件重画 106 张卡 | **发现没变化就不重画** |

### 我**不**改什么

- ❌ 界面长什么样（一个字不改）
- ❌ 业务怎么跑（怎么扫描、怎么生成、怎么导出，全不碰）
- ❌ 后端怎么算（状态还是后端算）

**只改"前端多久去后端问一次、问到了怎么画"。**

---

## 六、为什么这件事值得大动干戈

因为上面那 4 条毛病，**就是你觉得"到处都是 bug"的来源**：

| 你的感受 | 其实是 |
|---|---|
| 干了活界面不变 | 毛病 1、2（问得太少、各问各的） |
| 要切来切去才更新 | 毛病 1（只能靠重建来刷新） |
| 出错了什么提示都没有 | 毛病 3（静默失败） |
| 卡、闪 | 毛病 4（无条件重画） |
| 数据对不上 | 毛病 1 + 时间戳是假的 |

**它们不是一个一个的 bug，是同一件事的五个表现。** 所以修的时候要一起修。

## 附：几个你可能听过的词，一句话解释

| 词 | 意思 |
|---|---|
| **接口** | 前端向后端"提问"的那个通道。一个接口 = 一个问题 |
| **缓存** | 把上次问到的答案先存着，下次先拿它顶上，不用干等 |
| **数据层** | 我正在建的东西：专门管"什么时候去问、问到的答案存哪、问不到怎么办"的那一层 |
| **状态** | 一件事现在进行到哪一步（待扫描/生成中/已完成…），**由后端算，前端只显示** |
| **执行器** | 后端里真正干活的三个程序：模板生成器、成片生成器、视频导出器 |
| **证据等级** | 这件事我们验证到什么程度：1 读代码 → 2 测试通过 → 3 真实运行 → 4 你亲自验收 |
