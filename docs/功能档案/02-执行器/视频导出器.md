# 视频导出器

> 把生成好的**成片草稿**通过剪映自动导出成 mp4（模拟键鼠操作剪映 5.9）。
> **他会这么说**：「导出」「导出器」「剪映导出」「双 ESC」「人工检查」「卡在导出」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

- **入料**：一条成片草稿（剪映 5.9 原生草稿目录）。
- **产出**：一个验过的 mp4，落在正式目标位置。
- **怎么干**：打开剪映 → 找到草稿 → 触发导出 → 等文件出来 → 校验媒体 → 替换到正式位置。
- 它通过**模拟键鼠**操作剪映，因此每个阶段都配了"立刻停下来"的手段（双 Esc）。

## 二、怎么用

1. **生产中心 → 卡片 → 导出**（成片草稿就绪后进入导出队列）。
2. **人工检查模式**（剧集级开关）：导出前**自动打开草稿然后松开键鼠**，等你在剪映里看一眼，按**回车**继续。
3. **紧急停下**：**双击 Esc** —— 立刻释放键鼠，本次尝试结束。

## 三、业务规则

### 每次导出 = 一次"导出尝试"

- 每次导出新建一次尝试；**重试和重新导出都从头开始**，不复用旧尝试。
- 失败、超时、双 Esc 都是**终态**；要继续就**新建一次尝试**。

### 双 Esc

- 任何阶段都可双击 Esc：**立刻释放键鼠**，本次尝试按普通失败结束。

### 人工检查模式

- 自动打开**正确的那条草稿**后**释放键鼠**，等你在剪映里检查。
- 按回车后**重新接管**并**直接进入导出**（不回首页、不重复搜草稿）。
- 等待期间**同样可以双 Esc 结束**。

### 提交之后不再碰剪映

- 最终导出提交后，V2 **不再控制剪映**，只观察第一次记录的那个输出路径，并按统一超时计时。

### 什么算"真的导出成功"

必须**全部**满足：新视频出现 → 相对提交前基线有变化 → 文件大小稳定 → `ffprobe` 校验通过 → 替换成功 → 数据库收口成功。

- 正式目标位置已有旧文件时：**新视频验收通过后再替换它**。

### 连续失败才会暂停

- 连续失败 / 超时计数与暂停由**任务中心的执行器管理层**负责（三个执行器共用）；
  达到**连续 3 次**才暂停，**人工重启后清零**。
- 软件重启时正在跑的尝试**直接记失败**。

### 状态怎么走

```
queued → preparing → awaiting_human_check? → submitting → observing_output → finalizing → completed
```

- 普通失败 / 超时 / 双 Esc → `failed`（终态）。
- **未知页面**、**最终提交是否生效无法确认** → 结束本次尝试；要重导就新建一次尝试。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 说明 |
|---|---|---|---|
| 人工检查模式 | 剧集级开关（生产任务上） | 关 | 开了才会在导出前停下来等你按回车 |
| 导出超时 | 设置页 →「生产与任务设置」 | 20 分钟 | 超时按失败处理 |

写死在代码里的：连续失败阈值 3 次；媒体校验项（分辨率 / 编码 / 帧率 / 时长）。

## 五、改动须知（动这个功能前先看这段）

1. **提交之后的"不确定"一律结束本次尝试**：未知页面、或提交是否生效无法确认 → 本次尝试结束；
   要重导只能**新建一次尝试**（这是防止重复导出的那道闸）。
2. **正式目标位置用原子替换**：新文件验收通过后再替换，替换成功才算完成。
3. **连续失败计数与暂停在 `server/executor_management.py`**；导出器只报告"这一次"的结果。
   改暂停逻辑去那里改，别写进导出器。
4. **双 Esc 必须任何阶段都能立刻释放键鼠**：加新的等待或轮询时，保留这个逃生口。
5. **V1 只按接口迁低层能力**：剪映进程发现 / 启动、UIA 控件识别、完整草稿名搜索、提交后被动观察文件、
   `size + mtime_ns` 稳定采样、ffprobe 校验、提交前输出基线。
6. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

### 代码入口

| 干什么 | 文件 | 关键函数 |
|---|---|---|
| 一次真实导出尝试 | `server/v2_exporter/runner.py` | 领取任务、模拟键鼠、观察输出 |
| 状态机 | `server/v2_exporter/core.py` | 状态定义与转移 |
| 基线 / 文件稳定 / 媒体校验 / 安全替换 | `server/v2_exporter/runtime.py` | 这些在代码里是**函数** |
| 连续失败与暂停 | `server/executor_management.py` | 计数、暂停、人工重启清零 |
| 真实导出入口 | `tools/run_v2_real_export.py`；接口 `POST /api/v2/exporter/jobs`、`POST /api/v2/exporter/jobs/{job_id}/start` | 只接受明确指定的任务和**已存在的**真实草稿目录 |

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（`server/tests/test_v2_exporter.py`、`test_v2_export_runtime.py`）。
2. **动它之前，先在真机跑通一条真实草稿做成基线**：用 `tools\run_v2_real_export.py`（或上面的接口），
   在 Windows + 剪映现场确认"能找到草稿 → 能导出 → 校验通过 → 替换成功"，把这一步的结果当作以后对比的基准。
