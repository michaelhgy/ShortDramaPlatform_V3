# 成片生成器

> 把爆款素材、中插、尾插拼成一条完整成片（剪映草稿），交给视频导出器导出。
> **他会这么说**：「中插」「尾插」「成片」「爆款拆两段」「900 秒」「原素材处理」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

成片 = **主轨（爆款素材）** + 可选的**中插** + 可选的**尾插**。

| 中插 | 尾插 | 成片主轨长什么样 |
|---|---|---|
| 要 | 要 | 爆款拆成前后两段 → 中插插在中间 → 尾插放最后 |
| 不要 | 要 | 爆款整条不拆 → 尾插放最后 |
| 要 | 不要 | 爆款拆成前后两段 → 中插插在中间 |
| 不要 | 不要 | 只有爆款一条 |

成片总长**不超过 900 秒**。

## 二、怎么用

1. **参数中心 →「成片插片」**：中插、尾插各一行，分别选"要 / 不要"，以及"用哪一条"。
   卡片下方直接显示这次成片的结构。
2. **生产中心 → 账号×剧集卡片 → 生成成片草稿**。
3. 生成进度在**任务中心**看；草稿生成后由《视频导出器》自动导出。

## 三、业务规则

### 素材怎么选

- 默认**跟随最新序号**：每次生成时重新在 `生成资源/引流视频/` 里取序号最大的那一条
  （目录里换了新素材，下次生成自动用新的）。
- 也可以**指定某一条**：锁定后不再跟随。**指定的文件被删或改名 → 生成时明确报错**，不会偷偷换别的。
- 序号按自然序排（`中插10` 排在 `中插9` 之后），扩展名不限（`.mp4` / `.mov` 都算）；
  序号是**跨扩展名共用**的，所以参数中心里同时显示**序号 + 文件名 + 时长 + 体积**，免得选错。
- 中插、尾插**各自独立**设置，互不影响。
- 参数中心设的是**全局默认**；单个生产任务可以**单独覆盖**，不覆盖就听全局。

### 中插插在哪

- 爆款素材**长于 120 秒**时：取前 120 秒 → 中插 → 剩余部分。
- 爆款素材**不足 120 秒**时：**不插中插**，成片只剩爆款（有尾插就接尾插）。

### 成片时长

- 上限 **900 秒**，超出的部分截断。

### 原素材处理（设置页开关，默认开）

- **开**：先做片头 / 片尾 / 黑边 / 剧名四项分析与清理，再合成。
- **关**：不做任何处理，直接用原素材合成；**仍然按 900 秒截断**。

### 真人组合图片

- 成片里固定 **6 张真人组合图**，取自 `生成资源\真人图片\`，**透明度 0.02**（画面上几乎看不见）。
- 与模板的**照片墙是两套素材、两个流程**，互不影响。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 可选值 |
|---|---|---|---|
| 中插 要 / 不要 | 参数中心 →「成片插片」 | 要 | — |
| 中插 用哪一条 | 同上 | 跟随最新序号 | 跟随最新序号 / 指定某一条 |
| 尾插 要 / 不要 | 同上 | 要 | — |
| 尾插 用哪一条 | 同上 | 跟随最新序号 | 跟随最新序号 / 指定某一条 |
| 原素材视频处理 | 设置页 →「生产与任务设置」 | 开 | 开 / 关 |

写死在代码里的：成片上限 900 秒；中插插入点 120 秒；真人图片 6 张、透明度 0.02。

## 五、改动须知（动这个功能前先看这段）

### 一句话：改结构要**成对改**，改参数要**改透整条链**

1. **结构 = 两个函数必须一起改**：`jianying59_final/composition.py` 里
   `_main_sections()`（决定主轨怎么拼）和 `validate_plan()`（校验合法结构）。
   **只改前一个 → 新组合会被后一个拒掉**，报"结构不合法"。
2. **参数是一条链，任何一环没改透，设置就到不了草稿**：
   `参数中心界面` → `api/v2EngineParameters.ts` → `v2_settings.midroll_endroll_strategy`
   → `final_engine/runner.py` 的 `resolve_insertion_media()` → 批处理脚本的 `--midroll` / `--endroll`
   → `generate_jianying59_composition_draft.py` → 草稿。
   任务级覆盖走另一条：`production_tasks.midroll_endroll_strategy`（空 = 跟随全局）。
3. **别顺手动旧 ffmpeg 链路**：`generate_base_composition_draft.py`、
   `generate_composition_from_detection_reports.py` 的旧分支、`run_ffmpeg_composition_batch.py`、
   `render_finished_video_ffmpeg.py` **不在正式链路上**（正式链路是剪映 5.9 原生草稿），
   它们仍要求两条插片都给。**动它们 = 白担回归风险**。
4. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》），否则改动静默不生效。
5. **改了时长上限**：`MAX_FINISHED_SECONDS` 在**两个脚本里各写了一份**（剪映链路和 ffmpeg 链路），改一个漏一个就会出现"两条路跑出不同长度"。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（覆盖 `test_v2_final_engine.py`、`test_v2_insertion_policy.py`、`test_v2_engine_parameters.py`）。
2. **结构类改动必须实机跑**（单元测试测不出画面）：**四种组合各生成一条草稿**，
   打开草稿确认中插 / 尾插轨**真的按设置出现或消失**。
3. **两条组合至今没实机验证过**：①中插尾插**两个都不要**（主轨只剩爆款 + 模板视频循环铺满，画面效果未知）；
   ②**任务级覆盖**（界面上还没有那个开关）。

### 改这个功能时积累的经验（**每次改完往这里加一条**）
