# 模板生成器

> 把素材拼成一个剪映 5.9 能打开的**模板草稿**（背景铺底：真人窗口 + 照片墙 + 贴纸 + 文案）。
> **他会这么说**：「模板」「模板草稿」「照片墙」「剧照」「贴纸」「花字」「祝福语」「引导语」「文案」「180 秒」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

- **入料**：1 条竖屏真人视频 + 10 张 3:4 剧照 + 贴纸库 + 花字库。
- **产出**：一个剪映草稿目录（核心文件 `draft_content.json`）。
- **之后**：交给《成片生成器》做出成片，再由《视频导出器》导出。
- **它不启动剪映**，只写草稿文件。

## 二、怎么用

1. **生产中心 → 账号×剧集卡片 → 生成模板草稿**（进度在任务中心看）。
2. **文案要改**：参数中心 →「文案」卡（祝福语池、引导语池）。

## 三、业务规则

### 模板里有什么轨道

| 轨道 | 里面是什么 | 必须有吗 |
|---|---|---|
| `T01_OUTER_VIDEO` | 中央真人视频窗口（矩形蒙版，羽化固定 1） | 必须 |
| `T02_BOTTOM_PHOTO_WALL` | 底部照片墙：10 张剧照左右滚动 | 必须 |
| `T03_TOP_PHOTO_WALL` | 顶部照片墙（同上） | 必须 |
| `T09_STICKER_SKIN_01` ~ `_16` | 16 条贴纸，**全部来自同一个皮肤** | 必须 |
| `T10_TEXT_BLESSING` | 祝福语（花字） | **看文案池** |
| `T11_TEXT_DRAMA_PROMPT` | 引导语（花字） | **看文案池** |

模板时长固定 **180 秒**。

- **T04 / T05 已取消**（用户定）：它们原来是上下两条很窄的镜面真人视频装饰带；取消后**每个模板只需 1 条真人视频**（原为 3 条）。
  代码保留归档，只有单轨调试入口还能用，正式流程不再写入。
- ⚠️ **别把照片墙和它们搞混**：照片墙（T02/T03）是**宽幅、剧照滚动**；T04/T05 是**窄条、真人视频**。用户口语里的"轨道 2、3 真人视频"指的是后者。
- T06 / T07 / T08 属于**成片**环节，模板阶段出现会被结构校验拦下。

### 文案池（在参数中心调）

- 生成时从池里**随机挑一句**（保留"每次不同"的感觉）。
- 池里**没设置过** → 用内置默认池（各 10 条）。
- 把池**清空** → **不生成那条文案轨道**（草稿里不存在该轨）。
- 字数**不限**：超出原来的 6–9 字档位时，按**最接近的字数档位**取字号。

### 照片墙：必须是 10 张，而且**必须凑满**

模板端有三道硬校验：**恰好 10 个文件**、路径不重复、**内容（SHA256）不重复**。
所以选图**不能报错，只能降级**——用户定："**宁愿 10 张里有些质量比较差，也不能少数量**"。

选图标准（按优先级）：

| 档位 | 门槛 |
|---|---|
| `strict`（最好） | 正面分 ≥0.75、脸宽 ≥90px、睁眼、不喊叫、同一位演员 ≤2 张、同一集 ≤3 张 |
| `relaxed_frontal` | 正面分 ≥0.55 |
| `relaxed_size` | 脸宽 ≥60px |
| `relaxed_all` | 只要有人脸、画面各不相同 |
| `duplicates` | 允许同一位演员反复出现，画面仍要不重复 |
| `variants`（最差） | 画面都不够时，对同一画面做**极轻微二次裁切**凑出不同文件 |

**用了哪一档会记进 `剧照准备清单.json` 的 `selection_stage`**，任务日志里也会写
"正面镜头不足，本次使用了「xxx」级别凑满 10 张"。

其它选图规则：**以人脸为中心**裁切（没检测到脸才退回画面中心）；输出统一缩到 720px 宽以内的**精确 3:4**。

### 剧照缓存（按"账号 + 剧集"复用）

- **单位 = 账号 + 剧集**。用户明确："账号a+剧集a 是一个模板，**账号b+剧集a 不能共用同一个**"。
- 放在 `<系统数据>/剧照缓存/<账号__剧集>/<素材指纹>/`。
- **指纹** = 全部素材的「路径 + 大小 + 修改时间」；**素材一变，指纹就变，自动重做**。
- 每个单位**只留最近 3 份**，更旧的自动删。

### 已知局限（如实写，不影响使用）

- **同一位演员可能出现 2 张**。用户定："**这个影响不大的，只要不是一模一样的图片就行**"——
  所以只做"画面级去重"，不做更严的身份限制。
- **"头转正"不等于"眼睛看镜头"**：本机判的是头部朝向 + 眼睑开合，不是视线方向。
- **只认人脸**：不检测全身 / 动物 / 多人关系。短剧里有动物的镜头可能被判"没人"，此时退回画面中心裁切（**不会失败**）。
- **模型读不到不会失败**：退化成"画面中心裁切 + 老的质量打分"，并在清单里记一笔。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 说明 |
|---|---|---|---|
| 祝福语池 / 引导语池 | 参数中心 →「文案」 | 内置默认池各 10 条 | 清空 = 不要那条轨道 |

写死在代码里的：模板时长 180 秒；照片墙 10 张；采样密度 24 窗 × 6 帧；正面分 0.75 / 脸宽 90px 门槛；缓存保留 3 份；贴纸 16 条。

## 五、改动须知（动这个功能前先看这段）

### 一句话：选图只能"降级"不能"报错"，改门槛前必须先跑探针

1. **照片墙永远要凑满 10 张**。模板端三道硬校验（数量 / 路径 / SHA256），少一张、重复一张都会直接报错。
   **加任何筛选条件时，必须同时给它一条降级出路**，否则整批任务失败。
2. **改采样密度或门槛前，先跑探针脚本**（见下表）——这两个值是实测扫出来的，不是拍脑袋定的。
   直接改会觉得"更严更好"，实际会把可用帧降到凑不满。
3. **3:4 必须用整数推导**（`height = width * 4 // 3`），**不要用四舍五入的浮点**——
   老代码就是浮点凑数，约 69% 的常见竖屏尺寸会差 1 像素而被精确校验拒掉。
4. **缓存命中要先校验尺寸**：否则一个坏缓存会让任务**永远**以同一个文件名失败。
5. **写诊断脚本必须调用真实流程的函数**，不要自己复刻取数逻辑；造样本时"必须互不相同"的字段（画面指纹、身份向量）要**真的不同**。这两条都是踩过的坑。
6. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（文案：`server/tests/test_v2_template_copy.py`；选人与 3:4：`server/tests/test_v2_photo_wall_faces.py`）。
2. **改选图/门槛后必须实跑**：`py -3.12 tools\verify_photo_prep_real.py` —— 真跑一次剧照准备，逐张打印尺寸 / 比例 / 正面分 / 脸宽 / 闭眼度 / 演员序号。
3. **改轨道结构后必须实跑一次 `final` 生成**，然后打开 `draft_content.json` **核对轨道名**（单测测不出轨道结构）。
4. **改候选数量前先跑** `tools\probe_candidate_density.py`；**改门槛前先跑** `tools\probe_photo_wall_thresholds.py`。
5. 环境要求：`pyJianYingDraft`、`PIL`、`ffmpeg`；花字写入还需要剪映字体目录存在 `zh-hans.ttf`，否则报缺字体。

### 改这个功能时积累的经验（**每次改完往这里加一条**）

- **2026-09-18**：老代码用四舍五入凑 3:4 → **约 69% 的常见竖屏尺寸失败**。
  **结论：比例一律整数推导；缓存命中先校验尺寸。**（坑已修，留下的是"别再用浮点凑比例"这条约束。）
- **2026-09-18**：诊断脚本自己复刻取数逻辑 → 结论与真实运行相反，白查半天。
  **结论：诊断必须调用真实流程的函数。**
- **2026-09-18**：造测试数据时用 `seed % 4` 造"身份"，8 个人实际只有 4 个。
  **结论："必须互不相同"的字段要真的互不相同。**
