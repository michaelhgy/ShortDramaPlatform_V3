> 顶部六个页签（**收益 / 账号 / 剧集 / 视频 / 组合 / 微信指数**）：把采集回来的收益数据摊开看——赚了多少、谁赚的、靠哪部剧、哪条视频能打、哪种组合最稳；微信指数单独看关键词热度。

## 一、它做什么

| 页签 | 回答什么问题 | 数据从哪来 |
|---|---|---|
| **收益** | 昨日 / 本周期赚了多少、比上一周期涨跌、数据全不全、谁贡献的 | 日收益汇总 + 采集记录 |
| **账号** | 哪个账号产出高、常推哪部剧、发布地址哪个好用 | 日收益 + 青柠视频明细 |
| **剧集** | 哪部剧赚钱、单条视频差异大不大、哪些账号在推 | 青柠视频明细 |
| **视频** | 单条平台视频的播放、收益、承接强度：爆款转化还是常规 | 青柠视频明细 |
| **组合** | 账号×剧集 / 账号×地址 / 剧集×地址，哪种组合产量稳 | 视频明细 + 发布登记 |
| **微信指数** | 关键词热度曲线（关键词挂在剧集下） | 本机微信指数采集 |

## 二、怎么用

1. **选范围（前 5 个页签共用）**：顶部「时间」选昨日 / 近7日 / 近14日 / 近30日 / 本月 / 自定义；「剧场」选青柠剧场。
2. **采集收益**：右上角「采集收益」打开采集中心 → 选范围（全部已接入 / 按剧场 / 按账号）→ 选「同步昨日」或「历史补采」→ 设起止日期 → 开始，页面显示成功 / 无结算数据 / 失败三类进度。
3. **看各页签**：收益看总量与贡献结构，账号看单账号画像，剧集看收益榜与单条差异，视频看散点与明细，组合看矩阵；行上可直接跳到别的页签。
4. **视频认成片**：对未关联的视频点关联 → 系统列出候选原素材 → 人工点选确认。
5. **微信指数**：先做本机连接初始化 → 给剧集加关键词并选角色 →「验证采集」。
6. **看采集记录**：采集抽屉下半部分，按剧场 / 账号 / 数据日期 / 结果筛选；默认只看每个账号每个日期的最新结果。

## 三、业务规则

### 数据从哪来

- 收益由后端采集后落库，页面只读：`v2_daily_revenues`（账号 × 日期的日收益）、`v2_revenue_video_details`（青柠视频级明细）、`v2_revenue_collection_attempts`（每次采集尝试）、`v2_revenue_collection_runs`（一次采集任务）。
- 已接入四个剧场：**青柠 / 顶好 / 触摸 / 花生**；青柠与顶好按天逐个日期读，触摸与花生读当期累计值（只读截止日那一次）。停用账号自动跳过。
- 青柠视频明细**按所选日期范围向数据库要**（单次最多 90 天），范围外的日期不参与本次统计；每日收益汇总按账号读回后，在页面内按所选范围汇总。
- 青柠视频明细一次最多读 12,000 条，超出时页面写明「只显示前 12,000 条，请缩小日期或按账号筛选」，并把结果标记为已截断——多读一行正是为了如实判断是否被截断。
- 采集与补采一次最多 90 天；超范围时提示「一次补采最多 90 天，请分段进行」。
- 采集是**读后核对再写**：条数与页面「共 N 条记录」不一致、或明细合计与页面总计不一致 → 报错，并且这批数据不写库。
- 自动采集在设置页开关，默认开启、默认 06:00 / 12:30 / 18:00 三个时间点；后台每 15 秒检查一次，到点补采「昨天」这一天，错过的时间点合并补采一次。

### 四种结果，四种含义（核心）

| 界面说法 | 代码值 | 含义 | 金额怎么显示 |
|---|---|---|---|
| 成功 | `success`，金额 > 0 | 来源读取并核对成功 | ¥xx.xx |
| **0收益** | `success`，金额 = 0.00 | 明确读到 0，属于有效统计 | ¥0.00 |
| **无结算数据** | `no_data` | 来源正常返回，该日没有收益记录 | —（不是 0） |
| **失败** | `failed` | 读取或核对失败，可重采 | —（不是 0） |
| **待确认** | 待确认档位（库里的取值是失败） | 来源回 0.00，且分不清「真没收益」还是「没匹配到账号」：**按失败处理并写明原因要求重采**，不许当成 0 | —（不是 0） |

- 金额列只在**成功且有金额**时显示数字，其余一律「—」：读不到的数据**不写成 0**。
- 采集记录默认只看每个账号、每个数据日期的最新一条结果，旧失败不干扰当前判断。
- 正常返回「没有记录」也算**完成过采集**：这个日期不会因为后来一次重试失败而变成缺记录。
- 收益页顶部圆点是**昨日采集完整度** = 已成功或已正常返回无数据的账号数 ÷ 总账号数；不完整时写明「N 个账号尚无日收益记录」，并注明不应按零收益解释。
- 状态标签把几件事分开写：「待补采」= 本应有数据、采集还没成功；「0收益」= 周期收益明确为 0，属于有效统计；「推测」= 金额由既定规则估算；「数据不足」= 上一比较周期不足，不显示涨跌；「历史累计」= 不受顶部时间筛选影响；「已关联 / 未关联」= 有没有关联到内部成片；「不适用」= 账号与剧集分属不同剧场。

### 明细的唯一键

- 日收益：**账号 + 数据日期**；同一天再采一次是**更新**，不新增行。
- 青柠视频明细：**数据日期 + 账号 + 平台视频 ID**；不同日期保留为独立记录，才能看同一条视频的逐日变化。
- 人工关联结果：**账号 + 平台视频 ID**，确认一次后复用于该视频后续各日；关联**必须人工确认**——系统按「首次观测日期 + 账号 + 剧名」列出候选原素材，确认时校验素材确实属于该生产任务。
- 平台剧名与本系统剧集靠**剧名匹配**：匹配上显示剧集名，匹配不上显示「待匹配剧集」，不猜、不强归；「已匹配剧集」只表示剧名对上了，不等于已关联内部成片。

### 页面怎么刷新

- 数据**跟着筛选条件走**：换时间范围或剧场就按新条件取一次；取数按筛选条件分键缓存，旧条件的响应不会盖掉新条件的结果。切换筛选条件时**不清空当前画面**：新结果回来之前一直显示上一次的数据，避免闪成空白。
- 收益只在需要时刷新，不挂定时轮询；采集完成用「最新一条采集日志的 id」当信号，信号一变页面自己重取（数据层 `revenue` 区域，不自动刷）。

### 微信指数

- 关键词**挂在剧集下**，五种角色：主关键词 / 等价词（已确认）/ 相关词（不合并）/ 待确认候选 / 不采用。
- 每个关键词**保留自己的原始曲线，不自动相加**；标点差异的等价词只作对照，合不合并由人确认。
- 采集走本机连接：连接资料只保存在当前电脑、由当前 Windows 用户加密保护，不进入剧集数据库、不随软件复制到别的电脑。
- 采集运行时每 1.5 秒刷新一次进度；同一天重复采集是**更新**同一条观测值，明确读到的 0 也保留。独立版微信指数采集分析（另一个项目 `D:\wxindex-drama-analysis`）是另一套，与本页签各自独立。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 可选值 |
|---|---|---|---|
| 时间范围 | 数据分析顶部 | 近7日 | 昨日 / 近7日 / 近14日 / 近30日 / 本月 / 自定义；终点一律是昨天，当天不计入 |
| 剧场筛选 | 数据分析顶部 | 青柠剧场 | 青柠剧场 |
| 自动采集开关与时间点 | 设置页 | 开；06:00 / 12:30 / 18:00 | 开关 + 任意合法时间点 |
| 采集范围与日期 | 采集抽屉 | 全部已接入；昨日 | 全部已接入 / 按剧场 / 按账号；同步昨日 / 历史补采 |

写死在代码里的：视频明细一次最多 `12000` 条（后端上限 20000）、读取与补采上限 `90` 天、采集进度轮询 `700` 毫秒、微信指数采集时 `1.5` 秒轮询。

## 五、改动须知（动这个功能前先看这段）

1. **四种结果不许合并成 0**：成功 / 无结算数据 / 失败 / 待确认是四件事（前端保留「待确认」档位），金额为 0 只对「成功」成立；新增任何汇总都要把「读不到」排除在数值之外，文案沿用「无结算数据」「待补采」。
2. **唯一键不能改**：日收益 `账号 + 日期`、视频明细 `日期 + 账号 + 平台视频 ID`；改键要么产生重复行，要么把同一条视频的不同日期压成一条。
3. **按日期分段读**：明细查询必须带 `revenue_date` 范围；90 天上限在 `_dates` 与 `revenue_video_details` 各有一份，放宽要两处同改，并同步前端提示与「已截断」标记。
4. **切换筛选条件不许清空旧数据**：取数按筛选条件分键（内存 + localStorage），组件只在成功回调里写新数据；加新的筛选维度要同时进缓存键，否则会串数据。
5. **别在页面里挂定时器**：收益刷新走数据层 `revenue` 区域 + 采集信号；只有微信指数采集运行时才自带 1.5 秒轮询（属进度显示）。
6. **人工关联要保留人工确认**：候选只是候选，确认时校验「素材属于该生产任务」再写 `账号 + 平台视频 ID`；任何自动写关联的改动都要保留这道确认。
7. **采集先核对再落库**：条数与总计对不上就不写；新增采集源沿用这个顺序。
8. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。
