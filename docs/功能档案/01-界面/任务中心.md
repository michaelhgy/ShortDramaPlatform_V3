# 任务中心

## 导出合成诊断（2026-11-05，开发源码已接入）

全局任务中心“成片合成”队列右上方提供“导出合成诊断”，紧邻“暂停后续成片”按钮左侧。点击先打开条件弹窗，不立即写出文件：

- 默认“最近一轮运行”：保留该轮全部任务的摘要表和趋势，详细日志默认最近30条，可设1至200条，优先包含本轮运行中的任务。运行批次按最近一条合成诊断所属的软件会话识别；每次重试单独计为一条记录。
- 默认勾选前段同条件正常样本：同会话、模板、输入规格及加速路径匹配，取前面已完成且有有效速度的每组最多3条，合计额外最多12条；没有匹配样本时不补其他任务。
- “指定任务”：按名称搜索并分页勾选1至200条诊断记录，跨页保留选择，可开关对照样本；摘要和详细记录均限定在选定及对照范围。
- “全部历史”：仅在主动选择并点击“开始导出”后执行，保留当前仍有的全部诊断文件，弹窗提示可能较大。取消或关闭弹窗不导出；读取摘要失败可重试；导出失败保留条件并可再次尝试。

报告和ZIP使用相同筛选结果；有限范围只读取所选尝试目录的详细文件，公共连续摘要和排队/页面读取事件也重新筛选，不夹带整份旧历史公共日志。报告与ZIP清单注明范围、摘要数、详细数、对照数、仅有摘要数及缺失详细记录。不能把仅剩摘要的旧运行记录附上同目录的新运行日志；无法归属的损坏摘要仅在无可识别记录时默认附至多3份原文并提示。

“开始导出”后只读当前数据盘的合成日志，在工作区“诊断输出/时间文件夹”生成“合成诊断报告.md”和“合成诊断日志.zip”，自动尝试打开文件夹，页面显示可选择的完整路径。本机D:配置对应 `D:\短剧推广运营系统\诊断输出`。无需暂停队列；导出中禁止重复提交与关闭设置，独立目录不覆盖旧证据。不含视频、素材或数据库，每个原始日志文件最多收集最近8MiB；不对压缩包总大小作固定承诺，全部历史仍可能较大。

无日志、损坏/不可读记录、无法打开文件夹、写出失败分别明确提示；运行任务仅包含当时已写出的部分，不将未结束当成失败。入口和候选记录读取均不初始化合成器、不触发任务恢复。只在完整成片队列显示，小窗/模板/风景不显示。源码、52项相关后端、类型/隔离构建及9组页面流程已通过，正式桌面待重开开发版验收，未打包。详细边界与实样见[诊断导出与实样分析](../../事项档案/2026-11-05-V3合成诊断一键导出与实样分析.md)。

## 连续合成诊断日志（2026-11-04，源码已接入，待统一打包）

成片尝试新增定时资源记录、阶段开始/结束、真实帧速和无推进时长，保存文件与数据库写入分别计时；CPU/GPU画面路径与编码器分别记录。即使没有首帧也留状态。指标缺失与日志错误明确标注，诊断故障不改变合成结果。后台资源采样默认5秒，NVIDIA指标15秒；新增JSONL每8MiB轮转，保留当前及3个后缀文件，只轮转诊断日志。

## V3 当前规则（2026-10-19）

- 顶部任务统计、任务监控小窗、全局任务中心共用每3秒更新的任务快照，汇总“成片合成”“模板制作”和“风景处理”。完成数量为现存记录累计值，不称“今日完成”。旧剪映任务单独从“剪映历史任务”入口查看，不计入新队列的运行/等待/完成数。
- 小窗显示三条队列的执行、排队、完成和失败数量，当前任务名称、账号或模板系列、实际百分比、阶段、生成耗时。空闲、暂停、等待执行和读取失败分别显示；读取失败保留上次结果并标记未更新。
- 全局任务中心按“成片合成 / 模板制作 / 风景处理”页签查看记录，支持全部、进行中、失败、已完成、已取消筛选。运行任务优先，其次排队、失败、完成、取消。
- 三条队列分别暂停/继续；暂停只停止领取后续任务，当前条继续完成。运行中请求暂停显示“本条完成后暂停”，已暂停队列的等待项显示“等待恢复”。不再用旧剪映全局按钮控制新队列。
- 单条运行状态如“合成中 22%”“制作中 36%”，使用后台实际处理进度，不按耗时模拟。运行状态最多显示99%，后台校验保存完成后显示“已完成/已入库”。
- 等待项可取消；失败项可重试；已取消成片可重试；取消模板不提供重试按钮，保持现有后台约束。
- 模板记录使用短名称。已完成但文件缺失，或已标记删除的模板，从制作记录和对应计数中隐藏，保留任务、配方、素材使用账。文件还在但使用次数已满的模板显示“使用次数已满”，不再提供选用或预览入口。
- 生产中心任务卡片和成片区的绿色进度统一为“已完成条数 / 素材总条数”，当前单条合成百分比单独显示。详见[生产中心](生产中心.md)。
- 删除生产剧集或成功清理其过程文件后，对应成片记录退出新队列及完成/失败/取消计数，顶部统计、小窗和全局中心同步更新。公共模板制作记录与使用次数不随剧集删除；其他生产任务照常显示。历史漏删的队列记录在启动时核对清理，快照也不显示已无有效父任务的记录。

### 显卡编码提示（2026-10-20，源码已接入，待后续打包）

- 成片合成和模板制作读取本次尝试的 `encoder_check.json`。确认使用 CPU 编码时，任务行显示黄色“本次使用 CPU 编码，速度可能较慢”，并说明检测原因与处理建议。全局任务中心、生产页队列、模板制作记录和监控小窗复用同一提示。
- 日志明确说明 NVIDIA 编码接口不兼容时，提示更新驱动；最低驱动版本从该日志提取，避免把接口版本当成驱动版本。其他失败显示检查显卡/驱动的通用建议，不自行断言驱动过旧。完整任务行可展开本次检测原文，小窗保留中文原因与建议。
- 提示属于该任务的本次执行记录。任务完成或失败后仍可查看；等待重试时不沿用上一次提示，新尝试只读取自己的日志。硬件编码正常、检测尚未完成或旧任务日志缺失时不显示 CPU 警告。缺失、损坏或正在写入的日志不导致任务快照失败，也不代表显卡正常。
- 读取快照不启动显卡检测，不修改任务状态或业务数据；沿用已有硬件检测与 CPU 回退行为。只在成片、模板队列接入，风景处理提示不在本次范围。

风景处理显示实际编码与检查阶段，支持等待取消、失败重试与暂停后续。原片删除失败归为未完成，重试复用已有入库文件；只有所有结果可读且对应原片删除成功才显示完成。成功记录不保留原片名称、路径或裁切关联。

## 剪映历史入口的既有说明

以下保留旧任务的显示、诊断和调度规则，入口只在存在旧记录时显示；其三执行器、草稿/导出阶段不适用于新的 FFmpeg 任务。

> 一个弹窗：在一个地方看**三个执行器在干什么**，以及**每部剧做到哪一步**；顺序可以手动调。
> **他会这么说**：「任务中心」「优先级」「排序」「置顶」「执行器」「队列暂停」「今天做哪部先」
> 最后核对：2026-10-18 ｜ 状态：V3 弹窗打开与关闭白屏修复，浏览器回归通过

## 一、它做什么

- 它是**弹窗**（不是页签），从顶部状态区的入口打开：「展开全局任务中心」。
- 列表按 **账号 × 剧集** 分组：一部剧一个**组头**，组头下面才是它的每条素材。
- 组头带 **视频 / 草稿 / 素材** 三个数字和一条三色条，和《生产中心》左侧卡片口径一致。
- **默认全部收起**，一次只展开一个组——9 部剧的组头一眼能看完。

## 二、怎么用

1. **打开**：顶部状态区 →「展开全局任务中心」。
2. **看某部剧的素材**：点它的组头展开（再点收起）。
3. **调顺序**：组头右侧的 **置顶 / 🔼上移 / 🔽下移**（已做完的剧不显示这三个按钮）。
4. 历史入口不再提供全局暂停按钮；每个旧执行器仍可独立暂停或恢复。
5. **暂停单个执行器**：执行器卡片上的按钮；「错误暂停」时点它 = 启动并**清除连续失败计数**。
6. **对某一条素材动手**：鼠标悬停在该行，才会出现动作按钮（重新生成 / 重新导出 / 重试 / 诊断 / 文件路径）。

## 三、业务规则

### 显示哪些剧

显示范围＝**已开工的剧**（有模板任务、或有成片记录的）。

### 顺序怎么排（唯一规则）

```
1. 已做完的整部剧 → 沉到最后
2. 手动调过的 → 按手动位次，从小到大
3. 没调过的 → 计划发布日期早的在前；同一天则开工早的在前，忽略旧记录中的时分
```

组内素材按**序号升序**。

### 手动调整 = 最高调度优先

置顶/上移/下移**不是只改界面**：三个执行器（模板、成片、导出）真的按这个顺序取任务。
点「置顶」时按钮上的说明就是："让三个执行器下一个就做这部剧"。

- 手动调整只在**未完成的剧**之间进行；对已完成的剧点置顶会明确报错（已完成的会自动沉到最后）。

### 组头三个数字

- **绿** = 视频已导出，**蓝** = 草稿已生成未导出，**灰底** = 素材总数。
- 还没扫描的新素材**不计入分母**，另外单独标「新素材 +N」。
- 异常数量**单独显示**，不混进正常进度。

### 执行器卡片

每个执行器显示当前状态：待机就绪 / 排队等待 / 正在执行 / 正在暂停 / 人工暂停 / 错误暂停。
点按钮可以暂停或恢复：

- 「正在执行」时点暂停 → **当前任务结束后**才生效。
- 「错误暂停」时点启动 → 恢复并**清除连续失败计数**。

### 头部

- 显示已完成的数量；有孤儿记录时，顶部会出现橙色提醒条（可一键清除）。

## 四、可调参数

没有需要在这里调的参数——队列暂停、执行器暂停都是**操作**，不是配置项。

## 五、改动须知（动这个功能前先看这段）

1. **排序键只有一处**：界面显示的位次与执行器派单用的排序，必须共用同一个排序键常量
   （`server/task_center_service.py` 的 `MANUAL_ORDER_FIRST_SQL`）。各写一套 → 会出现"界面显示第一、实际最后跑"。
2. **手动位次只在"未完成"的单位之间排**：让已完成的参与会导致"点了置顶没反应"。已完成单位收到置顶请求要明确报错。
3. **组头三个数字必须与《生产中心》同口径**，并且**和任务快照在同一次查询里取到**——多查一轮就会出现两处数字对不上。
4. **任务卡查询用 `JOIN production_tasks`**（不是 `LEFT JOIN`）：父任务被删后留下的孤儿记录会自动不出现。
5. **队列暂停只管"领取新任务"**：不要改成中断正在执行的；执行器暂停在"当前任务结束后"生效这条也要保留。
6. **手动位次字段为空 = 从没调过**（`manual_order = 0`）；派单 SQL 要先检测该列是否存在，列还没有的库降级为不排序。
7. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。
8. **组内排序只按序号升序**：不要引入任何依赖状态的浮动或分层排序——那会把素材序号排成 `5,1,2,3,4`。
9. 弹窗关闭时也保持 React Hook 的调用顺序；按打开状态决定是否取数据的条件写在 Effect 内，所有 Hook 都放在关闭状态的提前返回之前。回归覆盖关闭 → 打开 → 关闭 → 再次打开，以及全屏和还原。
