# 资料中心

> 公司所有「人、场、剧、料」的基础档案总库：**业务资料**（剧场 / 子剧场 / 账号 / 剧集）、**剧集资料库**（封面与剧情知识）、**生产资源**（磁盘上的素材储备）、**爆款资产**（沉淀下来的爆款源素材）。
> **他会这么说**：资料中心、业务资料、剧集资料库、剧集库、剧集档案、生产资源、资源库、爆款资产、爆款素材、标记爆款、剧场、子剧场、账号、改名、历史剧名
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

生产中心的每一张「账号 × 剧集」卡片，选项都出自这里。顶部四个子页签各管一摊：

| 子页签 | 管什么 | 数据来源 |
|---|---|---|
| **业务资料** | 剧场、子剧场、账号、剧集四个档案表（新增 / 批量导入 / 编辑 / 删除） | 数据库 |
| **剧集资料库** | 一部剧一份档案：封面、题材标签、原片目录、剧情知识库 | 数据库 + 磁盘目录 |
| **生产资源** | 真人视频 / 真人图片 / BGM / 引流视频四类素材储备与产能 | 扫描磁盘 |
| **爆款资产** | 沉淀下来的爆款源素材，及其历次投放记录 | 页面数据 |

## 二、怎么用

| 你想干什么 | 在哪 |
|---|---|
| 录新账号 / 剧场 / 子剧场 / 剧集 | 业务资料 → 对应子表 →「新增…」；一次多条用「批量导入…」 |
| 改账号状态 | 业务资料 → 账号管理 → 表里点一下状态就切换 |
| 改剧名 | 业务资料 → 剧集档案 →「改名 / 维护」（可同时维护历史剧名） |
| 留一份剧的封面与剧情资料 | 剧集资料库 → 选剧 →「一键建立剧集档案」→ 换封面 / 加题材标签 / 打开原片目录 |
| 看素材储备够拍几部剧 | 生产资源（页签上直接写「支持 N 剧」）→ 打开视频 / 图片 / 引流目录 |
| 标一部爆款素材、看它爆过几次 | 爆款资产 →「标记爆款」→ 选源素材 + 填投放记录 → 点素材看爆款记录抽屉（含 MD5 指纹） |

## 三、业务规则

### 剧场与子剧场

- 剧场名称唯一；分成比例与税率取值 0–100；状态只有**启用 / 停用**。新建剧集、新建子剧场必须挂在**启用**的剧场下。
- 子剧场挂在剧场下、名称唯一；已绑定账号的子剧场**不能换所属剧场**，改名时同步把账号的归属名一起改掉。删除前先查引用：剧场下有子剧场或关联账号 → 拒绝并报出**数量与名字**；子剧场已绑定账号 → 拒绝。

### 账号

| 项 | 规则 |
|---|---|
| 必填与唯一 | 昵称、平台 ID、所属剧场必填；昵称与平台 ID 都唯一（重复时报「平台iD已存在」）；报白时间只能填「未报白」或有效日期，注册时间必须是有效日期 |
| 状态 | **正常 / 观察 / 限流 / 二限 / 实名 / 封禁 / 停用** 七种；列表按此顺序排（正常在前、停用在后） |
| 批量导入 | 归属停用剧场、或子剧场不属于该剧场 → 报错中断（此前已写入的行保留）；昵称或平台 ID 重复的行**跳过**并列入结果 |
| 删除 | 先查生产任务：已有生产任务 → 拒绝删除 |

### 剧集与改名

- **剧名唯一、改名即沉淀**：当前剧名与其他剧集的当前名或历史名撞名 → 拒绝（「当前剧名或历史剧名已被其他剧集使用」）；改名后新名成为当前生效名，旧名进历史剧名，历史名可一键设为当前名，也可删掉写错的那条。
- 全系统展示的是**当前生效剧名**；生产任务按「当前名 **或** 任一历史名」认剧，所以改过名的剧，之前建的任务仍然算它的；删除剧集前查生产任务引用，已有生产任务 → 拒绝删除。

### 剧集资料库

- 一部剧一份档案，落在 `<数据盘>\剧集资料\<剧名>\`：`原片` 目录 + `封面` 目录，建档后记入 `drama_profiles`；封面只接受 **JPG / PNG / WEBP / GIF**。
- 上传封面写到「当前剧名」的封面目录，文件名形如 `<剧名>-封面.<后缀>`；剧情知识库按剧保存：主线故事梗概、核心人物小传、分镜剧本目录（可一键打开目录）。

### 爆款素材怎么标、怎么去重

- 标记爆款 = 选一条源素材，再填**一条投放记录**：发布日期、发布时间、数据来源（人工录入 / 青柠平台数据）、视频播放量、剧集播放量、收益、备注；播放量与收益支持「38.6万」这类写法，按万换算成数字。
- 平台没有视频级收益时**不勾**「有真实收益数据」——没有数字就不编数字。
- **MD5 指纹去重**：命中已有素材 → 只给这条素材**追加**一条投放记录（「不需重复保存文件」）；未命中 → 新建源素材，首次爆款时间 = 这条记录的日期。素材上的播放量与收益是**各次记录之和**，视频播放与剧集播放分别累计。

### 生产资源与资源索引

- 四类资源来自四个目录：真人视频、真人图片、BGM、引流视频；清单由后端扫描磁盘得到，页面只读。
- **资源索引**记每一个资源：路径、体积、时长、分辨率、缩略图、探测状态，并按「路径 + 文件系统标识」认文件，改名或移动后沿用同一条索引。
- 名字和体积立刻可见；时长、分辨率、缩略图由后台线程慢慢补，状态是**探测中 → 就绪**；单个文件读不出来只标这一条失败，不影响整张清单。读取资源清单时顺带对账一次索引：源文件已不在的记录被清掉，**引流视频与 BGM 的索引保留**（它们跨任务复用）。
- **产能口径**：真人视频 3 条 + 真人图片 6 张 = 支持 1 部剧；可支持剧数取两者较小值，并指出瓶颈是视频还是图片。文件名以「已使用」开头 = 已领用，不计入剩余量。

### 写入方与刷新

- **所有写入都走后端接口**：页面不拼路径、不写文件、不直接改数据库，只发起请求并显示后端返回的结果。
- 手填资料（剧场 / 子剧场 / 账号 / 剧集）订阅数据层 `catalog` 区域：**打开读一次 + 改完立刻刷**；磁盘素材订阅 `resourceIndex` 区域：**30 秒**一次。
- 某一块读失败时保留上一次的数据，提示「部分资料暂未更新：…」，其余资料照常使用。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 可选值 |
|---|---|---|---|
| 剧场默认分成比例 / 默认税率 | 业务资料 → 剧场管理 → 编辑 | 70 / 6（新建表单预填） | 0–100 |
| 子剧场分成 | 业务资料 → 子剧场管理 → 编辑 | 继承主剧场 | 0–100，可继承主剧场或独立（独立时生效值取子剧场自己的） |
| 剧场 / 子剧场状态 | 同上 | 启用 | 启用 / 停用 |
| 账号状态 | 业务资料 → 账号管理（表里点一下） | 正常 | 七种 |
| 剧名与历史剧名 | 剧集档案 →「改名 / 维护」 | — | — |

写死在代码里的：产能口径 `3` 条视频 / `6` 张图片 = 1 部剧、已领用前缀 `已使用`、资源探测状态 `pending / ready / failed`。

## 五、改动须知（动这个功能前先看这段）

1. **后端是唯一写入方**：加一个字段要同时改前端表单 + 后端校验（`create_*` / `update_*`）+ 列表或详情展示三处；只改前端会「填得进去、刷新就变回去」。
2. **唯一性靠数据库约束 + 后端预检两道**：提示语写在后端（如「剧名或历史剧名已存在」），改文案改后端，不要在前端另写一套判断。
3. **批量导入是"部分成功"**：返回 `created_count` 与 `skipped_names`；新增校验时先想清楚这一行是**跳过**还是**整批失败**（账号重复跳过、账号归属错误整批失败）。
4. **删除前必查引用**：剧场查子剧场与账号、子剧场查绑定账号、账号与剧集查生产任务；新增一种引用关系时把新检查加进对应的 `delete_*`，否则会出现删完就悬空的档案。
5. **按剧名找任务必须带历史名**：生产任务认剧用「当前名 or `drama_aliases` 里的历史名」，凡是按剧名匹配的查询都要带上这一条，漏了就表现成「改了名老任务不见了」。
6. **资源索引是磁盘的镜像**：加字段要让扫描、后台探测、缩略图接口三处都认；容量口径只在 `calculateResourceMetrics` 里算一份，界面上的「支持 N 剧」不许另算一套。
7. **资源清单接口会写库**：`GET /api/v2/production-resources` 会 upsert 索引、清理失效索引并提交，还会建四个目录、给后台线程排探测任务；打开资料中心时的种子取数也会调它，所以在别处调它同样会触发这些写入。
8. **封面路径跟着剧名走**：封面与档案目录按建档时的剧名落盘；改名之后重新上传封面会写到新剧名目录，要迁移旧文件得按旧路径找。
9. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（覆盖 `server/tests/test_v2_file_service.py`）。
2. **必须实机走一遍**：新增剧场 → 新增子剧场 → 新增账号（填平台 ID）→ 新增剧集 → 改名 → 回列表看历史剧名、看生产中心里这部戏的任务是否还认。
3. **引用保护要看提示原文**：删有账号或有子剧场的剧场、删有绑定账号的子剧场、删有生产任务的账号与剧集，四种都必须被拒绝并给出数量。
4. **生产资源要放真文件**：往四个目录各放一个文件，刷新看产能数字与探测状态（探测中 → 就绪），再给一个文件加上「已使用」前缀看剩余量是否减少。
5. **首次实机跑通后记基线**：把命令、数据盘位置、放了哪些测试文件记下来当基线，下次回归照它比。
