## 三、业务规则

### 剧场与子剧场

- 剧场名称唯一；分成比例与税率取值 0–100；状态只有**启用 / 停用**。新建剧集、新建子剧场必须挂在**启用**的剧场下。剧场删除前检查子剧场、账号、剧集三类关联，存在关联时拒绝删除并报告数量。
- 剧场管理新增“关联账号”数量列（2026-11-01）：按完整账号库的所属剧场ID统计，排除封禁（用户称封号，亦兼容历史“封号”值）、注销、停用，正常/观察/限流/二限/实名计入，无关联显示0个。随账号状态或归属更新，不受当前资料搜索/筛选影响。此列为展示统计，不更改账号档案，也不替代删除操作对全部关联的保护检查。
- 子剧场挂在剧场下、名称唯一；已绑定账号的子剧场**不能换所属剧场**，改名时同步把账号的归属名一起改掉。删除前先查引用：剧场下有子剧场或关联账号 → 拒绝并报出**数量与名字**；子剧场已绑定账号 → 拒绝。

### 账号

| 项 | 规则 |
|---|---|
| 必填与唯一 | 昵称、平台 ID、所属剧场必填；昵称与平台 ID 都唯一（重复时报「平台iD已存在」）；子剧场、收益采集器和备注允许留空。账号列表与编辑不再显示报白时间、注册时间；已有数据库日期保留，当前界面不再提交这两个字段 |
| 状态 | **正常 / 观察 / 限流 / 二限 / 实名 / 封禁 / 停用** 七种；列表按此顺序排（正常在前、停用在后） |
| 批量导入 | 固定列顺序为昵称、账号 ID、剧场、子剧场、状态、备注；旧八列表格仍可识别，忽略两个退役日期并保留备注；前三列必填，剧场须已存在且启用。状态留空默认正常，其余选填列留空则保存空值，不创建默认子剧场、不补当天日期或默认备注。归属停用剧场、或填写的子剧场不属于该剧场 → 报错中断（此前已写入的行保留）；昵称或平台 ID 重复的行**跳过**并列入结果 |
| 删除 | 先查生产任务：已有生产任务 → 拒绝删除 |

批量导入保留 Excel/Tab、逗号、分号中的中间空列，后续字段不向前补位；支持既有的两格以上空格分隔文本。填写选填列时保留完整列位置。预览展示日期与备注，输入改变后须重新解析；空值在列表和预览用「—」表示，编辑表单仍为空，保存时不自动补子剧场或日期。

### 账号头像统一显示与同步

2026-11-04：资料中心、安排任务、账号矩阵、账号详情、采集窗口及生产中心统一使用账号资料中的本地头像地址；生产任务返回真实账号ID，生产卡片按ID读取头像及剧场信息，前端不把昵称当作ID。没有本地图片或无法关联账号的历史任务显示昵称首字。现有任务库仍以昵称保存账号关系；改名后无法映射的历史任务不会猜测关联，本次不迁移任务身份或修改任务路径。

通用头像组件在加载失败后自动重试两次（0.8秒、2.4秒），仍失败显示首字；网络恢复或窗口重新获得焦点时可再次尝试，地址变化时清除旧失败状态。仅为本地缓存地址增加重试参数，不改写小V猫等外部图片的签名地址。

“获取账号”窗口增加“同步已有头像”，对本次完整预览中已存在且平台ID仍匹配的本地账号单独同步，不受当前搜索/分组/匹配筛选及勾选范围影响，不新增账号，不修改昵称、剧场、业务状态、日期、备注或账号记录更新时间。预览和“重新获取”本身保持只读；未入库账号可显示小V猫原始头像供参考。同步结果分别显示更新、跳过、失败；没有新图或下载失败保留原头像，新预览可重试。

同步后台最多4个下载并行；相同图片内容共用缓存文件，落盘防止并发竞争；提交前在同一写事务中核对账号ID及平台ID，归属已改变时拒绝挂图。成功更新头像缓存版本并发出账号变更通知，前端刷新共享账号资料与使用该账号的页面。关闭弹窗不取消同步，前端任务观察继续完成通知（软件整体退出后，重开读取当前缓存）。原头像文件保留，不清理历史缓存。

### 从小V猫获取账号

账号管理顶部在“批量导入账号”和“新增账号”之间提供“获取账号”。点击打开居中软件风格弹窗，读取小V猫已添加的视频号账号列表；获取只产生预览，用户点击“新增所选账号”才写入账号资料。

本渠道的来源字段与用途如下，后续维护不得把参考字段当作业务归属：

| 小V猫字段 | V3用途 |
|---|---|
| 平台类型与名称 | 仅展示和处理视频号账号；其他平台不混入当前账号库 |
| `uid` | 作为平台ID匹配已有账号，新增写入`channel_id`，不允许在弹窗修改 |
| `nickname` | 带入本地昵称，可调整以解决同名冲突；已有账号不随平台昵称变化改名 |
| `avatar` | 新增账号后缓存头像；已有账号可通过“同步已有头像”单独补齐或更新。已有本地缓存的账号预览优先显示同一缓存，失败保留旧图；不因此撤销账号或修改其他资料 |
| `loginStatus` | 预览、筛选与登录提示；不改写V3业务状态 |
| `groupName`、`tags` | 小V猫管理信息，其中分组可用于搜索；不自动转成剧场、子剧场或备注 |
| `fansTotal` | 预览参考，缺值显示“未获取”；不作为收入或其他业务数据回填 |

### 剧集与改名

- **剧名唯一、改名即沉淀**：当前剧名与其他剧集的当前名或历史名撞名 → 拒绝（「当前剧名或历史剧名已被其他剧集使用」）；改名后新名成为当前生效名，旧名进历史剧名，历史名可一键设为当前名，也可删掉写错的那条。
- 全系统展示的是**当前生效剧名**；生产任务按「当前名 **或** 任一历史名」认剧，所以改过名的剧，之前建的任务仍然算它的；删除剧集前查生产任务引用，已有生产任务 → 拒绝删除。

### 批量删除

- 业务资料的账号、剧场、子剧场、剧集列表支持勾选单条或「全选筛选结果」后批量删除；全选范围是当前搜索和筛选命中的所有记录，包含其他分页。
- 点击批量删除后需二次确认。实际删除逐条调用原有删除接口；已有关联的项目由后端拒绝，其他无关联项目仍可成功删除。完成后汇报成功数和失败原因，失败项保留在列表并保持勾选。
- 批量删除不级联删除账号、剧场、子剧场或生产记录，不绕过删除保护；剧集的成功使用计次仍按原规则保留。

### 剧集资料库

- 一部剧一份档案，落在 `<数据盘>\剧集资料\<剧名>\`：`原片` 目录 + `封面` 目录，建档后记入 `drama_profiles`；封面只接受 **JPG / PNG / WEBP / GIF**。
- 上传封面写到「当前剧名」的封面目录，文件名形如 `<剧名>-封面.<后缀>`；剧情知识库按剧保存：主线故事梗概、核心人物小传、分镜剧本目录（可一键打开目录）。
- **原片从哪来**：本系统不负责下载原片。外挂工具在 `D:\爆款拆解\`（手机自动化，进微信视频号小程序取原片全集），用法、环境要求、踩过的坑都写在 `D:\爆款拆解\README.md`。把下好的原片放进上面那个 `原片` 目录即可。

### 爆款素材怎么标、怎么去重

- 标记爆款 = 选一条源素材，再填**一条投放记录**：发布日期、发布时间、数据来源（人工录入 / 青柠平台数据）、视频播放量、剧集播放量、收益、备注；播放量与收益支持「38.6万」这类写法，按万换算成数字。
- 平台没有视频级收益时**不勾**「有真实收益数据」——没有数字就不编数字。
- **MD5 指纹去重**：命中已有素材 → 只给这条素材**追加**一条投放记录（「不需重复保存文件」）；未命中 → 新建源素材，首次爆款时间 = 这条记录的日期。素材上的播放量与收益是**各次记录之和**，视频播放与剧集播放分别累计。

### 生产资源与资源索引

- V3 扫描 `生成资源\风景视频`、`生成资源\真人图片`、`生成资源\引流视频`，包含子目录；类别分别为 `scenery_video`、`real_image`、`lead_video`。
- 风景视频用于后续模板制作；旧真人视频与 BGM 文件保留原位，不自动移动、改名或作为风景视频导入。V3 不再展示 BGM 的统计、分类、目录和播放入口，设置说明同步移除。
- **资源索引**记录路径、体积、时长、分辨率、缩略图、探测状态，文件改名后沿用稳定身份。视频名称和体积先显示，后台线程再补媒体信息；单个失败不影响整张清单。
- 预览通过稳定资源编号找到当前文件，读取前核对类别、所在目录、体积和修改时间；文件变化时提示刷新。目录按钮由后端按固定类别确定真实路径，空目录可创建并打开。
- 历史 `real_video`、`bgm` 索引和缓存保留，不参与 V3 列表、统计或陈旧索引清理；前端旧缓存中的这些类别也会过滤。
- **库存口径**：分别统计风景视频、真人图片和引流视频。前两类文件名以「已使用」开头或状态为已使用时不计可用量；引流视频按可复用资源统计。顶部显示可用风景视频数量，资料中心页签显示资源总项数。
- 原「3 条真人视频 + 6 张图片 = 支持 1 部剧」属于旧流程，V3 页面已撤下该换算及产能瓶颈建议。风景视频的模板制作取用规则由制作端后续接入，不编造新换算。

### 写入方与刷新

- **所有写入都走后端接口**：页面不拼路径、不写文件、不直接改数据库，只发起请求并显示后端返回的结果。
- 手填资料（剧场 / 子剧场 / 账号 / 剧集）订阅数据层 `catalog` 区域：**打开读一次 + 改完立刻刷**；磁盘素材订阅 `resourceIndex` 区域：**30 秒**一次。
- 某一块读失败时保留上一次的数据，提示「部分资料暂未更新：…」，其余资料照常使用。

## 五、改动须知（动这个功能前先看这段）

1. **后端是唯一写入方**：加一个字段要同时改前端表单 + 后端校验（`create_*` / `update_*`）+ 列表或详情展示三处；只改前端会「填得进去、刷新就变回去」。
2. **唯一性靠数据库约束 + 后端预检两道**：提示语写在后端（如「剧名或历史剧名已存在」），改文案改后端，不要在前端另写一套判断。
3. **批量导入是"部分成功"**：返回 `created_count` 与 `skipped_names`；新增校验时先想清楚这一行是**跳过**还是**整批失败**（账号重复跳过、账号归属错误整批失败）。
4. **删除前必查引用**：剧场查子剧场与账号、子剧场查绑定账号、账号与剧集查生产任务；新增一种引用关系时把新检查加进对应的 `delete_*`，否则会出现删完就悬空的档案。
5. **按剧名找任务必须带历史名**：生产任务认剧用「当前名 or `drama_aliases` 里的历史名」，凡是按剧名匹配的查询都要带上这一条，漏了就表现成「改了名老任务不见了」。
6. **资源索引是磁盘的镜像**：加字段要让扫描、后台探测、缩略图接口三处都认；库存口径只在 `calculateResourceMetrics` 里算一份；新流程不再换算「支持 N 剧」。
7. **资源清单接口会写库**：`GET /api/v2/production-resources` 会 upsert 索引、清理失效索引并提交，还会建三个 V3 类别目录、给后台线程排探测任务；打开资料中心时的种子取数也会调它，所以在别处调它同样会触发这些写入。
8. **封面路径跟着剧名走**：封面与档案目录按建档时的剧名落盘；改名之后重新上传封面会写到新剧名目录，要迁移旧文件得按旧路径找。
9. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。
10. **原片不由本系统下载**：本系统只负责"建档 + 放原片进去"，下载靠外挂工具 `D:\爆款拆解\`（手机自动化）。改这里不要顺手去接下载逻辑。

注销只改变展示、选择和后续采集资格，不清空数据库，不删除素材、草稿或成片，不自动中断已经开始的渲染/导出。底层任务记录和文件保留；不把停用或注销记录判为孤儿或触发清理。审计运行记录及剧场/剧集公共档案保留。停用与注销不同，停用仍保留历史业务展示。当前账号主表为文本状态，无需数据库结构迁移，本次没有自动更改任何现有账号。


## 查单管理（2026-11-03）

- 入口：资料中心顶部分页，位于“业务资料”右侧；剧场编辑“收益采集器”旁另有“管理查单链接”入口，前往前提示未保存的剧场修改不会保留。
- 复用资料中心浅灰底、白色圆角卡片、细边框及深色/荧光黄按钮；列表按名称/别名搜索，显示内置采集器、日/累计能力、当前生效链接、启停、配置版本及最近候选试查。未试查不显示为在线成功。
- 编辑流程：修改查单链接 → 填写该来源对应的账号 ID → 只读试查 → 预览金额/错误 → 确认生效。只读试查不写收益、累计基线、补采进度或账号关联；正常空数据及失败不作为新链接通过依据。
- 修改链接/累计期间、重新启用必须通过相同候选配置的有效试查；改动后旧试查失效。仅停用无需发起外部请求。后端同样校验，不能绕过界面按钮直接保存未经测试的链接。
- 历史链接含软件默认版本，载入后重新测试确认；保留所有配置修订及历史收益。恢复入口载入旧链接、提取码（如适用）和启停状态，期间沿用当前设置，必须按来源核对，防止回退未知期间误算累计。
- 累计来源可人工标注月份。同一期由“期间未知”补充成月份会沿用原累计基线；新月份独立计算。未知期间在界面留空，不要求操作人输入内部标记。该设置不代表来源增加了历史月份查询能力。
- 固定编号与账号/剧场绑定不变；只维护已实现来源，不提供填写链接生成新采集器功能。来源域名/页面类型或结果字段变化须重新适配；古言端原生尚未登记为可用采集器。
- 源码、隔离检查与浏览器验收见[查单管理事项](../../事项档案/2026-11-03-V3查单管理与链接配置.md)。正式桌面、真实查单及发布包另行验收。

## 短剧原片下载的逐集结果与自动队列（2026-11-09）

入口保持资料中心的“短剧原片下载”，是 V3 内的通用任务弹窗，不是独立程序或指定当前资料剧目的下载按钮。主微信第一条置顶聊天最后一组 `#剧名 + 卡片` 决定任务；只有最新组完整、剧目与剧场唯一时才开始。

下载位置取 V3 设置，按根目录/剧场/剧名保存；逐集链接、解析结果及校验凭据保存到 V3 系统数据的 `drama-download/tasks/`。界面实时显示已采、已解析、已下载、已校验及待完成集数。一部结束或停止时刷新原片列表，优先读取当前配置目录。
