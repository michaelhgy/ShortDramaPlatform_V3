# 设置

> 一个页签：全系统共用的一份配置——装在哪个盘、剪映在哪、任务超时多久、文件留几天、几点自动采集、用哪个本地 AI 模型。
> **他会这么说**：「设置」「系统设置」「数据盘」「剪映路径」「超时」「清理周期」「发布预设」「自动采集时间」「AI 模型」「保存配置」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

- 它是**页头最右侧的齿轮**（悬停显示"系统设置"），收纳**装完机基本不动**的配置。
- 全系统共用**一份**配置，存在数据盘的「系统数据」库里（`v2_settings` 表，一行一个设置项、值是 JSON）；
  模板 / 成片 / 导出三个执行器、清理循环、收益采集调度都读这一份。
- 只放"配置"：**经常要调的生产参数**（文案池、中插 / 尾插）在《参数中心》，两处各存各的、各自保存。
- 页头右上角「保存所有配置」＝**整份提交**：后端逐项校验，全部合格才写库并立刻生效；任一项不合格整份拒绝，界面弹出后端给的原因。

## 二、怎么用

1. **进入**：页头最右侧齿轮 →「系统设置」。
2. **改一项**：找到它所在的分组改掉 → 点右上角「保存所有配置」。
3. **选路径**：点「选择程序」/「选择目录」用系统选择框挑，也可以直接在路径框里输入。
4. **换数据盘**：先点「更换数据盘」并确认进入更换模式 → 选盘符 → 保存。
5. **本地视觉 AI**：点「检测环境」看 Ollama 与模型状态；缺模型点「下载」，留在本页看进度。
6. **预设与采集时间**：时间芯片上带 上移 / 下移 / 改 / 删；在输入框选好时间点后点「新增预设」/「添加时间点」。

## 三、业务规则

页面上分**六张参数卡**（存储与程序 / 生产与任务设置 / 文件清理周期设置 / 常用发布时间预设 / 本地视觉 AI / 收益自动采集定时任务），另加数据维护与系统诊断两块运维卡。下面按卡讲规则，完整清单在第四段那张表里。

### 存储与程序

- 系统根目录 = `<数据盘>\短剧推广运营系统`，**只由数据盘推导、不能手改**；标准目录树（生产文件、剧集资料、爆款素材、真人视频图片、BGM、系统数据）由系统自动建好。
- 数据盘徽标取真实状态：设置里的盘符与本机实际可用盘符比对 → 正常 / 不存在 / 无法访问；数据盘为空即"无法访问"。
- 换数据盘**不搬迁已有数据**；保存时把整份设置快照复制进新根目录，换盘不会丢剪映路径与任务设置。
- 剪映程序路径必须是**存在的 `.exe` 文件**；草稿根目录、用户数据目录必须是**存在的文件夹**；用户数据目录留空即自动识别当前 Windows 用户的剪映目录。

### 生产与任务设置

- 三个执行器各有独立超时（模板 / 成片 / 导出），超时触发保护重试或异常告警；任务中心的执行器卡片按同一个值显示超时阈值。单任务串行、模板最高优先级、剧集生产优先级是固定架构，只能看不能调。
- 「成片人工检查模式」默认关闭；开启后成片**每一集**导出前暂停等人工确认。这个值在建任务那一刻写进任务，改开关只作用于之后新建的任务。
- 「原素材视频处理」默认开启：生成成片前分析片头片尾、裁掉黑边、抹掉原素材上的剧名水印；关闭时跳过分析直接用原素材合成，时长上限照旧。

### 文件清理周期设置

- 两项：原素材保留时间（天）、短期过程文件清理时间（小时），都从**发布登记记录的发布时间**起算；删除范围与流程见《清理系统》。
- 长期资产永久保留、不参与自动清理：爆款素材库的收藏分镜与片段、BGM 母本、剧集母本资料与分镜结构库。

### 常用发布时间预设 / 默认发布日期

- 预设是「安排今日」里的快捷标签，可增删改与上下排序，格式 `HH:MM`，重复的时间点会被拒；默认发布日期偏移 0 天 = 当天，只接受 0 或更大的整数，新建任务后仍可逐条改。

### 本地视觉 AI

- 三档：兼容模式（`qwen2.5vl:3b`，约 3.2 GB）、质量模式（`qwen2.5vl:7b`，约 6.0 GB）、关闭（只用 OCR 与固定规则）。模型经 Ollama 下载，下载期间本页每 1.5 秒刷一次进度。
- 模式在**保存后**用于下一条成片草稿任务；正在生成的任务按它开始时的设置走。

### 收益自动采集定时任务

- 开关 + 时间点列表（`HH:MM`、互不重复、至少留一个）。到点自动发起采集，采集的是**前一自然日**。
- 当天首次打开软件时，已错过的时间点合并补采一次；已经采过的槽位不重复采。已有采集在排队或进行中时本轮跳过，等下一次检查（每 15 秒看一眼）。

### 保存与生效

- 设置页打开时读一次、改完立刻刷，不定时轮询；保存成功即生效。保存失败时界面原样保留，弹出的提示就是后端给出的原因（范围、格式、路径是否存在都由后端判）。

## 五、改动须知（动这个功能前先看这段）

1. **加 / 改一个设置项必须同时改四处**：① 表单状态与控件（`SettingsView.tsx`）；② `handleSave` 的提交对象；③ 后端 `DEFAULT_SETTINGS`；④ 后端 `update_v2_settings` 的校验分支。前端类型 `V2Settings`（`src/api/v2Catalog.ts`）一起加。只改表单 → 后端报"包含不支持的系统设置"。
2. **范围校验写在后端**：新数字项照抄 `update_v2_settings` 里"类型 + 闭区间"的写法；界面输入框的 `min`/`max` 只是提示，不是拦截。
3. **改完回头找读者**：每个设置项都有人在别处读（`get_v2_settings()` 的调用点）。三个超时 `template_timeout_min` / `final_generation_timeout_min` / `video_export_timeout_min` 的读者是 `server/template_engine/runner.py`、`server/final_engine/runner.py`、`server/task_center_service.py` 的 `timeout_keys`；清理两项的读者在清理循环；视觉 AI 模式的读者在成片生成器。改键名或改含义要连读者一起改。
4. **保存一定走"数据盘"分支**：表单每次都提交 `data_drive`，所以每次保存都会重算系统根目录、重写 bootstrap、建标准目录、把整份设置快照写回库；改这一段要保住"设置不丢"这条性质。
5. **开关的生效时机分两种**：写进任务快照的（`final_video_manual_check` 建任务时落进 `production_tasks`）只影响之后新建的任务；每次读取的（三个超时、两项清理期限、`final_raw_material_process`、`local_vision_ai_mode`）下一轮就生效。改哪一类都按这个时机写界面文案。
6. **两个接口各管一份参数**：设置页保存走 `/api/v2/settings`；参数中心走 `/api/v2/engine-parameters`（`template_copy`、`midroll_endroll_strategy`）。各自的保存只动自己那份。
7. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（覆盖 `server/tests/test_v2_file_service.py`、`server/tests/test_v2_revenue.py`、`server/tests/test_v2_task_center.py`）。
2. **保存要实机看**：改一项 → 保存 → 刷新页面再进来，值还在；把某一项填到范围外保存，被拒且提示能看懂。
3. **时间类要实机看**：预设加重复时间被拒；采集时间点删到只剩一个就删不动；关掉自动采集到点不发起，打开后到点自动采到前一自然日。
4. **换数据盘要实机看**：保存后新盘根目录建好、设置还在、生产中心仍能读到任务。
5. **首次实机跑通后记基线**：把命令与现场条件（数据盘、剪映是否已装、Ollama 状态）记进 `docs/验证基线.md`。
