# 工作台

> 首页：一屏看完"今天排了哪些、账号昨天怎么样、今天该上哪部剧"。
> **他会这么说**：「工作台」「首页」「探索版」「标准版」「今日决策速报」「流水线」「账号矩阵」「热度雷达」「昨日收益」「工作台那些假数据」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

- 它是**首页**（顶部导航第一个页签），开软件默认停在这里。
- 它把三件事摆在一屏：**今天的排期**、**账号昨天表现**、**今天选哪部剧**。
- 页头有**两套版式**：**探索版**（默认，卡片式决策看板）与**标准版**（左排期、右账号 + 剧集三栏）。
- 页面上的数字分两类：

| 类型 | 包含 | 行为 |
|---|---|---|
| **真实数据** | 账号名单、昨日收益、页头状态条（执行 / 等待 / 完成） | 跟着系统走，按《数据与刷新》的节奏更新 |
| **示意数据** | 决策速报、排期初值、账号矩阵、热度雷达、剧集推测 | 固定值：进软件什么样，退出前就是什么样 |

## 二、怎么用

1. **开软件**：默认落在「工作台 · 探索版」。
2. **换版式**：页头中间的「探索版 (Explore ✨) / 标准版」——在工作台页签、窗口够宽时出现。
3. **排期**：探索版用「采纳推荐并一键填充排期」、账号卡「快速配对」、剧集卡「安排」/「矩阵排期」；标准版用排期区里的「安排今天任务」/「添加剧集」打开排期弹窗。
4. **改时间 / 移除**：排期卡片上的时间标签点开改时间，卡片上的垃圾桶移除。
5. **进生产**：卡片上的「生产看板」跳到生产中心。
6. **看机会**：右栏「剧集热度雷达 & 选剧机会榜」，可按题材筛选。

## 三、业务规则

### 首页由哪几块组成，数字从哪来

| 版式 | 区块 | 数字来源 |
|---|---|---|
| 探索版 | 今日运营决策速报（3 张策略卡 + 昨日总营收 + 一键填充） | 示意数据 |
| 探索版 | 今日制作与发布流水线（三档时间窗 + 账号分组卡） | 排期（见下） |
| 探索版 | 账号矩阵雷达（健康标签、迷你走势） | 示意数据 |
| 探索版 | 剧集热度雷达 & 选剧机会榜 | 示意数据 |
| 标准版 | 今日制作与发布 | 排期（见下） |
| 标准版 | 昨日账号表现 | **真实**：账号 + 昨日收益 |
| 标准版 | 近期剧集表现（推测收益区间、命中率） | 示意数据 |

### 示意数据具体在哪几处（看到这些就是示意数据）

- 速报里的「昨日总营收」＝示意账号的昨日收益求和；旁边的 `+18.4%`、标题里的「3 项重点机会」是固定文案。
- 策略卡的标题、预估单号收益、推荐动作，全部来自示意清单。
- 账号矩阵的账号名、健康标签（爆发主攻 / 流量爬坡 / 未排期预警 / 防限流观察 / 稳定长尾）、涨跌与迷你曲线。
- 热度雷达的热度分、市场排名、钩子评价、预估收益区间、完播率。
- 标准版「近期剧集表现」的推测收益区间、命中率与推荐理由。

### 示意数据的边界

这几块是**未完成模块**的占位内容：**数值固定不变是刻意为之**，它们和生产中心、数据分析的数字对不上属于预期表现。
要接真实数据，按第五段第 3 条走。

### 排期这一块的数据怎么走

- 起点是固定的示意排期；从本页走「安排今日」弹窗排的任务会真的创建到生产任务库（生产中心、任务中心能看到），并在**本次运行内**追加到本页列表。
- 计划发布时间必须是 `YYYY-MM-DDTHH:MM`；界面上给人看的"今天 18:30"只是标签，两者在排期弹窗里分开保存。
- 三档时间窗按发布时间的文本前缀归类：`09:`/`12:` → 午间轻娱档，`18:`/`19:`/`20:` → 晚黄金峰值，`21:`/`22:`/`23:` → 深夜长尾档；其余时间不进任何一档。
- 列表按账号分组，组内一条一部剧；排期为 0 条时，区块中央给「安排今天任务」按钮。

### 页面上的动作

- 探索版的排期动作都汇聚到同一个"创建生产任务"调用；「矩阵排期」给**前 3 个正常账号**按 18:30 / 19:45 / 21:00 建阶梯排期。
- 速报右上角的「一键填充」给"尚未排期"的示意账号按各自推荐剧目各建一条今天 18:30 的排期；没有可补的账号时回一条提示。
- 「一键推送到剪映」这类按钮的动作是回一条执行提示。

## 四、可调参数

本页没有配置项。版式（探索版 / 标准版）是页面状态，不进库。
与首页有关的可调项都在《设置》页：常用发布时间预设、默认发布日期偏移。
写死在代码里的：示意数据本体（`src/exploreMockData.ts`、`src/mockData.ts`）、速报的 `+18.4%` 与「3 项重点机会」。

## 五、改动须知（动这个功能前先看这段）

1. **示意数据只改数据文件**：探索版改 `src/exploreMockData.ts`（`EXPLORE_INSIGHTS` / `EXPLORE_DRAMAS` / `EXPLORE_ACCOUNTS`），标准版与排期初值改 `src/mockData.ts`（`INITIAL_SCHEDULE_TASKS` / `RECENT_DRAMA_PREDICTIONS`）。
2. **写死在组件里的文案必须与数据一起改**：`+18.4%`、「3 项重点机会」在 `src/components/explore/DecisionBriefing.tsx`，改数字不同步改这两句就会自相矛盾。
3. **要接真实数据时才动这几块**：平时保持固定值——速报、账号矩阵、热度雷达、近期剧集表现的数字与别处不一致属于预期表现，收到"数字对不上"的反馈不动它们。
   接真实数据时：先在 `src/services/dataHub.ts` 的 `areaIntervals` 注册区域，再用 `useDataArea` 订阅；
   在组件里自写 `setInterval` 或直接调 api 会绕开《数据与刷新》的统一节奏。
4. **一次只换一块**：速报、流水线、账号矩阵、热度雷达、近期剧集表现彼此独立，按块替换数据源，不做整页重写。
5. **排期动作必须落库**：本页所有排期按钮都走 `src/App.tsx` 的 `handleSaveNewSchedule`
   → `src/api/v2Production.ts` 的 `createV2ProductionTask`；新增按钮复用这个函数。
   并保证 `plannedPublishAt` 是 `YYYY-MM-DDTHH:MM`：排期弹窗用 `publishLabel` 显示"今天 18:30"，
   机器用的标准时间单独放进 `plannedPublishAt`。
6. **版式有两个判断点，要成对改**：`src/App.tsx` 的 `workbenchMode` 挂载逻辑与 `src/components/Header.tsx` 的切换按钮。两套版式互斥挂载，切版式等于重建当前版式。
7. **真实数据只有两条链路**：账号与昨日收益走 `getV2Accounts` + `loadV2DailyAccountRevenueSummary`，页头状态条读任务中心快照；改这块要保住这两条。
8. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。
