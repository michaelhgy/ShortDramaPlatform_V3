# 三层状态

> 生产中心卡片上那些状态是怎么来的：**后端算，前端只显示**。
> **他会这么说**：「状态不对」「卡片显示不对」「为什么显示导出中」「三层」「已就绪」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

生产中心一张卡 = 一个「账号 × 剧集」。卡上分**三层**：素材（左侧总阶段）、模板区、成片区。
所有状态由**后端**根据数据库 + 执行器当前任务 + 实际文件校验算出来；**前端只显示，不自己推断**。

## 二、怎么用

- **左侧卡片**：看这部剧走到哪一步（总阶段）。
- **右侧区域**：上面模板、下面成片，各自显示草稿 / 视频两个阶段的进度。
- 异常数量**单独显示**，不混进正常进度里。

## 三、业务规则

### 后台任务的通用状态

排队中 / 执行中 / 成功 / 失败 / 超时 / 暂停 / 已取消 / 已完成。
失败、超时和人工中断**必须保留错误原因和时间**。

### 左侧任务卡（总阶段）

| 后端状态 | 显示 | 什么时候是它 |
|---|---|---|
| `released` | 已登记发布 | 发布登记完成 |
| `action_required` | 待处理异常 | 存在草稿或视频异常 |
| `final_processing` | 成片处理中 | 成片草稿排队/生成、草稿已生成待导出、视频排队/导出 |
| `awaiting_release` | 待登记发布 | 当前全部已提交成片都已导出并通过校验 |
| `awaiting_final_generation` | 待生成成片 | 模板视频已就绪，仍有素材未完成成片 |
| `template_processing` | 模板处理中 | 模板草稿或模板视频处于排队/执行/已生成等待导出 |
| `template_error` | 模板异常 | 模板草稿或模板视频失败/超时 |
| `awaiting_template` | 待制作模板 | 已有素材，尚未创建模板任务 |
| `awaiting_scan` | 待扫描素材 | 素材目录里有未登记的视频 |
| `awaiting_material` | 待导入素材 | 没有可处理素材 |

### 模板区域

| 后端状态 | 显示 | 什么时候是它 |
|---|---|---|
| `not_generated` | 草稿·待生成 | 尚未创建模板任务 |
| `draft_queued` | 草稿·排队中 | 模板任务已创建，未被模板生成器领取 |
| `draft_generating` | 草稿·生成中 | 模板生成器当前任务 |
| `draft_retrying` | 草稿·重试中 | 正在终止并重新排队 |
| `draft_ready` | 草稿·已生成 | 剪映模板草稿已实际写出，尚未创建导出尝试 |
| `video_queued` | 视频·排队中 | 模板导出尝试已创建，未被视频导出器领取 |
| `video_exporting` | 视频·导出中 | 视频导出器当前模板任务（含提交后的文件监测） |
| `video_ready` | 视频·已就绪 | 模板 MP4 与配对参数存在、通过校验，且属于同一模板版本 |
| `draft_error` | 草稿·异常 | 模板草稿阶段失败或超时 |
| `video_error` | 视频·异常 | 模板视频导出阶段失败或超时 |

**只有 `video_ready` 才允许提交成片生成任务**；草稿写出 ≠ 模板视频就绪。

### 成片区域

| 后端状态 | 显示 | 什么时候是它 |
|---|---|---|
| `not_generated` | 草稿·待生成 | 素材已扫描但未提交成片任务 |
| `draft_queued` | 草稿·排队中 | 成片任务已提交，未被成片生成器领取 |
| `draft_generating` | 草稿·生成中 | 成片生成器当前任务 |
| `draft_ready` | 草稿·已生成 | 剪映草稿已实际写出，尚未进入导出队列 |
| `video_queued` | 视频·排队中 | 导出尝试已创建，未被视频导出器领取 |
| `video_exporting` | 视频·导出中 | 视频导出器当前任务（含剪映提交后的文件监测） |
| `video_exported` | 视频·已导出 | 正式 MP4 存在并通过媒体校验 |
| `draft_error` | 草稿·异常 | 草稿生成失败或超时 |
| `video_error` | 视频·异常 | 视频导出失败或超时 |

「视频·导出中」的**唯一权威是视频导出器的 `current_task_id`**：数据库里有活动记录但不属于当前执行器的，不显示成"正在导出"。

### 统计数字的口径

- **排队任务不计入"草稿已生成"**，只有 `draft_ready` 才计入。
- 只有 `video_exported` 才计入**视频完成**。

### 人工检查模式

- 设置里的 `final_video_manual_check` 只是**新建剧集时的默认值**；每个剧集保存自己的开关，
  生产中心按钮改的是**当前剧集**，不影响别的剧集。
- 视频导出器在**真正开始该剧集导出前**重新读一次开关 —— 排队中的后续任务会**实时采用最新设置**。
- 已经进入 `awaiting_human_check`（等待人工检查）的那一条**不会因关闭开关而跳过**；关闭从下一条生效。

### 接口字段

生产任务摘要和详情返回：`task_display_status`（左侧卡）、`template_display_status`（模板区）、
`videos[].display_status`（单条成片）。

## 四、可调参数

| 参数 | 在哪调 | 默认 |
|---|---|---|
| 人工检查模式 | 设置页（新建剧集的默认值）+ 生产中心按钮（改当前剧集） | 关 |

## 五、改动须知（动这个功能前先看这段）

1. **状态只由后端算**：前端不得自行推断、拼装或降级显示状态；页面只渲染后端给的值。
2. **状态判定要同时看三样**：数据库记录、执行器当前任务、实际文件校验。只看数据库会把"文件其实不在"显示成就绪。
3. **「导出中」认执行器的 `current_task_id`**，不认数据库里的活动记录。
4. **统计口径跟着状态走**：改状态定义时，同步检查"草稿已生成""视频完成"等计数，避免两处口径分叉。
5. **人工检查开关的生效边界**：改动它时保留"排队中的任务实时读最新值、已进入等待的不跳过"这两条。
6. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

| 干什么 | 文件 |

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（`server/tests/test_v2_file_service.py`、`test_v2_task_center.py`）。
2. **改状态定义后实测**：造一个任务走完"素材→模板草稿→模板视频→成片草稿→成片视频"，
   逐层核对卡片显示与上表一致；再故意让某一步失败，确认异常单独显示。
