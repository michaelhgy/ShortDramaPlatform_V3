# 界面与开发规范

> 界面上怎么加东西、改代码有哪些硬规矩。
> **他会这么说**：「界面」「按钮放哪」「新页面」「能不能加个页签」
> 最后核对：2026-09-19 ｜ 状态：已整理
> 溯源：由原《UI迁移规则》《UI界面基线》《V2开发规范》合并而成，三份原件在 `docs/archive/`。

## 一、界面怎么加

- **新界面必须用项目现有的 UI 元素拼装**，不得自创一套新的 UI 体系：复用现有弹窗、抽屉、表单控件、按钮、卡片、Toast；**不引入新组件库、不另起配色与间距规则**。
- 新增入口放在**已有页面 / 已有操作流**里（如生产中心、设置页）；**要新增页签需用户批准**
  （例：2026-09-18 批准的「参数中心」页签）。
- 视觉参照现成的同类界面：`src/components/assets/modals/`（各类弹窗）、`src/components/settings/SettingsView.tsx`（设置表单）。
- 保持一致的交互习惯（确认/取消、加载态、空态、错误提示）。
- **顶部导航**，未获设计授权不改左侧导航。
- 数据为空时：**保留原页面结构**，只在该区域用它自己的空列表 / 空表格表现；不显示示例业务数据，也不显示"接口未接入"这类技术说明。

## 二、数据只能这么拿

- 页面只负责：用户操作、页面本地 UI 状态、调对应模块的 service、按返回的展示模型渲染加载 / 空 / 错误 / 成功。
- **禁止**：组件里直接 import `*MockData.ts`；组件里自己造账号 / 收益 / 任务 / 剧集 / 文件路径等业务数据；绕过 service 直接调 API；
  把"失败 / 无数据 / 未知"显示成 0、成功或已完成。
- Mock 仅供显式开发调试（`VITE_V2_DATA_SOURCE=mock`），且只能经 `src/services/mockServices.ts` 或模块 service 暴露。

## 三、改代码的硬规矩

- **数据库结构一改，必须把 `SCHEMA_VERSION` 加 1**（建表 / 建索引 / 建触发器 / ALTER TABLE 都算）。
  忘了加，整套 DDL 会被跳过、**改动静默不生效**——这是最难查的一类问题。
- 未经单独授权，不修改 V1、SQLite 结构、文件规则或剪映代码。
- 新页面或共享改动要跑 `npm run lint`；涉及构建跑 `npm run build`。
- **构建通过 ≠ 已验收**：桌面窗口、剪映、真实媒体流程要另行说明验证边界。
- 交付时说清：改了哪些文件、真实接口、数据来源、验证结果，并区分"已实现 / 静态检查通过 / 真实桌面验收"。

## 四、桌面基线

- 窗口 `1440x920`，最小 `1100x720`；测试脚本 `tools/run_v2_desktop_test.py`。
- 涉及布局的改动要检查 100% / 125% / 150% Windows 缩放，以及主页面、弹窗、抽屉各自的滚动行为。

## 五、改动须知（动这个功能前先看这段）

1. **新界面用现有元素拼装**：复用现有弹窗 / 抽屉 / 表单控件 / 按钮 / 卡片 / Toast；不引入新组件库，不另起配色与间距。
2. **新增页签要经批准**；新增入口优先放在已有页面或已有操作流里。
3. **数据只走 service / adapter**：组件不直接 import `*MockData.ts`、不自造业务数据、不绕过 service 调 API。
4. **改数据库结构必加 `SCHEMA_VERSION` +1**：建表 / 建索引 / 建触发器 / ALTER TABLE 都算；
   忘了加，整套 DDL 会被跳过、改动静默不生效。
5. **改完要跑** `npm run lint`（涉及构建再加 `npm run build`）；构建通过不等于已验收。
6. **交付时说清**：改了哪些文件、真实接口、数据来源、验证结果，并区分"已实现 / 静态检查通过 / 真实桌面验收"。

### 代码入口

| 要改的东西 | 去哪 |
|---|---|
| 顶部导航与页签 | `src/components/Header.tsx`、`src/App.tsx` |
| 复用的弹窗范例 | `src/components/assets/modals/` |
| 复用的表单范例 | `src/components/settings/SettingsView.tsx` |
| 数据流分层（页面→service→adapter→api） | 见《数据与刷新》§代码入口 |
| 数据库结构脚本 | `server/v2_file_service.py`（顶部 `SCHEMA_VERSION`） |

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（后端测试 + 前端类型检查 + 前端单测）。
2. **涉及布局的改动**：用 `tools\run_v2_desktop_test.py` 起窗口，检查 100% / 125% / 150% 显示缩放，
   以及主页面、弹窗、抽屉各自的滚动行为。
