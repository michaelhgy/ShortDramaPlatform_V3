# 清理系统

> 软件自动把"用完的东西"删掉：发布满 24 小时删中间产物，满 7 天删原素材；另有一键清理和孤儿记录体检。
> **他会这么说**：「清理」「删剧集」「保留期」「24 小时」「7 天」「幽灵任务」「孤儿」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

两套**各自独立**的删东西机制：

| | **A. 删除剧集**（你说删就删） | **B. 发布后清理**（到点自己删） |
|---|---|---|
| 谁触发 | 你在生产中心点"一键清理" | 后台**每 30 秒**自己检查一遍 |
| 任务主表 | 删整行 | **保留**，登记信息永久留存 |
| 磁盘 | 整个任务目录 | 24 小时后：模板 / 成片 / 缓存 / 剪映草稿；7 天后：原素材 |
| 撤销 | 不可撤销 | 不可撤销（登记信息仍在） |

## 二、怎么用

1. **清理某部剧**：生产中心 → 卡片 → 一键清理 → **先给预览**（删什么、多大）→ 确认才真删。
2. **看有没有"幽灵任务"**：任务中心顶部——有孤儿记录时会自动出现橙色提醒条，可一键清除。
3. **改删除期限**：设置页 →「文件清理周期设置」。

## 三、业务规则

### 两个时间点，在**登记发布那一刻**就算好了

```
process_cleanup_at = 实际发布时间 + 24 小时   ← 到点删中间产物
raw_cleanup_at     = 实际发布时间 + 7 天      ← 到点删原素材
cleanup_status     = active
```

设置页改的期限，作用于**之后新登记的发布**；已登记任务的时间是当时算好的。

### 状态怎么走

```
active ──(24 小时到)──▶ process_cleaned ──(7 天到)──▶ raw_cleaned   （终态）
   │                          │
   └─ 删失败 ─▶ partial        └─ 删失败 ─▶ raw_partial
                （下一轮自动重试）
```

### 删除剧集 = **连子表一起删**

删一部剧会同时删掉它名下的：导出尝试 → 导出任务 → 模板任务 → 成片任务 → 生产文件 → 预约 → 追踪记录。

### 一个文件被占用，不拖住整批

删文件遇到"被占用"这类**可重试**的错误会退避重试 3 次；**仍失败只跳过该文件、继续删下一个**。

### 孤儿记录（"幽灵任务"）

- 什么叫孤儿：**子表记录还在、但它所属的任务已经被删了**，界面上会显示成「未知账号 ×《未知剧集》」。
- 体检：任务中心顶部的提醒条；命令行 `tools/cleanup_orphans.py`（默认预演，加 `--apply` 才真删）。
- 清理**只删数据库行**。

### 变更事件只留最近 1,000 条

裁剪随 30 秒清理循环走，**节流 10 分钟**一次。

### 已结算明细：只在"原素材也清完"时才列进清理名单

`process_cleaned` 阶段保留明细便于排查；**主表行始终保留**（发布登记 / 时间 / 地址 / 收益关联都在主表）。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 范围 |
|---|---|---|---|
| 发布后短期清理（小时） | 设置页 →「文件清理周期设置」 | 24 | 1~168 |
| 原素材保留（天） | 同上 | 7 | 1~90 |

写死在代码里的：变更事件保留 1,000 条；文件删除重试 3 次；扫描间隔 30 秒。

## 五、改动须知（动这个功能前先看这段）

1. **删父对象必须级联删子表**：漏一张，界面上就会出现「未知账号 ×《未知剧集》」分组。
   做任何"删除"类改动，先列出它名下的子表。
2. **改保留期改设置项，不动已算好的时间戳**：已发布任务的 `process_cleanup_at` / `raw_cleanup_at`
   是发布时的快照，新期限只作用于之后的发布。
3. **删文件走 `_remove_one()`**：它负责识别可重试错误、退避、单个失败不拖累整批。自己写 `unlink` / `rmtree` 会绕过这些。
4. **到期扫描走索引** `idx_production_tasks_cleanup_due`：改查询条件时保住这个索引，否则会退回"每 30 秒全表捞一遍"。
5. **改触发器定义 = DROP + CREATE**：安装语句是 `CREATE TRIGGER IF NOT EXISTS`，只改定义不生效；同时升 `SCHEMA_VERSION`。
6. **动 `run_due_cleanup()` 之前，先确认它没有在高频重入**：它是长事务（先写库、再真删文件、最后才提交），
   异常时 `last_cleanup` 不更新会导致重复进入并堵住任务中心派单。
7. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。

### 代码入口

| 干什么 | 文件 | 关键函数 / 常量 |
|---|---|---|
| 到期计算、状态机、扫描、删文件 | `server/v2_file_service.py` | `run_due_cleanup()`、`_remove_one()`、`_due_at_or_backfill()` |
| 登记发布时算两个到期时间 | 同上 | 登记发布接口里写 `process_cleanup_at` / `raw_cleanup_at` 的那段 |
| 孤儿体检 / 清除 | 同上 | `preview_orphan_records()`、`cleanup_orphan_records()` |
| 已结算明细体检 / 清除 | 同上 | `preview_settled_detail_records()`、`cleanup_settled_detail_records()` |
| 变更事件裁剪 | 同上 | `CHANGE_EVENT_RETENTION`、`_prune_change_events()` |
| 30 秒清理循环 + 裁剪节流 | `server/task_center_service.py` | `_loop()` |
| 命令行孤儿清理 | `tools/cleanup_orphans.py` | `--apply` 才真删 |

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（清理相关主要在 `server/tests/test_v2_file_service.py`）。
2. **删剧集后跑一次** `python tools\cleanup_orphans.py` 预演 → 应为 **0 条孤儿**。
3. **发布后清理跑完**，`GET /api/v2/task-center/settled-records` 的 `total` 应为 0。
4. 孤儿为 0 时，任务中心顶部的提醒条不出现。
