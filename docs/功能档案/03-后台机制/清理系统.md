## V3 当前清理范围

- “删除剧集”针对当前账号下这条生产任务：删除任务目录、成片、任务临时文件，以及旧任务表和 FFmpeg 成片队列中的对应记录、模板选用关系。其他账号制作的同名剧集不受影响。
- 成功交付官方后台后的“立即清理”及到期清理，共用同一份任务专属文件清单：过程清理成功后移除该任务的 FFmpeg 队列与选用关系，保留生产记录、发布记录、作品关联、收益分析和清理记录。原素材继续按成功交付时间保存的到期时间清理，默认过程文件 24 小时、原素材 7 天。
- FFmpeg 任务专属目录为 `系统数据/fg/<成片任务编号前12位>`，所有尝试目录一起进入预览和清理。只按任务编号确定归属；编号异常、路径跳转或与其他任务冲突时停止清理，不能通过配方中的路径扩大删除范围。
- 公共模板视频、`系统数据/tg` 模板复用缓存、素材库和成功成片的模板使用账保留。删除生产任务不退回已消耗的模板次数。
- 同一生产任务还有等待或运行的 FFmpeg 成片时，预览提示阻止原因，确认按钮不可用，后台也拒绝删除；定时清理跳过它。不会自动取消或恢复队列。
- 文件清理失败时保留任务与队列记录，按原有失败重试规则处理。成功清理后，生产页面立即刷新，任务小窗及全局中心从同一快照移除记录和计数。
- 启动时核对历史残留：父生产任务已删除或过程清理已完成的 FFmpeg 队列与选用记录被移除；成功使用账和历史磁盘文件保持原样。快照和任务投影也检查父任务状态，避免旧记录重新显示或恢复成片明细。

新队列的清理不依赖历史外部草稿的“孤儿记录”入口。实际修复和验证见[删除剧集联动事项](../../事项档案/2026-10-19-V3删除剧集联动FFmpeg任务清理.md)。

## 一、它做什么

两套**各自独立**的删东西机制：

| | **A. 删除剧集**（你说删就删） | **B. 发布后清理**（到点自己删） |
|---|---|---|
| 谁触发 | 你在生产中心点"一键清理" | 后台**每 30 秒**自己检查一遍 |
| 任务主表 | 删整行 | **保留**，生产、发布、作品关联和分析信息留存 |
| 磁盘 | 整个任务目录及任务专属外部缓存 | 过程文件到期后：FFmpeg成片 / 缓存 / 任务专属临时文件；原素材到期后再删原素材；公共模板和公共资源保留 |
| 撤销 | 不可撤销 | 不可撤销（生产、发布和分析记录仍在） |

## 二、怎么用

1. **清理某部剧**：生产中心 → 卡片 → 一键清理 → **先给预览**（删什么、多大）→ 确认才真删。
2. **看有没有"幽灵任务"**：任务中心顶部——有孤儿记录时会自动出现橙色提醒条，可一键清除。
3. **改删除期限**：设置页 →「文件清理周期设置」。

## 三、业务规则

### 两个时间点，在**整批成功交付官方后台并确认作品归属时**就算好了

```
process_cleanup_at = 最后一条成功交付时间 + 24 小时   ← 到点删中间产物
raw_cleanup_at     = 最后一条成功交付时间 + 7 天      ← 到点删原素材
cleanup_status     = active
```

官方已接受的平台定时也计交付完成，不等待公开。优先使用小V猫成功任务的 `postEndTime`；缺失时从首次核实交付的时间起算，不使用上传开始、任务创建或计划公开时间。新增 `delivery_completed_at` 保存生产交付完成时间；`actual_release_time` 和作品历史中的实际公开时间保持原含义，不提前改写收益匹配日期。旧任务缺交付时间且没有已保存期限时，仍用原实际发布时间兜底。小V猫成功记录中的作品ID，或已匹配归属的作品ID，必须可核对；仅本地排队或本机定时不触发。过程文件清理后退出“已完成”，不显示历史归档卡片。

设置页改的期限，作用于**之后确认整批成功交付的发布**；已进入清理周期的任务时间是当时算好的。

### 状态怎么走

```
active ──(24 小时到)──▶ process_cleaned ──(7 天到)──▶ raw_cleaned   （终态）
   │                          │
   └─ 删失败 ─▶ partial        └─ 删失败 ─▶ raw_partial
                （下一轮自动重试）
```

### 删除剧集 = **连子表一起删**

删一部剧会同时删掉它名下的：导出尝试 → 导出任务 → 旧专属模板任务 → 成片任务 → 生产文件 → 预约 → 追踪记录，以及独立模板库中的 FFmpeg 成片队列和模板选用关系；公共模板制作记录与成功使用账独立保留。

### 一个文件被占用，不拖住整批

删文件遇到"被占用"这类**可重试**的错误会退避重试 3 次；**仍失败只跳过该文件、继续删下一个**。

### 彻底清完的任务不留空壳目录

7 天原素材清理把 `素材` 里的文件清空时**会保留 `素材` 目录本身**（失败重试还要用它），
所以这一步**成功之后要顺手回收空目录**：先清这条任务自己的空子目录（`素材`／`模板`／`成片`／`缓存`），
再从 `剧集` 往上收 `账号`、`日期`，**到 `生产文件` 根为止**；碰到还有内容的祖先立刻停手。
"删除剧集"把任务目录整棵删掉之后，同样往上回收一次。

**"空"的判定**：除 `.DS_Store` 外没有别的东西就算空 —— `.DS_Store` 是苹果电脑 Finder 写下的垃圾文件，
**不算内容、不许阻挡目录回收**（用户口径，2026-09-19）。回收到的目录会一起写进清理记录，方便回溯。

下次建任务时后端会自动重建整条目录链，所以删掉 `账号`／`日期` 目录是安全的。

### 孤儿记录（"幽灵任务"）

- 什么叫孤儿：**子表记录还在、但它所属的任务已经被删了**，界面上会显示成「未知账号 ×《未知剧集》」。
- 体检：任务中心顶部的提醒条；命令行 `tools/cleanup_orphans.py`（默认预演，加 `--apply` 才真删）。
- 清理**只删数据库行**。

### 变更事件只留最近 1,000 条

裁剪随 30 秒清理循环走，**节流 10 分钟**一次。

### 已结算明细：只在"原素材也清完"时才列进清理名单

`process_cleaned` 阶段保留明细便于排查；**主表行始终保留**（生产记录、官方作品时间、发布关联和收益分析都在主表或分析底座）。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 范围 |
|---|---|---|---|
| 发布后短期清理（小时） | 设置页 →「文件清理周期设置」 | 24 | 1~168 |
| 原素材保留（天） | 同上 | 7 | 1~90 |

写死在代码里的：变更事件保留 1,000 条；文件删除重试 3 次；扫描间隔 30 秒。

## 五、改动须知（动这个功能前先看这段）

1. **删父对象必须级联删子表**：漏一张，界面上就会出现「未知账号 ×《未知剧集》」分组。
   做任何"删除"类改动，先列出它名下的子表。
2. **改保留期改设置项，不动已算好的时间戳**：已发布任务的 `process_cleanup_at` / `raw_cleanup_at`
   是发布时的快照，新期限只作用于之后的发布。
3. **删文件走 `_remove_one()`**：它负责识别可重试错误、退避、单个失败不拖累整批。自己写 `unlink` / `rmtree` 会绕过这些。
4. **到期扫描走索引** `idx_production_tasks_cleanup_due`：改查询条件时保住这个索引，否则会退回"每 30 秒全表捞一遍"。
5. **改触发器定义 = DROP + CREATE**：安装语句是 `CREATE TRIGGER IF NOT EXISTS`，只改定义不生效；同时升 `SCHEMA_VERSION`。
6. **动 `run_due_cleanup()` 之前，先确认它没有在高频重入**：它是长事务（先写库、再真删文件、最后才提交），
   异常时 `last_cleanup` 不更新会导致重复进入并堵住任务中心派单。
7. **改 DDL 必加 `SCHEMA_VERSION` +1**（见《界面与开发规范》）。
8. **回收空目录只能按任务往上走**（`prune_empty_task_directories()`）：先清这条任务自己的空子目录，再往回收祖先。
   **不要改成"启动时扫盘删所有空目录"**，也**不要把它套到别人的任务目录上**——
   新建任务的 `素材/模板/成片` 三个目录生来就是空的，那样会把**正在使用的任务目录**一起删掉。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（清理相关主要在 `server/tests/test_v2_file_service.py`）。
2. **删剧集后跑一次** `python tools\cleanup_orphans.py` 预演 → 应为 **0 条孤儿**。
3. **发布后清理跑完**，`GET /api/v2/task-center/settled-records` 的 `total` 应为 0。
4. 孤儿为 0 时，任务中心顶部的提醒条不出现。
