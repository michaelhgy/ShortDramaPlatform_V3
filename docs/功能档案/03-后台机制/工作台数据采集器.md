## 2. 账号日流量采集器

### 2.1 来源与字段

范围是账号全部来源作品的官方每日统计，不限V3发布，不用作品累计播放量相减推算。

小V猫 `vcat_get_account_stats` 读取它的本地统计数据，支持 `uid/startDate/endDate`；本地数据不保证存在。V3缺数据时才按规则调用 `vcat_refresh_account_stats` 主动刷新官方，再读本地。主动刷新工具当前只传账号列表，不支持传指定日期；不能把本地日期查询范围描述成官方一定只抓这些日期。

| 小V猫字段 | 含义 | 日流量表列名 |
| --- | --- | --- |
| `fansTotal` | 当日关注者存量，可缺失 | 关注者总量 |
| `view` | 当日播放量 | 总计播放量 |
| `fansAdd` | 新增关注 | 新增关注 |
| `fansNet` | 净增关注，可为负 | 净增关注 |
| `fansReduce` | 取消关注 | 取消关注 |
| `like` | 爱心 | 爱心数 |
| `favorite` | 点赞，此接口不按“收藏”解释 | 点赞数 |
| `comment` | 评论 | 评论数 |
| `forward` | 分享 | 分享数 |

表格另外显示账号、账号UID、绑定剧场、指定日期，共13列；CSV另有记录ID。缺失在页面显示“—”、CSV留空，真实0保留0。部分日记录仍展示已知字段。

**主页访问已移除，不采集保存、不展示、不导出。** 上游整包附带返回时由适配器直接剔除；不会为获取该项另发请求。已清理V3现存相关字段，保留其余指标、记录与日期；未改动小V猫自身数据库和历史备份。

### 2.2 历史起点与补缺规则

1. 截止日为上海时区的昨天，不采尚未结束的当天。
2. 先检查V3已有数据：完整日期直接跳过，不查询、不覆盖。
3. 缺日或缺核心字段，先按缺口读取小V猫本地；仍缺才主动刷新对应账号，然后重读缺口。已有有效字段保留，仅补缺失或无效字段。
4. 首次或历史起点尚未确认时，以昨天为截止日最多反推90个自然日（包含昨天，最早为昨天减89天），不再额外向更早的90天分段回溯。已保存的更早日记录继续保留，不清理旧数据。
5. 优先以该范围内最早非零日前紧邻的连续7个完整全0日推定起点。若核对到90天上限仍无法满足零边界，则以范围内实际可查到的最早记录日期作为统计起始日，保存 `rule=lookback_limit`、90天查询上下界及实际起始日。它只是可查数据起点，不代表注册日期，也不需要知道注册日期；例如来源仅返回10月15日至昨天，则可从10月15日开始，不要求此前存在7天零记录。关注者存量不参与全0判断；播放、关注变化和互动字段参与。
6. 空响应、缺日期、缺字段不能视为0。90天范围无任何记录、查询尚有未成功核对的范围或兜底所需官方刷新未成功确认时，不强行确定起点。起点之前成功查询但未返回的日期不计入该起点之后的缺日；起点当天及起点至昨天之间缺日、缺核心字段仍保留 `partial`，不因采用最早可查日期而掩盖真实缺口。
7. 起点至昨天之间真实0日正常保留。起点前的连续0日保存在缓存中作判断依据，日表从推定起点展示。
8. 起点已建立且区间完整时，返回 `up_to_date`，账号日查询和官方日统计刷新均不调用。`fansTotal`缺失不使核心日数据永久重复采集。

这里沿用用户确认的“昨日数据一旦取得就不再变化”的业务口径；后续如需纠错覆盖，须单独定义，不混入日常补缺。

### 2.3 保存位置与使用位置

## 3. 优化记录与作品分析采集器

### 3.1 来源与字段

第一步由统一队列调用小V猫 `vcat_refresh_account_feeds` 主动检测近期异常作品，完成后读取账号UID、异常作品 `exportId`、原始秒级发布时间、平台状态、删除标记与完整性。成功完成时间由V3单独保存，不把账号缓存时间冒充本次检测时间。旧版总采集入口仍保留读缓存诊断的历史行为，自动/立即检测以本节下述统一队列为准。

第二步先保存全部通知，再为缺失官方时间证据或分析的通知读取详情，不以软件发布归属作为收录条件。历史待查通知即使不再出现于近期名单，也继续自动补查。`VcatClient.optimization_detail(uid, export_id)` 使用该账号小V猫登录态，调用已验证的官方作品分析详情GET接口 `get_finder_appeal_detail_by_export_id`；不是提交申诉。

| 获取内容 | 当前保存方式或用途 |
| --- | --- |
| `reason` | 作品分析完整原文，保存为 `analysis`，用于原因分类 |
| `tips` | 保存为 `tips_json` |
| `appeal_type` | 保存为 `appeal_type`，不直接当作原因分类结论 |
| `punish_state/audit_result` | 保存平台状态 `platform_state` |
| 账号UID、作品编号、异常 `exportId` | 保存归属关联 |
| `feed_create_time` | 自动关联必须取得秒级作品时间，并与通知及作品时间一致 |
| `unique_id`、`operateItems`及封面/视频是否存在 | 适配器可返回的辅助内容；当前不全部单独入业务表，不宣称均已持久保存 |

登录凭据只用于内存内的请求，不写入业务返回、档案或日志。无法取得完整原文时保留缺失，不编造原因。

### 3.2 全部作品历史、归属与自动关联（2026-11-05）

- 账号作品以 `(uid, post_id)` 保存官方已发布历史，按实际发布时间计每日数量，重复采集不重复计数。上传、排期或发布任务完成都不等于官方已发布。列表不再返回的作品保留历史，不凭缺失推断已删除。
- 所有优化通知先独立留存，再查询官方详情。匹配要求同账号、通知发布时间、作品发布时间、官方详情时间三路精确到秒一致，且完整作品采集覆盖该发布时间、仅有一个作品候选和一条通知；不截断或模糊匹配 `exportId`，不按分钟猜配。
- 优化通知与作品列表的 `exportId` 已在真实9条样本中证明并不相同，不能直接当作同一个ID。通知 `uniqueId` 也不当作作品 `postId`。
- 缺少作品/详情为待补查，同秒多候选为歧义，时间或身份不一致为冲突。全部保留证据，不让用户人工猜配。相关区间存在待查通知时，优化比例显示未补齐，不显示确定的低比例或0。
- 已确认关联独立于当前作品列表；删除/隐藏后不从已收录发布数量、优化证据中扣减。正式启用前已删且从未采集的作品无法凭现存列表恢复，未知发布时间不得补造。
- 全部作品在 `v3_work_history`，通知及详情/关联状态在 `v3_work_notices`。软件发布归属继续使用 `v3_publication_history`；已匹配的软件优化兼容写入 `v3_publication_optimizations`。旧分析保留，但不能把旧关联推导出的时间充作官方详情证明。
- 采集过程中自动补查完整作品；若本批次已完整采过作品，则复用该批次结果，避免重复全量翻页。随机检测周期、登录失效排除、停止点和分页等待规则继续有效。

### 3.3 优化作品处理与播放保护（2026-11-05）

入口在账号优化页标题右侧、日期筛选左侧“优化设置”。检测周期设置与作品处理设置独立。

- 默认自动处理关闭、处理方式隐藏、处理范围仅软件，播放保护门槛留空；启用前必须填写正整数门槛。范围可以改为全部作品，独立持久保存，不随看板筛选变化。发布后处理时限默认10小时，允许自定义正数及小数小时，旧设置读取时兼容补上此字段，不改原启用开关、范围或方式。
- 只处理本次成功主动检测仍返回、已有唯一官方关联且执行时仍在发布后时限内的异常作品。例如10小时：刚满10小时允许，超过10小时跳过；缺失/未来发布时间跳过。查询前与查询完成后、动作入队前均复核时限，查询期间跨过时限不发送动作。超时作品仍保留统计和优化证据。动作前按该作品的发布日期再在线查询一次，确认作品ID、发布时间、当前累计播放和置顶状态；不用早先完整列表的旧播放量直接处理。
- 播放达到或超过门槛、数据缺失/超过5分钟、身份歧义或冲突、账号异常、置顶需保护或置顶状态不明时均跳过。设置在每条执行前重读，停止请求在远程调用之间生效。
- 删除用 `vcat_delete_punish_post({uid, exportId})`，隐藏用 `vcat_hide_punish_post({uid, exportId})`，这里的ID是优化通知原始 `exportId`。专用能力只开放这两个动作，不加入只读白名单，不修改或启用小V猫原生自动设置。
- 单条接口不支持原子播放门槛。V3在每条动作前重新查询并校验，但平台查询到动作提交之间仍存在时间差，不能宣称平台原子保护已经实现。
- 动作发送前写处理日志；中断/失败结果记未确认，不自动重发。接口返回仅记“已返回、最终状态待核实”，不把接口返回当作已实际删除/隐藏。删除不可恢复，关闭处理开关停止后续动作，已提交的请求无法撤回。
- 设置与日志分别保存于 `v3_optimization_action_settings`、`v3_optimization_action_log`。处理设置和处理记录分两个页签；记录经只读 `/api/v3/operations-dashboard/optimization/actions/records` 每页10条分页读取全部留存记录，不再受首页最近100条摘要限制，也不自动清理处理历史。按新到旧稳定翻页，刷新时才纳入新记录；分页不发平台请求。记录显示账号、作品/ID、发布时间、处理时间、隐藏/删除方式、提交前播放、优化原因及待核实状态。保护跳过未发请求的作品不产生处理请求记录。弹窗最高90%当前视口，标题/页签/保存或分页按钮固定，中间滚动，长优化原因可展开。本轮只做临时库、模拟动作和隔离页面验证，没有向真实作品发送删除/隐藏。

### 自动检测与立即检测（2026-11-03）

- 优化模块左侧为立即检测选项，右侧为独立的全局自动检测设置，两者不互斥。右侧不作为采集类别或执行选项，不依赖账号选择，也不依赖本次是否勾选优化采集。
- 自动检测设置为全局规则：默认随机50～70分钟，允许1～1440分钟的整数上下限；无需选择账号。启用开关点击后立即请求保存，成功才呈现新状态，失败保留原状态并显示原因。开关使用已经保存的周期；间隔草稿只由右侧卡片内的“保存”提交，不自动提交。覆盖V3有效绑定且未停用、未注销的账号，执行前核对小V猫登录，失效不请求；后续新增账号自动纳入。右下角执行不保存、不关闭、不更改自动规则。
- 立即检测在左、自动检测设置在右。左侧立即检测控制本次优化采集是否参与，选中后仍需选择账号并点击右下角执行；不与右侧自动设置互斥。执行时只对所选账号强制主动检测，绕过自动等待；不会改变全局自动开关或周期。成功后重新随机安排该账号下一次时间。
- 每个账号独立随机，账号不按作品数量、新发布或有无优化决定是否继续检测；全局设置不保存人工选择的账号名单。账号登录状态在任务执行前读取，失效则不发检测请求，记录原因并推迟至下一周期。
- 软件后端运行期间每5秒检查本地计划，到期账号通过现有统一采集队列串行执行；后台关闭后不运行，重启保留设置与下次时间，过期只补一次，不重放错过的每个周期。
- 默认关闭。开启后首次等待随机周期；需立刻采集可选择立即检测并统一执行。失败保留历史与成功时间，不连续快速重试；明确访问限制暂停自动检测，处理后手动执行或重新保存设置。
- `v3_optimization_detection_settings` 只保存全局开关、周期与暂停原因，`v3_optimization_detection_accounts` 保存按账号的下次时间、尝试/成功时间和错误；新增表不清理已有历史、优化记录或作品数据。
- 单账号周期是业务策略，不是小V猫承诺的风控安全阈值。MCP目录说明已核对；当前自动调度、立即强制和详情续补已用隔离模拟来源验证，真实账号的刷新返回及是否受小V猫异常处理设置影响仍需实测，未宣称正式运行验收。

### 3.3 优化率口径与边界

整体优化率＝已关联V3作品中的优化作品数÷已确认公开的V3历史发布作品数。原创优化率同一分母，仅把完整原文归类为原创原因的作品计入分子。原因按完整文本和已核实同义原文映射，不直接用接口数字类型替代。

没有分母、诊断不完整/过旧、详情缺失或归属不唯一时保留未知，不用账号当前视频数作历史发布分母，不把未知显示成0%。

详情读取已验证；发布归属、重复保存、删除后历史保留和冲突排除有相关自动检查。已删除的旧V3测试作品无法唯一补关联；新的真实V3发布到后续优化的完整链路仍待业务样本验收，不能因接口可读就标记全链路验收完成。

## 8. 在线作品采集正式接入（2026-11-02）

用户确认直接使用小V猫“作品管理→在线浏览”的快速来源，V3控制每页等待。现有工作台刷新和发布归属跟踪改用 `VcatClient.online_account_posts`，通过 `PostManager.getPostList` 分页：首屏参数为空对象，后续原样传递 `nextState`，当前源每页40条。不再启动或等待 `vcat_start_post_sync`，在线失败也不回退至慢速同步。旧独立调查工具 `tools/collect_v3_account_data.py` 仍保留原同步逻辑，不是工作台当前采集入口。
