# 收益采集

> 定时或手动去青柠、顶好、触摸、花生四个平台的公开页面，把你各账号的收益读回来：按「账号 × 数据日期」存成日收益，并把青柠逐条视频的明细一起记下来。
> **他会这么说**：「收益采集」「采集收益」「采集中心」「同步昨日」「补采」「抓收益」「青柠 / 顶好 / 触摸 / 花生」「采集记录」「采集日志」「无结算数据」「零收益」
> 最后核对：2026-09-19 ｜ 状态：已整理

## 一、它做什么

一次采集 = 一个**批次**，批次下面按「账号 × 数据日期」拆成一条条读取单元：

| 剧场 | 读取口径 | 一次读到什么 |
|---|---|---|
| 青柠剧场 | 公开收益页面，按天分页查 | 当日总额 + 该日每条视频的播放与收益明细 |
| 顶好剧场 | 收益接口，按天查 | 该账号该日的总额 |
| 触摸剧场 | 公开查询页 | 该账号**累计**广告收益（一个数） |
| 花生剧场 | 公开表格查询 | 该账号**累计**收益合计（一个数） |

结果分三处落地：日收益汇总、青柠视频明细、采集日志（每次读取追加一条，记着本次口径是逐条明细 / 账号当日总额 / 账号累计）。

## 二、怎么用

1. **手动采**：数据分析 →「收益」页签 → 右上角「采集收益」→ 抽屉「收益与数据采集中心」→ 选范围（全部已接入 / 按剧场 / 按账号）→「同步昨日」或「历史补采」→ 选日期 → 发起采集 → 看进度条（成功 / 无结算数据 / 失败三个计数）。
2. **查采集记录**：同一个抽屉下半部分，按剧场、账号、数据日期、结果筛选；同一账号同一天的历史尝试只显示最新一条。
3. **设自动采集**：设置页 →「收益自动采集定时任务」→ 开关 + 时间点（可增删）。

## 三、业务规则

### 谁触发、采哪一天

- **手动**：抽屉里发起，日期自己选。
- **自动**：后台每 **15 秒**检查一次，到点就采**前一天**的数据。
- 软件当天首次打开时，已过点而当天还没跑过的时间点**合并补采一次**；批次里记着这次覆盖了哪些时间点，重启也不会把同一时间点重复跑。
- 自动采集看到已有批次在排队或运行中时，**本次检查跳过**。

### 采谁：停用账号不采

- 范围只有四个剧场的账号，且**状态不是「停用」**；按剧场 / 按账号发起时，只采所选范围。
- 账号没填视频号 ID → 这条单元直接记失败（说明写「账号未填写视频号 ID」），不写收益。

### 日期

- 青柠、顶好**按天逐日读**（选 7 天就是 7 次读取）。
- 触摸、花生按累计口径读，只读所选范围的**最后一天**。
- 一次补采**最多 90 天**；截止日期早于起始日期会被拒。

### 唯一键：同一天重复采集是更新

| 数据 | 唯一键 | 重复采集时 |
|---|---|---|
| 日收益汇总 | 账号 + 数据日期 | 覆盖成最新金额 |
| 青柠视频明细 | 数据日期 + 账号 + 平台视频 ID | 同一条视频**更新**播放、收益、排名 |
| 采集日志 | 每次读取追加一条 | 只增不改 |

**不同日期各自独立**：同一条视频在不同日期各留一行，才能看出它的变化。

### 「无结算数据」「失败」「零收益」是三件事

| 结果 | 什么情况下 | 写不写日收益 |
|---|---|---|
| 成功 | 平台正常返回、数值校验通过 | 写（金额可以是 0.00） |
| 无结算数据 | 平台正常返回「该日没有收益记录」 | 不写 |
| 失败 | 网络、解析、校验不通过，或账号缺 ID | 不写 |

- 青柠写完一天前先**对账**：页面声明的记录数、总计金额必须与抓到的明细一致，对不上就整条判失败，**一个数都不写**。
- 顶好返回 0.00 时无法确认是真零收益还是账号没匹配上，这种**按失败处理**，不当零收益。
- 零收益要平台明确给出 0.00 且校验通过，才算成功。

### 明细怎么对上剧集和成片

- 平台剧名匹配到本系统剧集 → 标「已匹配剧集」；匹配不上 → 标「待匹配剧集」，不猜、不强归。
- 平台视频与内部成片的关联在候选列表里**人工确认**；确认结果按「账号 + 平台视频 ID」保存，复用于该视频之后各天的收益。

### 日志、明细与批次状态

- **采集日志与业务明细是两类数据**：日志管排错，日收益与视频明细管分析；清日志**不碰**后两者（清理规则见《清理系统》）。
- 批次走 `queued → running → completed / failed`；跑的时候记当前剧场、当前账号与三个计数。
- 采集期间软件重启，未跑完的批次记为失败，说明是「软件重启，未完成的收益采集已停止，请重新发起采集」；「采集记录」里最新一条日志的 id 当作「收益数据变了没有」的信号，编号一变收益页重新拉数据。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 可选值 |
|---|---|---|---|
| 自动采集开关 | 设置页 →「收益自动采集定时任务」 | 开启 | 开 / 停用 |
| 自动采集时间点 | 同上 | 06:00、12:30、18:00 | 任意 `HH:MM`，可增删，至少保留 1 个，不重复 |

写死在代码里的：检查间隔 15 秒；自动采集取前一天；一次补采上限 90 天；请求超时 40 秒；青柠来源地址 `SOURCE_URL` 与顶好、触摸、花生的查询地址。

## 五、改动须知（动这个功能前先看这段）

1. **写库必须幂等**：日收益按「账号 + 数据日期」、明细按「数据日期 + 账号 + 平台视频 ID」做 upsert，任何新写入都要能重复执行而不多出行。
2. **采集器读的是公开网页**：站点改版会让解析失效，解析不到必须落成明确的**失败态**、金额留空；宁可整条判失败，也不把解析不到的数字记成 0。
3. **不动已存的历史明细**：重采只更新同键那条；加字段按《界面与开发规范》升 `SCHEMA_VERSION` 并写 `ALTER TABLE` 迁移。
4. **手动与自动共用一个执行体**：两条路都必须走 `start_revenue_collection()`——批次记录、进度计数、证据链都在它里面；另开一条采集路径会让日志和进度对不上。
5. **要加剧场就三处同改**：`collect_supported_theaters()` 的口径表、`estimate_collection_units()` 的日期口径、设置页与调度器的剧场范围；漏掉 `estimate_collection_units()` 会让进度条总数对不上。
6. **新平台的「真零收益」先定义再动手**：确认不了就记失败，禁止默认按 0 写。
7. **日志与明细分开清理**：清 `v2_revenue_collection_attempts` 的代码不许顺手删 `v2_daily_revenues` / `v2_revenue_video_details`。

### 改完怎么验

1. **一定先跑**：`tools\一键验证.bat`（收益用 `server/tests/test_v2_revenue.py`）。
2. **必须实机看**：抽屉里发起一次「同步昨日」——进度条总数等于 `estimate_collection_units()` 的读数，跑完后成功 + 无结算数据 + 失败三个计数之和等于总数，「采集记录」出现对应行。
3. **碰平台解析时**：先手动采**一天**核对金额，再补采 7 天，确认明细是更新而不是新增。
4. **首次实机跑通后记基线**：把命令、四个剧场启用账号数、一次「同步昨日」的读取单元数记进 `docs/3-验证基线.md`。
