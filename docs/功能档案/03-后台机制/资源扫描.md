## 一、它做什么

两个扫描器同一句话：**磁盘是事实来源，系统清单是它的镜像。**

| | **A. 任务原素材扫描** | **B. 生成资源索引** |
|---|---|---|
| 扫什么 | 某个生产任务 `原素材` 目录里**第一层**的视频文件 | `生成资源\风景视频 / 真人图片 / 引流视频`（含子目录） |
| 谁触发 | 生产中心任务卡片 →「扫描素材」 | 打开「资料中心 → 生产资源」、顶部栏、资源库存读取、参数中心；资源区域每 30 秒自动刷一次 |
| 结果落哪 | `production_files`（`file_type='original_material'`） | `resource_index` |
| 每个文件做什么 | 改名为「剧集名-序号」→ 算 md5 + sha256 → 探时长 → 抽首帧缩略图 → 读分辨率 | 记大小、修改时间、文件身份；视频排进后台探测队列补时长、分辨率、缩略图 |
| 快慢 | **慢**：全文件哈希 + ffprobe + 抽帧，全程一次只跑一个 | 快：列表请求只记磁盘变化，探测在后台单线程慢慢做 |

## 二、怎么用

1. **扫一个任务的素材**：生产中心 → 选任务 → 素材目录区右侧「扫描素材」→ 转圈结束，素材带缩略图、时长与序号出现在素材条里。
2. **看生成资源**：资料中心 →「生产资源」页签 → 按分类与标签筛选，卡片显示时长、分辨率、大小；视频信息还在识别时先显示「正在识别视频信息…」。
3. **补素材**：把文件放进 `生成资源\风景视频`、`生成资源\真人图片`（保留原下载文件名）；目录规矩见《文件与资源生命周期》。

## 三、业务规则

### 扫原素材时保留有效编号，按尾部类型续接

- 普通素材命名为 `剧集名-序号.后缀`；原文件名包含“羊头”的新素材命名为 `羊-剧集名-序号.后缀`，新文件后缀转小写。重复扫描识别已有 `羊-` 标记，不丢标记、不重复追加。
- **已有正确名称和编号固定，新增从最大有效序号＋1继续**：有效名称是当前剧名的 `剧名-N` 或 `羊-剧名-N`，N为正整数；比较数字而非字符串，9排在10前。保留旧空号与既有普通/羊头排列，重复序号在改名前提示核对。
- 读取最大有效序号那条的类型：尾部是羊头且新文件有羊头，先编新增羊头，再编新增普通；尾部是普通且新文件有普通，先编新增普通，再编新增羊头。新文件没有尾部同类时，直接编现有类型。每组内部按**自然顺序**处理（`download2`在`download10`前），两组不逐条交错。
- 没有任何有效编号时，从1开始，普通在前、羊头在后。例如首次10条普通加10条羊头仍为 `剧名-1` 至 `剧名-10`、`羊-剧名-11` 至 `羊-剧名-20`。
- 例如已有普通1～4、羊头5～10，又补入 `7.mp4`、`8.mp4`、`羊头.mp4`，新增依次为 `羊-剧名-11.mp4`、`剧名-12.mp4`、`剧名-13.mp4`，旧1～10不动。已有成片记录的任务同样支持这种追加扫描。
- 素材与成片列表按数字序号排列；FFmpeg成片沿用素材名。成片区及预览直接显示文件名（含后缀和羊前缀）；已生成文件优先显示实际成片路径的文件名，待合成项显示当前素材文件名。
- 改名分「先临时名、再落位」两步；目标位置会覆盖已有文件时**当场停下报错**，不覆盖。

### 每个原素材记什么

| 字段 | 怎么来的 |
|---|---|
| md5 / sha256 | 读整个文件算出的内容哈希 |
| 序号 | 从「剧集名-序号」或「羊-剧集名-序号」文件名里解析 |
| 时长 | ffprobe 读容器时长 |
| 分辨率 | ffprobe 读第一条视频流的宽×高 |
| 缩略图 | ffmpeg 抽首帧，缓存到 `系统数据\cache\material-thumbnails`，按内容哈希命名 |

- 同一路径重复扫描是**更新同一行**（`UNIQUE(task_id, file_path)`）：哈希与探测结果刷新、缺席计数归零、状态回到可用。
- 重扫保留记录ID和首次入库的原文件名；追加扫描不改变旧编号及成片关联。目标仍由另一条不可移动的记录占用时，扫描拒绝执行。
- 探测或抽帧失败只影响该文件的那几个字段，其余素材照常入册。
- 扫完把任务状态置为「素材已扫描」。

### 磁盘上找不到的记录怎么处理

- **第 1 次**扫不到：这一行标为源文件缺失、记一次缺席，素材条里不再显示它，成片相关记录不动。
- **连续第 2 次**仍扫不到：清掉它派生出来的成片任务、草稿与成片文件、缓存目录和导出作业，然后删掉这行原素材记录。
- 文件重新放回目录再扫一次，就按可用素材重新入册。

### 生成资源索引怎么维护

- 当前扫描三类 V3 资源，旧真人视频、BGM 文件及其索引/缓存不参与本扫描的对账清理。
- `production_resource_media` 按索引中的稳定编号取文件，核对所在类别目录及大小、修改时间，支持改名后继续预览；目录打开接口只接受三类有效类别，空目录也可打开。

- 认文件身份的顺序：先按**当前路径**认；路径变了就按**文件身份**（磁盘 inode）认出改过名、搬过家的同一个文件，缩略图与探测结果跟着走；两者都对不上时按路径算一个固定 id。
- 大小与修改时间都没变 → 沿用已存的时长、分辨率、缩略图与识别状态；变了 → 状态回到「待识别」并重新排队。
- 图片：缩略图就是它本身，直接可用。视频：先以文件名与大小出现在列表里，时长、分辨率、缩略图随后补上。
- 探测结果回写前核对文件身份、大小、修改时间与排队时一致，对不上就丢弃这次结果，不把旧结果贴到新文件上。
- 同一个资源最多排一次探测；探测线程一条条做，单个文件失败不影响整张列表。
- 索引里有、目录里已经没有的记录：带缩略图缓存的风景视频 → 连缩略图缓存一起撤掉索引行；引流视频与源文件本身也已不在的图片 → 保留索引行，只标「源文件已不在」。
- 文件名以「已使用」开头的非引流资源在列表里标为已使用（领取标记，规则见《文件与资源生命周期》）。
- 缩略图请求带「大小 + 修改时间」校验，对不上就当场重新探测一次再给图。

## 四、可调参数

| 参数 | 在哪调 | 默认 | 可选值 |
|---|---|---|---|
| 资源索引自动刷新间隔 | 代码：`AREA_INTERVAL_MS.resourceIndex` | 30 秒 | 毫秒；改这里等于改全站资源刷新节奏 |
| 素材放哪 | 直接往 `生成资源` 对应目录放文件 | 三个 V3 固定目录 | 目录由数据盘决定 |

写死在代码里的：视频后缀 `.mp4/.mov/.mkv/.avi/.webm`；图片 `.jpg/.jpeg/.png/.webp/.gif/.bmp`；BGM `.mp3/.wav/.m4a/.aac/.flac/.ogg`；缩略图缓存后缀 `-v3.jpg`；ffprobe 超时 8 秒、抽帧超时 15 秒；缺席满 2 次才清记录。

## 五、改动须知（动这个功能前先看这段）

1. **扫描是单次占锁最久的操作**：`scan_task()` 在 `SCAN_LOCK` 里对每个文件做全文件 md5 + sha256 + ffprobe + 抽帧，最后才提交。要加耗时步骤，先考虑把它挪出事务、按条提交；占着写锁会连带卡住任务中心派单与其他写操作。
2. **改名规则成套改**：`rename_without_overwrite()` 决定「序号只增不复用」，`canonical_sequence()` 负责认号；改其中一个必须同时确认另一个与文件名格式，否则重扫会把同一个文件当成新文件。
3. **索引表与磁盘要能对账**：`resource_index` 每行要么能在磁盘找到对应文件，要么明确标着源文件已不在；加清理动作前先确认它不会把还能用的缩略图缓存删掉。
4. **探测结果必须绑定文件身份**：回写前比对 `file_identity / 大小 / 修改时间`；这一层去掉，换了内容的同名文件会顶着旧时长与旧缩略图。
5. **「已使用」前缀是领取标记**：可用量以文件名为准，改扫描代码时不要顺手挪走或改写前缀判断。
6. **改表结构要升 `SCHEMA_VERSION`**：`resource_index` 与 `production_files` 的 DDL 改动按《界面与开发规范》升级版本号，并让旧库能迁移。
7. **不要写数据盘里的真实文件**：扫描只读目录、只改素材文件名与自己的缓存；`D:\短剧推广运营系统` 是真实业务数据，任何清理动作都要先预览再确认。
