## 5. 危险提醒

1. **不要**直接在项目根目录跑 `pytest server/tests`（不带隔离）——2026-09-17 发生过一次：测试触碰了生产库（执行了幂等的建表/建索引语句；事后核验 integrity ok、无外键违规、文件大小未变）。此后**一律用一键验证脚本**。
2. **测试通过 ≠ 功能可用**：本基线只覆盖单元测试与类型检查，属**证据等级 2**；剪映真实行为、打包后运行、界面操作都不在其中，必须另外人工验证。
3. **测试隔离的红线**：**不能**靠"让环境里的数据库能打开"来修测试——那样会把建表语句写进**真实生产库**，必须给测试自建临时库。
4. **已知无害噪声**：一键验证跑完时 pytest 在 Windows 上清理临时目录失败，打印一行 `PermissionError: [WinError 5] ... pytest-current`——那是 **pytest 自己的临时目录收尾，不是测试失败**，以输出里的 `N passed` / `N failed` 为准。
   另有 PowerShell 把 stderr 当错误处理，会让**退出码变成 1——退出码不等于验证结论**。
5. **本基线未覆盖**：剪映导出、打包、界面行为；运行期护栏（单实例守卫 / 写锁监视器）有 `server/tests/test_runtime_guard.py` 10 个测试覆盖，沙箱实测见 `D:\V2_DevSandbox\verify_guards.py`。
6. **未来增强（待补）**：加"启动自检"（真把软件跑起来，确认服务能起、界面能开，等级 3）；打包产物冒烟验证（等级 4）。
