# V3 双封面花字正式接入

日期：2026-10-26。结果：正式源码和前端构建已完成，隔离后端/浏览器实际联通通过；当前用户程序未自动重启，安装/轻量更新包本轮未生成。

## 目标与最终规则

用户确认将已验收的花字编辑器正式接入生产中心，保留另一会话完成的封面显示和左键上传/替换。剧集封面与羊头封面按剧独立保存，各原图加三张修改版；通用文字模板最多五个。羊头没有单独原图和修改版时，只显示剧集封面；出现独立设置后在其右侧显示羊头当前使用封面。计划发布时间、生成耗时放回标题下方和封面右侧，不另起一整排。

发布工作台新分组默认使用对应封面，普通/羊头视频逐条读取各自当前封面。明确“不指定”的旧分组设置保留；对应图片缺失时不指定，不用另一套图片代替。未扩展实际发布权限或自动覆盖旧外部草稿。

## 实现与保护

- 修改前读取并保留 `ProductionCenter`、`DramaTaskCover`、`PublishingWorkbench`、上传接口及发布模块的最新现场，快照位于 `local-test-output/cover-integration-20261026/before/`；TS/TSX快照使用 `.snapshot` 后缀，避免进入项目类型检查。未恢复旧版文件覆盖另一会话的实现。
- `DramaTaskCover` 保留原上传流程和占位，增加条件双图、羊头上传、右键编辑、缺图/不可读提示及同剧刷新。`ProductionCenter` 只调整标题区域结构与必要的标题截断。
- `CoverEditorModal` 以正式弹窗复用已验收的编辑页；同源、指定窗口的消息校验负责保存后刷新和关闭。保存时阻止关闭/切换，未保存编辑切换前提示。
- 新增 `server/cover_editor.py`，业务库增加 `v3_cover_projects` 和 `v3_cover_templates`，不删改旧表。封面按剧集ID保存，模板全库共用；修订号检查防止旧窗口覆盖新内容。图片验证格式、字节数、画幅及参数，不能引用任意本地路径。
- 图片按内容校验值写入 `剧集资料/_封面编辑/<剧集ID>/images/`，旧图不覆盖；变更前文档保存在 `history/`。删除修改版腾出当前名额，历史图片不自动清理。旧封面按需引用；同一不可变图片可被两套原图独立引用，替换一套不改变另一套。
- 当前剧集选用路径同步回原 `drama_profiles.cover_path`，资料中心和既有封面接口继续读取；首次上传仍创建剧集资料目录，已有原片路径等元数据保留。
- 发布 context 增加 `sheep_cover`、`sheep_cover_visible`，载荷按视频的羊头标记分别取图，混合分组也适用。分组的“不指定”仍可使用。
- `npm run build` 自动构建无测试图片的 `public/cover-editor.html`，并进入正式 `dist`；不增加运行依赖。旧离线预览及浏览器本地内容保留，不自动写入正式业务。

## 用户使用与剩余边界

当前运行中的后端需要正常退出后再从根目录 `启动V3开发版.bat` 打开；原图左键替换，右键进入编辑。花字编辑、两套各三张及五模板使用与已验收预览一致。当前安装EXE没有被替换，本轮没有制作发布包。

真实对外发布、平台接受结果、用户当前Windows程序重启后的观感和跨电脑安装仍未验收。发布模块当前仍是本地草稿准备阶段，不能把参数选图通过当作真实发布成功。
