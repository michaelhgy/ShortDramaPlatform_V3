# 2026-10-29 V3 账号数据第一阶段

## 目标

在不把剧场收益口径、作品同步和账号诊断混在一起的前提下，为 V3 增加受控的小V猫账号统计获取入口，先把“实际能获得什么数据”落成本地可查看证据。

## 已完成

- 新增 `账号数据` 页签。
- 页面读取 V3 本地快照，不因打开页面或切换页签访问视频号。
- 仅选择 V3 已登记且有视频号 UID、未停用的账号。
- 日期选择和「读取本地快照」不访问小V猫；明确点击「获取所选日期」后，先调用 `vcat_list_accounts` 做小V猫本地账号状态预检查；小V猫未找到、已作废或登录失效的账号保存为 `unavailable`，不进入统计刷新。
- 对预检查通过的账号，按最多 10 个 UID 一批调用 `vcat_refresh_account_stats`，确认逐账号刷新结果成功后，再按指定日期范围读取 `vcat_get_account_stats`。
- 支持单日或最多 90 天范围；V3 按日期拆分保存每日状态，同时保存刷新逐账号结果、获取时间、日期范围和未加工的 MCP 原始 JSON。
- 同一数据日已有刷新成功或 `unavailable` 快照自动复用；临时失败允许手动重试；程序重启后遗留的 queued/running 会标为失败并要求人工确认后重试。
- 页面单独显示“已失效”和“获取失败”；失效账号不会自动重试，也不被解释为平台数据为 0。
- 统计刷新已从普通小V猫发布连接中隔离，只能由账号数据采集连接触发。

## 数据边界

- 快捷默认日期仍为本地时间的昨日；历史日期必须由用户明确选择，避免页面读取和分析过程触发平台访问。
- 本阶段不启动作品同步，不调用账号诊断，不查询或计算剧场收益。
- 收益仍按剧场独立网站的月结口径处理，已结算月份不纳入本事项。
- 不把 MCP 返回字段直接解释成“收益原因”或平台因果结论；先保留原始返回，待一次真实人工触发后再按实际字段设计指标。

## 后续规则确认与实现

- 用户确认架构：小V猫只负责按明确请求向视频号平台获取；V3 保存刷新证据和查询原文，之后的分析全部基于 V3 本地数据。
- 账号数据支持手动指定最多 90 天范围；刷新逐账号结果和每个日期的查询状态分别持久化，每个数据日保留原始 MCP JSON。
- `refresh_status`、`data_state` 明确区分刷新失败、查询失败、无每日记录、存在每日记录和旧快照缺少证据。无每日记录不能作为 0；有日期记录且指标为 0 才是确认的 0。
- 第二阶段实现已通过账号数据 5 项测试、数据结构升级回归、文件服务 51 项测试、前端 87 项测试、TypeScript 检查和生产构建。尚未对真实账号触发新的历史范围采集；生产现场验收待用户重启后手动选日期验证。
