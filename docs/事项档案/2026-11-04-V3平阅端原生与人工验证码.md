# V3 平阅端原生与人工验证码

日期：2026-11-04。范围：平阅挂载日收益、可编辑查单链接和提取码、人工验证码、查询会话复用及现有任务续采。不新增其他剧场或平阅绿泡泡，不发布、不改版本、不重启正式软件，不写正式业务库。

## 用户可见行为

资料中心 → 查单管理 → 平阅端原生，可编辑链接和提取码、试查后确认。剧场管理勾选固定编号 pingyue，账号选择该采集器；软件目录与自建剧场名称分离。等待时弹出原站验证码图片和输入框，可换图、提交、收起或稍后处理。提交后续采，成功日期复用；其他剧场及其他采集类别先继续处理。

## 实现

- 新 `server/pingyue_collector.py`：固定来源公开协议、人工解锁门槛、持久CookieJar及解锁状态、图片编号校验、错误刷新、会话隔离和来源失效处理。网页公开JS将提取码存sessionStorage；软件保留等价查询会话，不维持真实浏览器标签页或增加浏览器打包依赖。重启不保留成功解锁状态。
- `revenue_collectors.py` 内置第六项；`revenue_query_settings.py` 增加平阅专属HTTP/hash路由约束与提取码配置/指纹/历史，其他来源仍受既有HTTPS限制。配置存入既有修订表，无新增业务库结构迁移。
- `v2_revenue_service.py` 按原日期、金额和当日合计核对入账；人工等待不落失败/零记录。`revenue_queue.py`、`collection_jobs.py` 及 `v2_file_service.py` 原入口续采，等待时不持数据库事务，不发无意义重复请求。
- 新全局 `RevenueVerificationModal.tsx`；查单详情可隐藏/显示提取码，改配置使试查凭证失效。验证码状态查询兼容提交事件遗漏或另一窗口验证完成；不能靠前端事件决定服务器已解锁。
- 账号/剧场固定编号绑定和既有收益历史保留；青柠仍不保存视频明细。
