# V3 统一面板接入剧场收益

日期：2026-11-03。用户确认按分析方案接入，保留 Gemini 统一面板大框架。

## 可观察行为

入口：工作台 → 数据采集 / 刷新 → 勾选「剧场收益」、选择账号 → 右下执行。也可使用现有「仅核对剧场收益账单」快捷选项。

- 收益卡片只保留一个采集选项和真实计划：历史待补齐、待更新、已完成跳过、配置问题。删除来源分类框、开发中标记、不可用明细开关；不提供首次/日常或日期选择。
- 账号列表展示实际绑定的采集器，不按剧场名字推断能力。无绑定、停用、缺视频号ID明确说明；不伪装为零收益。
- 日来源首次从北京时间昨天倒查，按既有采集器确认的连续7天零/正常无收益记录停止；每轮历史最多新读90天，未完成可继续。后续按保存边界扫描缺口，补全到昨天；超过90天分段查询，已确定日期不再请求。
- 已有历史补采未完成时，先补齐原锚点之后的新日期，再继续原历史与失败日期。所有新结果按单日事务保存，中断不会抹掉已经取得的数据。
- 累计来源沿用后台快照与增量计算，同采集日不重复查；后续新增差额归实际采集日，不套用按日七天规则。当前触摸/花生仍不具备可靠历史月份能力。
- 有金额、明确0、正常无记录、待更新、查询失败分别保留。新增待确认标记表，不扩大现有尝试表状态约束；读接口转换为 pending，避免待更新被当完成或停止边界。来源必须明确返回状态；兼容明确尚未出账等提示，不猜测正常空的最终性。
- 进度展示当前账号/日期、补历史或补缺、结果、连续无收益计数和跳过。失败、待更新、未补完均保留重试；单号重试只重新请求缺失或失败日期。
- 收益独立于小V猫登录，收益单独执行不会连接小V猫。混选时收益先执行，再检查视频类别的登录；视频失败不覆盖已完成收益。
- 复用收益运行记录与启动锁，原定时/手动收益任务和统一队列不会重叠请求。已有收益任务时标记本项待继续；访问限制停止后续请求，不关闭优化自动检测的全局设置。
