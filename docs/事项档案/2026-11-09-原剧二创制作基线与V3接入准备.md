# 原剧二创制作基线与V3接入准备

日期：2026-11-09。状态：独立脚本样片已获得“视频差不多吧”的阶段反馈；转入V3界面和中转站API接入讨论，尚未实施产品代码。

## 1. 当前目标和用户边界

用户选择一部原剧后，软件自动批量输出可直接发布的MP4，发布到视频号并挂载对应短剧链接，引导观众继续看剧。用户最多整体查看结果、淘汰明显不合格的视频，不逐条参与剪辑。原片获取由用户解决，最小输入是按集保存的视频文件；简介、封面、人物图可有可无。

当前不以发布反馈、爆款概率或复杂分析体系作为开发前置条件。先接入V3让用户实用，再按结果调整。用户对少量不完美衔接有明确容忍度，一条5—10分钟视频只有一两个跳点时，大致能懂即可，不反复精修。不要把软件合成成功等同于爆款验证。

## 2. 已确认的制作方法

### 方式一：高光切入，按原顺序连续播放

模型选择原片中的高光起点，从该位置起沿原集序播放，结尾尽量在一句话或事件可停顿的位置。原声、原画面和原有字幕保留。无需另写旁白或固定文案；不能把某部剧的选点硬编码到通用流程。

### 方式二：高光切入，少量跳集播放

模型选择高光后，保留能构成剧情发展的原片范围，跳过部分过渡或支线；本阶段沿原剧情时间顺序，不倒叙重排。范围可以是完整集，也可以是某集的一段，不能把一集强制当成唯一故事模块。当前不另建全剧精细故事模块体系。

优先一两个跳点；现有计划校验支持数量上限，本次测试设为最多2处且实际每条只有1处。每个跳点要能说明删掉什么、后文为何大致能懂。不要删掉理解后文必需的问题、关系、动机或完整动作的一半。不确定时多保留。允许用新场景明确的对白承接时间省略。

### 参数

- 时长由用户输入区间，例如5—10分钟；剧情效果优先，随机时长只是参考，不为精确凑秒而截断关键对白。
- 当前真实测试和渲染器硬校验均为300—600秒。界面如允许其他区间，必须同时调整底层校验，不能只改输入框。
- 片尾停顿保留/去除做成可选。已交付样片均保留；去尾只有范围逻辑测试，尚未做本轮实际观感验证。
- 默认保持原声和原字幕。当前成片采用720×1280、24fps、H264/AAC，作为实测参数；最终产品默认值待讨论。
- 数量按有效高光和可组合内容决定。不要为达到数字反复输出几乎相同的视频或强凑弱开头。目标数量与不足时处理待界面设计确定。

## 3. 复用已有skill，不重建选点算法

主要复用：`C:/Users/Michael/.codex/skills/shortdrama-highlight-batch-jianying/SKILL.md`。

高光至少满足以下三项中的两项：三秒内能理解冲突；有当下动作、命令、明确利害或强声明；对白暗示可见对抗。排除感悟、寒暄、泛泛提问和依赖前情才能理解的身份揭晓。按叙事完整性保留上下文，不用关键词打分替代模型判断。

## 4. 已跑通的实际链路及职责

原片扫描 → 本地faster-whisper识别/缓存复用 → 转成现有skill可读取的transcript.json和SRT → 当前模型按skill集中判断 → 保存picks.json → 校验并生成连续/跳集计划 → 本地FFmpeg合成 → 完整解码检查 → 用户看成片。

- 本地程序负责扫描、识别、缓存、时间戳、范围校验和合成。
- 模型负责高光选择、剧情范围、跳集取舍及语义上的收尾。
- 当前仍由会话中的Codex完成模型判断。中转站API、无人值守自动判断和软件按钮均未接入。
- `run_local_skill_flow.py`的prepare步骤会停在模型判断入口，finish读取已有picks后批量输出。不能描述成现在已经完全无人参与。
- 材料兼容原skill已经验证；本地识别优于或等同豆包没有验证。识别文本存在错字和重复幻觉，不能当作精确剧情事实。原片原声/硬字幕并未被识别文本替换。

## 5. 控制Token和重复工作

- 识别与合成本地执行，同一部剧识别缓存复用；缓存记录源文件身份，源变化不盲用旧缓存。
- 供判断的字幕按集排列，每句只出现一次，避免为每个候选复制一大段上下文。现有适配器按不超过4000文本Token分包，分包本身不代表已完成全剧理解或模型调用。
- 高光及剪辑方案保存后，多条视频复用已有判断。只对缺信息的位置补局部材料，不因换时长、重试合成就重读全剧。
- 中转接入后保存每次请求的模型、输入/输出用量、耗时、结果及失败阶段；费用按服务商真实计费信息算，缺失时显示未知。
- 保存材料的Token估算不等于当前会话账单，也不等于每条视频成本。不得用“外部API调用0”宣称当前会话免费或低成本。
- 不反复补测试、扩展理论或重新研究已存在的skill标准。一次小批量真实运行后交用户看成片。

## 8. 已确认的业务分层与通版模板方向

用户确认：制作、入库、编组、发布原创、发布授权分开计算；业务框架保持可调整，不把当前不稳定的运营规则硬编码成不可变流程。专属模板采用通版方式，在制作成片时直接套入，不再作为后置包装阶段。成片库是高于某一种制作方式的视频资产库，可以收纳二创生成、原有制作方式和外部导入的作品。

推荐的业务对象和关系：

```text
不同来源的视频 → 成片库
                    ↓ 选择作品
                  编组（自由管理集合）
                    ├─ 发布原创
                    └─ 发布授权

原剧二创制作 → 生成记录（内部去重和追溯）→ 成片库
```

- **制作**：根据原剧、选点方案和当前通版模板生成最终成片。系统保留生成记录、来源范围、方式、时长、模板版本和结果，主要用于避免同一部剧重复产出相同或高度相似的东西；生成记录不是用户日常必须管理的业务分组。重新剪出不同内容时保留新的生成记录；同一方案失败重试可以归在原生成记录下。
- **入库**：技术检查通过的视频进入成片库，来源不限于当前二创制作。每条成片保存来源类型、来源剧集或外部来源、生成记录（如有）、模板、时长、路径、文件指纹、技术合格状态、人工淘汰状态、淘汰原因、原创声明状态、授权次数和使用账号。成片库不是无限期自动积累的归档区，淘汰作品可以删除；已经发布过的作品保留，授权次数用完也不自动删除。
- **编组**：从成片库选择作品组成一个方便发布管理的集合，例如10条。编组不是制作批次，也不要求作品来自同一种制作方式；可以混合不同剧集、不同来源和外部视频。编组只建立可调整的集合和发布安排，不重新制作视频。同一成片可以进入不同编组，但每次原创声明和授权占用都要单独记录。
- **发布原创**：从编组中选择作品，使用现有自动发布流程发到原创账号并声明原创。一条最终成片只能有一次原创声明；发布成功后记录原创账号、发布次数、时间和平台作品信息。当前一个账号连续发布同一视频1次、2次或3次都只是可变的运营做法，不写死在作品定义里；系统重点记录该账号实际消耗了几次。
- **发布授权**：原创发布成功的作品交给小V猫现有授权能力处理，V3不重复实现授权流程。系统只保留授权使用记录和账号消耗统计。当前平台规则为每条作品最多9次授权；发布成功后才消耗一次授权，发布失败不消耗，也不算原创通过。

同一部剧再次制作时，系统保留新的生成记录，用于相似检测和追溯；用户不需要把它当作主要业务分组。系统发现同剧已有相同或高度相似内容时先提醒，不强制禁止生成。换账号或换发布安排时，只新建编组或发布任务。作品归属不能只靠“剧集 + 账号”判断。

如果将来同一素材确实表现很好，改用另一个模板后再次声明原创，应视为新的最终成片或成片变体，保留新的文件指纹和独立原创声明记录，不能修改原成片的原创状态。该能力属于下一阶段，本阶段只保留扩展位置。

技术合格由软件自动检查；人工审核作为可开启的设置，不要求逐条查看。正常情况下成片自动入库，用户发现明显不合格时可以人工淘汰并删除。已发布作品不能因为授权次数用完自动删除；发布失败不标记为原创成功，也不扣授权次数。原创声明失败本阶段只记录结果，暂不扩展失败处理流程。

### 专属通版模板的建议

专属模板作为“品牌通版模板库”，在制作成片时直接套入。每条成片一旦入库，就锁定实际使用的模板版本；以后模板更新只影响新制作，不回写历史成片。

模板具体样式和制作方式暂不在本事项确定。当前只确认：模板属于制作输入，直接进入最终成片；模板版本和参数要随成片保存。将来模板变化时，不覆盖旧成片，可基于已有剪辑方案重新合成新的成片变体，不需要重新识别和重新判断高光。

- 配置服务名称、Base URL、API格式和密钥。密钥写入V3的`系统数据/gpt-relay.json`，接口返回只提供是否已设置和掩码，不把密钥返回前端或写入普通运行日志。
- “获取模型”调用中转站的`GET /v1/models`，按当前服务返回的模型ID刷新列表并保存抓取时间，不在V3硬编码模型名单。
- 任务默认模型目前分为高光判断、连续播放规划、跳集播放规划和结果复核四类，保存的是“任务角色→实际模型ID”。
- “测试连接”使用已选择模型发起一次最小请求，记录模型、状态、usage和测试时间，不记录密钥。
- 已增加通用结构化 JSON 调用层，接口为`/api/v3/gpt-relay/generate-json`。调用方传入任务角色、prompt和JSON Schema，返回经本地JSON解析的结果、模型、usage和耗时；prompt和返回正文不写入配置文件。
- V3后端直接调用中转站，运行不依赖CC Switch。当前已支持OpenAI Responses和OpenAI Chat Completions两种协议；短剧流程默认使用Responses。

代码入口：`server/gpt_relay.py`、`src/api/gptRelay.ts`、`src/components/settings/SettingsView.tsx`。接口为`/api/v3/gpt-relay`、`/api/v3/gpt-relay/models`和`/api/v3/gpt-relay/test`。

本阶段没有把本机CC Switch密钥自动导入V3，也没有把密钥写入文档。后端单元测试4项通过，Python语法检查通过，Vite生产构建通过。用户已在V3界面填写中转配置并完成“获取模型”和“测试连接”，模型列表正常返回。随后用新代码真实调用`gpt-5.6-terra`完成结构化JSON请求，返回`{"ok":true}`，HTTP 200，usage和耗时均已记录。过程中发现urllib TLS兼容问题，已切换到requests并加入运行依赖。二创任务尚未接入该模型调用链。

本轮已先替换三处容易误导业务的数据：原剧下拉框读取V3剧集与原片资料，账号下拉框读取V3账号，中转模型下拉框读取系统中转配置当前返回的可用模型，并排除`codex-auto-review`。这些读取失败时页面提示，不再回退到压缩包里的演示剧集和演示账号。

模板列表、生成任务推进、成片库、编组、原创发布和授权发布仍是前端原型状态。点击这些原型操作只改变当前页面状态，尚未写入成片库或调用真实制作、自动发布、小V猫接口；页面顶部已明确显示这个边界。旧生产中心保持原样。本轮通过Vite生产构建和现有236项前端测试，TypeScript全量检查仍因项目规模超过Node堆内存而未完成。

### 12.1 成片文件目录规则

成片库使用V3数据盘下的标准内容资产根目录，不使用源码目录或原片目录：

```text
<数据盘>\\短剧推广运营系统\\内容资产\\成片库\\
├─ 原剧二创\\<剧名>\\
├─ 旧流程成片\\<剧名>\\
└─ 外部导入\\<来源或剧名>\\
```

目录按来源和剧名保持稳定，不能用“制作批次”作为主要目录层级。同一部剧重复制作时，通过成片ID、文件指纹、生成记录和模板版本区分，避免把运营编组与文件存储混在一起。`待审核`、`已发布`、`授权次数用完`等状态由成片库记录，不再搬动文件目录。当前界面会显示这个正式目录，真实成片写入将在后端成片库接口接入时落地。

### 12.2 制作输入界面规则

- 原剧选择改为可输入关键词的搜索框。
- 默认只显示已经登记并确认有原片视频的剧集，按可用集数优先排序，不把全部剧集目录直接展开。
- 模型不在制作页重新选择。制作页只展示设置页已经分配的“高光判断、连续播放规划、跳集播放规划、结果复核”模型。
- 连续播放和少量跳集播放属于同一批次内可以同时启用的生成方式，分别设置数量，不能用互斥单选表达。

### 12.3 木木短剧通版模板与长剧名规则

当前保留4个模板视觉版本：原始通版、蓝色版、青色版和红色版。四个版本使用同一套版式，只切换配色，后续新增配色继续沿用同一结构。

- 顶部使用可变剧名，底部固定使用“木木短剧”。
- 英文辅助信息使用`SHORT DRAMA`和`DRAMA SERIES`，不再加入其他中文说明。
- 当前先保留原版静态模板，不接入动效层。
- 剧名长度不使用横向滚动。短标题保持较大字号，中等长度自动缩小，较长标题自动分成两行；极端长度保留人工短标题覆盖字段。
- 标题条宽度、字号、行距和断行位置由模板参数控制，不能因为剧名变化遮挡人物脸部或原剧字幕。

长剧名静态适配样片位于`docs/界面设计输入/`：

```text
木木短剧模板-原版长剧名-保持原字形.png
木木短剧模板-蓝-长剧名-保持原字形.png
木木短剧模板-青-长剧名-保持原字形.png
木木短剧模板-红-长剧名-保持原字形.png
```

这些文件是以“靠一碗福饺，我逆风扭转人生”为标题的静态视觉验证样片。长标题沿用原版标题字形和标题板，按各配色标题区域的实际宽度缩小字号。当前只验证静态版式，尚未接入正式成片合成器。

运行时模板已加入`server/content_template_renderer.py`。它按模板编号生成透明叠层，剧名由调用方传入，先尝试单行自动缩小，再按标点换成两行；无法放入时返回明确错误，不截断剧名。四个模板的运行时叠层已用该标题生成到`docs/界面设计输入/木木短剧运行时叠层/`，命令入口为`tools/render_mumu_template_preview.py`。当前已验证叠层生成和标题布局规则，内容生产页面仍未把真实二创合成任务接到该渲染器。

2026-11-10 已把模板预览接入V3内容生产页面。后端新增`/api/v3/content-templates`目录接口和`/api/v3/content-templates/render-preview`预览接口，页面根据当前选择的原剧名和模板配色自动请求透明叠层并显示预览；真实二创合成任务仍未接入该接口。
