# V3工作台真实数据与发布归属

日期：2026-11-02。范围：真实数据读取、V3发布历史与优化口径；用户再次明确不修改既有UI。撤回本次新增提示条、字段改名和健康状态配色，保留原布局、卡片顺序、文案与样式。前端仅连接数据和处理缺失值，缺失沿用“—”。

## 当前规则

- 账号资料、作品累计流量、账号日数据覆盖账号全部来源的作品。日数据不由作品累计量相减生成。
- 整体优化率＝已关联V3作品中的优化作品数÷已确认公开的V3历史发布作品数；原创优化率使用同一分母，分子仅为完整作品分析归类到“原创优化”的作品。
- 一作品一条优化；分析保留官方完整原文，按完整文本及已核实的同义原文精确映射，接口数字类型不直接替代原因。
- 没有V3发布归属的优化记录不写入业务优化历史；不把账号当前剩余视频数当作历史发布数。
- 没有完整诊断、诊断早于发布、异常缺少具体分析时，优化结论保持未知；范围内存在未知结论时不展示完整优化率。确认的0与缺失分开。

## 实现

- `server/operations_collection.py`新增采集与历史记录：发布尝试、作品编号与公开状态、匹配优化原文、真实缓存、采集结果。发布记录保存时同步归档，保留历史尝试。
- 原刷新按钮读取平台账号统计、在线分页作品与最近诊断。2026-11-02后续已用在线读取替换慢速后台作品同步；失败保留历史与缺失。仅采集有效且在V3有效账号档案中的账号，跳过注销。
- 在线作品观察时间为实际读取时间；本地作品缓存观察时间使用小V猫的`updatedAt`，不把重新读取旧缓存的当前时间冒充指标更新时间。账号日数据按日期累计保存，后续七日读取不抹掉更早日数据。
- 定时作品优先通过V3任务编号、账号与平台定时时间唯一关联稳定作品编号。任务上传成功不算已公开；后续读取已发布状态才进入历史分母。平台公开后可能不再保留原定时时间，因此桌面运行时每30秒跟踪待公开记录，在等待期间先保存编号；此跟踪只读取平台数据，不提交发布/删除操作。
- 优化与已确认发布历史按账号和原始秒级时间唯一匹配。多个候选、同秒外部作品或同秒多条诊断时保持未关联。不按近似分钟或固定时差推断。
- 已保存发布历史和作品分析独立于当前作品列表，平台删除不会移除这些历史。尚未采到的分析无法凭空恢复。
- 运行接口默认只读取本次真实缓存，首次采集前也不回退模拟数据。模拟、开发造数和未验证旧迁移收益均保留在原表但不进入工作台；旧聚合回归测试显式使用历史快照模式。

## 2026-11-02 账号日流量补齐与增量采集

用户进一步确认：先复用小V猫本地已有数据；缺失时才主动刷新官方统计，随后重新按指定日期读取。不能假定小V猫自动拥有历史数据，也不能把缓存最早日期当成开始使用日期。

- 首次从截至昨天的90个自然日开始查询，尚未取得起点依据时分段继续向前查本地历史，每段最多90天；已有完整日期同样跳过。查询返回实际日记录；按已取得记录中的最早非零活动日、以及紧邻之前连续7天全0推定起点。7天为当前暂定实现值，未表述成平台规则或账号注册日。全0判断只用播放、关注变化、爱心、点赞、评论、分享，关注者总量不参与；缺日、缺字段、空返回不能充当0。区间内的0日继续保留。
- V3已有完整日记录不重新查询、不覆盖；中间缺日/缺核心字段先按缺口查小V猫本地，仍缺才调用`vcat_refresh_account_stats`主动刷新对应账号，再只读回缺口。原有非空字段保留，仅补缺失项。可为空的当日关注者总量不造成永久重复采集。
- 小V猫MCP的日期查询读取本地缓存；刷新接口目前不接受日期参数，因此触发刷新时它自身可能一并获取一段统计，V3只读取和保存所需缺口。逐段查询与主动刷新后若仍没有连续全0的起点依据，或仍缺日，记录`partial`，不得冒称历史已补齐；这类账号更早的主动回溯仍待按实际样本验证与扩展。
