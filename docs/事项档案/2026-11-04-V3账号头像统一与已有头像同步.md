# V3账号头像统一与已有头像同步

日期：2026-11-04

## 目标与现场

用户确认修复账号头像多处显示不一致。前一轮只读核对当时账号库7个账号中6个有本地头像，6张均HTTP200；账号列表与运营驾驶舱同账号头像地址一致。确认的问题是：获取账号预览直接用远程图片、业务页面用本地缓存；生产中心独立实现且按昵称关联；公共头像组件加载失败后不重试；已有账号导入直接跳过，不能独立补齐头像。本次正式库当前数量没有重新盘点，不把前一轮数量当作永久状态。

## 实施范围

- `src/components/AccountAvatar.tsx`：所有已使用该组件的账号页面统一有限次自动重试、网络/窗口恢复重试、URL变化清除失败状态；仅本地URL添加重试参数。失败/缺图时保留姓名首字回退。
- `server/v2_file_service.py`、`src/api/v2Production.ts`、`src/adapters/production.ts`：生产详情及摘要附带实际账号ID，前端不再将账号昵称冒充ID。
- `src/components/production/ProductionCenter.tsx`：按账号ID查共享账号资料并使用公共头像组件；移除另一套按昵称查找、加载失败后永久隐藏图片的实现。未改变任务文件或发布逻辑。
- `server/account_import.py`、`src/api/accountImport.ts`、`src/components/assets/modals/AccountFetchModal.tsx`：预览已有本地缓存优先显示；增加“同步已有头像”及单独后台任务，只处理本次获取结果中与当前本地平台ID匹配的账号。预览本身只读。同步不要求勾选账号，不创建账号，不改其他业务字段。
- `server/drama_catalog.py`：头像提交时再次校验身份，并以写事务保持校验与保存的一致性；变更通知与缓存版本同步更新；同图文件落盘锁保护共享缓存，下载失败保留旧图。不删除缓存或原媒体，不新增数据库表或字段。
- `src/services/accountAvatarSync.ts`：单任务单观察者持续读取进度，增量通知各页面；关闭弹窗仍继续，避免同步完了其他页面还留在首字。连续3次读取失败停止观察并提示重新获取核对，后台任务本身不因此取消。
- 两个相关后端测试文件新增同步边界、缓存通知、下载时身份变更、相同图片并发写、预览地址及生产ID检查。功能档案和控制台同步维护。

## 可观察入口

源码开发版正常重启并构建后，进入资料中心 → 账号管理 → 获取账号，在右上角点击“同步已有头像”。界面显示更新、跳过、失败及逐账号结果。任务只更新头像，失败保留原图；再次重新获取后可重试。现有分组筛选保留。

## 验证结果

- 97项相关后端检查通过（账号导入、剧集目录、小V分组及文件服务）。加入同图并发保护后，38项头像/导入相关检查最终复查通过；最后强化写事务后，3项并发/身份/通知定向检查通过。计数有重叠，不累计为138项。
- 55项前端既有检查通过，覆盖共享数据刷新、账号变更事件、驾驶舱模型及生产排序。
- src全部TypeScript检查通过；生产账号ID适配断言通过，缺ID时不猜成昵称。
- Vite界面完整构建通过，1826模块，输出隔离目录，未覆盖正在运行的dist；保留已有单包体积提示。
- 9组实际React组件＋隔离后端浏览器验证通过，使用真实AccountFetchModal、AccountAvatar、ProductionCenter及临时数据库，仅小V猫来源和图片下载为固定模拟：有图/缺图、同ID不同任务显示名、503自动恢复、失败有界重试、URL切换恢复、已有预览共用本地图、关闭弹窗后自动更新、业务字段不变且不新增账号、重新打开显示同步后地址。无页面脚本错误，已查看结果截图。
- 隔离账号甲原有图片、账号乙原本缺图；同步后两者使用相同内容缓存，账号API与生产卡片一致。逐字段对比昵称、剧场、状态、备注、账号更新时间均未变化。
- 初次页面验收的定位器作用域不当，已修正；随后双账号同图并发验收出现一项失败，复查发现原实现有同图文件并发落盘风险，增加文件锁并以专门并发用例及新隔离库复验通过。未保留异常详情，不能将初次失败的精确异常类型当作已证实事实。
- 隔离服务已停止。没有操作正式业务库、真实小V猫账号、正式媒体；未重启正式桌面、未打包或收口版本。
