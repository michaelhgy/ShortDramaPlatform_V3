# V3视频流量标签与分级规则

## 用户要求与当前口径

用户修订观察期为12小时、低播为24小时、小爆从3万开始，要求沿现有标签做样式，并把优化标签放在流量标签左侧。本次仅改变作品表现的分级与展示，以及只读接口选择有效作品快照的优先级；不改业务库、模拟数据、采集任务、账号等级或收益算法。

| 流量标签 | 规则 |
| --- | --- |
| 待采集 | 无有效播放记录、时间异常，或发布已满24小时但还未采到覆盖24小时的数据 |
| 观察中 | 发布不足12小时，累计播放不足1000 |
| 待起量 | 发布满12小时、不足24小时，累计播放不足1000 |
| 低播 | 发布满24小时后已有有效采集，累计播放仍不足1000 |
| 常规 | 累计播放1000—不足3万 |
| 小爆 | 累计播放3万—不足5万 |
| 爆款 | 累计播放5万—不足10万 |
| 大爆 | 累计播放≥10万 |

“待起量”是为12—24小时空档补齐的实现选择，表示等待，不代表已确认增长。有效播放达到门槛可立即升级，不等观察期结束。正常后续流量减少不取消已记录的累计级别；本次没有伪造不可修正的历史峰值。数据被正式修订时仍按可用事实计算。

时间按北京时间解析无时区字符串、按绝对时刻处理带时区值；缺失/失败不转为零播放。低播要求采集时刻已满发布后24小时，不能仅等电脑时间过去24小时就据旧值判断。采集只有日期时，以当日零点作为保守下界，不伪造当日晚间采集；小于门槛且发布时间不明确时待采集。页面在12/24小时边界自动重算，不需要切换页签。

## 实现与展示

- `src/services/videoTrafficRating.ts`集中定义8种状态、门槛和确认条件，10项规则测试覆盖边界、时区、缺失、失败、旧采集、立即升级、历史累计保留及与完播/优化独立。
- `shortDramaOps.ts`和`cockpitModel.ts`为作品传递接口原有采集时间、快照日期和状态，未改变作品金额或播放数。
- `VideoTrafficTags.tsx`共用于作品卡片、表格和作品详情：优化标签左、流量右，现有圆角胶囊＋小图标；常规/观察为浅底，爆款保留橙色白字，大爆橙红。无原生长文本title，悬停白色圆角浮卡显示简明规则与采集依据，详情可展开完整规则。未归类的平台优化如实显示待归类，不冒充正常。
- `CockpitView.tsx`移除按25%完播率贴爆款，表格“优化状态”改为“视频标签”；`VideoDetailDrawer.tsx`共用标签与折叠规则，并移除“爆款级高完播”等文案。平台通知和处置影响仍在原详情，卡片中已删除的大段预览不恢复。
- `server/operations_dashboard.py`选择每条作品最后可用快照；后续失败/空计数不能覆盖已有有效播放成绩。不存在有效历史的失败记录不新增成绩，前端原有效数据筛选继续适用。不迁移、建表、写库或触发外部采集。

## 交付边界

刷新前端可加载新标签与采集元信息；新增后端的失败快照优先级需用户重新打开V3开发版加载源码。当前没有替用户重启服务或窗口，Windows实际观感仍由用户验收。

本次没有接入单条视频日增量、单条收益或平台实时状态，不推断增长/回落/尾量，也不把低播当限流。完整采集失败且没有有效历史的作品仍遵循现有前端有效作品过滤，待采集标签不会凭空创建不存在的作品记录。截图夹具不能代表正式平台返回和外部采集已验收。
