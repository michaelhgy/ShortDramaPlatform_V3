# V3完成模板直接循环复用

## 现场与原因

用户重新生成模板1019-002后，第一条《一副旧牌定生死-1》87.666667秒成片用了674秒。只读核实生产日志：655.171秒用于把159秒模板缓存扩展到477秒，实际画面合成16.266秒、完整解码1.781秒。批量提交把本批最长素材12786帧（426.2秒）写入每条配方的 `template_prepare_frames`，导致第一条替全批准备缓存。

用户确认模板时长不够应直接复制/循环，授权在当前生成完成后修正。开始时当前任务已完成、4条等待、队列暂停，无FFmpeg进程。没有恢复生产队列。

## 落实

- 成片改为只读加载模板原始完整周期，循环已完成文件的引用，末尾直接截断；原素材和原声保持原时间轴。成片不调用模板制作或缓存扩展。
- 新批次不再保存最长素材准备字段；已经排队的旧配方保留原数据，但执行时忽略该字段。因此现有4条等待任务重启后可继续，无需重提。
- 已被旧代码扩展的模板仍可用，只选择最初一个完整周期；后续扩展文件保留，不修改或删除。缺失/不完整/损坏缓存明确报错，不在成片阶段临时重做。
- 普通透明和滤色整条一次编码；素材相关滤镜重复使用同一组已准备输入，仅主素材读取位置前移。每帧只编码一次，音频不随模板循环。
- 模板预览使用相同周期读取方式；新模板不再额外生成按成片结尾长度调整的备用画面。已有模板无须为此次修改重新生成。
- 循环意味着风景、贴纸、特效、边条按整段模板重复，沿用模板已保存过渡；本轮不重新设计首尾画面或新增淡变。长片循环边界的风景切换在对照页可查看。

正式修改：`server/ffmpeg_templates/precompose.py`、`renderer.py`；`server/ffmpeg_finals/renderer.py`、`cached.py`、`service.py`；对应两组后端测试和当前规则。界面无改动。

## 实际验证

输出只写入 `local-test-output/v3-template-loop-20261019/`，输入来自真实模板和同批素材，未写入业务任务或计次。

| 验证 | 结果 |
|---|---|
| 同一87.666667秒短素材 | 18.609秒，31,175,498字节；与刚完成的正式成片逐字节一致 |
| 同批426.2秒完整长素材 | 90.875秒，150,677,936字节；159秒模板循环3次，最后一轮截断 |
| 缓存制作/扩展 | 两条均0秒，正式缓存索引、文件集合、大小和修改时间保持不变 |
| 长片帧数与时间戳 | 12786帧，1080×2400、30fps，逐帧时间戳连续 |
| 循环引用 | 第一周期10个缓存文件，第二周期重复同一顺序，第三周期读取前缀，共27个引用 |
| 素材相关特效 | 已有2秒特效缓存循环合成135帧通过，完整解码通过 |
| 模板预览路径 | 已有10秒完成缓存生成300帧预览通过 |

两条完整成片均执行规格、音轨存在/时长及完整解码检查。短片完整文件一致也覆盖画面和原声一致；长片主素材和原声保持连续。循环点159、318秒前后六帧已查看，无空画面；风景回到模板开头属于整段重复，最终观感由用户确认。

相关后端检查共100项；新增覆盖短片不扩展、长片重复引用、不改正式缓存、缺失缓存不自动创建、素材相关滤镜原声时间轴、批量配方不再带最长长度。一次测试夹具未先准备原始周期，修正后针对28项重跑通过，再执行整组检查；日志留在验收目录。

## 交付与保护

`index.html`提供短片前后对照、完整长片与两次循环跳转；`baseline.json`、`results.json`、`preservation.json`、`loop-check.json`和`other-paths.json`记录证据。既有正式素材、成片和模板缓存未改动，V2未改动，未提交或推送。测试初次特殊滤镜路径引用已不存在的历史素材，失败日志保留，随后改用本轮现有素材验证通过。

未自动重启软件；用户正常关闭并通过V3启动入口重开，再继续当前暂停队列即可。模板1019-002可以继续使用，已完成第1条不需要重做，4条等待项无需重建。其他模板的大批量耐久及用户连续观看仍需区分验收。
