### 2026-11-12 code 模式：中转站连接失败（代理）修复

- 现象：生成「剧情地图」第 3 步报错 `中转站连接失败：... host='m2ai.top' ... Unable to connect to proxy, Remote end closed connection`；设置里"获取模型"却正常。报错后任务停住，再点开始会新建任务。
- 根因：`server/gpt_relay.py` 的 `_request_json` 用 `requests` 默认会读系统代理（梯子/VPN）。用户开着代理，大请求被导去代理连 `m2ai.top`，被代理端断开。获取模型是小请求、偶尔没被代理掐，所以看起来正常。
- 修复：请求中转站默认直连、忽略系统代理；保留一个开关，个别需靠代理访问的中转站可打开。
  - `gpt_relay.py`：`DEFAULT_CONFIG` 加 `use_system_proxy`（默认 False）；`_request_json` 加 `use_proxy` 参数，`requests` 分支用 `trust_env=False + proxies={}`，`urllib` 分支用 `ProxyHandler({})`；`fetch_models/test_connection/generate_json` 都把开关传下去；`save_config` 读写该字段。
  - 前端：`src/api/gptRelay.ts` 加 `use_system_proxy` 字段；`SettingsView.tsx` GPT 中转设置加勾选框"通过系统代理访问中转站"（默认关闭）。
- 验证：`npm run build` 通过；`test_remix_planner` + `test_gpt_relay` 共 13 项通过（含新增代理开关用例）。用真实配置（m2ai.top / gpt-6.1-sol）在设有代理环境变量的情况下实调 `test_connection`，默认直连成功返回 200，证明用户那条失败请求已修好。
- 未改：「报错后原任务不能续跑、重跑即新建任务」是现有流程设计，本次未动。若要"重试同一任务"需单独立项。
