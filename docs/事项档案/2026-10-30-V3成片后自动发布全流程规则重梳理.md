# V3 成片后自动发布全流程规则重梳理

## 文档状态

本文件是自动发布代码比对前的业务规则基线。它根据当前实际使用场景重新整理“成片合成完成 → 自动发布 → 异常处理 → 成片区状态”的完整流程。现有自动发布功能档案和旧事项档案中的冲突内容，在本文件确认后再统一修订；本轮只整理规则，不代表代码已经符合这些规则。

## 一、对象和边界

一次成片任务对应一个账号和一部剧。成片合成成功后，发布模块接管成片文件，但不会自动发布、自动删除成片，也不会因为打开发布工作台就创建小V猫任务。

发布过程中要区分四类对象：

| 对象 | 作用 |
| --- | --- |
| 发布设置 | 本次发布的账号、视频、封面、文案、地址、挂载、声明、份数、时间和间隔 |
| 发布批次 | 一次“发布”或“重新发布”形成的完整批次 |
| 发布条目 | 批次中的一个视频复制份数，拥有独立状态 |
| 小V猫任务 | 发布条目提交后由小V猫生成的远端任务及任务ID |

V3只负责保存任务快照、调用小V猫、读取状态和提供人工决策入口。小V猫的任务历史不能通过V3删除；官方账号后台已经上传成功的视频，也不能由MCP删除，必须人工处理。

## 二、从成片完成到第一次发布

### 1. 成片完成

- 成片文件存在且可以读取，才进入可发布列表。
- 正剧视频和羊视频按成片文件标记自动分组。
- 成片没有封面时仍可以发布，封面字段直接省略。
- 成片阶段的计划发布日期不等于实际发布时间；实际时间在发布工作台重新确认。
- 此时不创建小V猫任务。

### 2. 打开自动发布工作台

工作台按账号ID读取小V猫账号，不按昵称替换账号；读取当前剧集、成片、挂载来源、封面、地址库和默认配置。

本次可以调整：

- 正剧/羊视频归属、份数和排列方式；
- 发布封面是否使用；
- 视频标题、简介、话题、短标题、声明、追评；
- 地址和正剧/羊地址同步；
- 小程序、视频号、插件挂载方式；
- 平台定时或本机定时、开始时间和间隔。

保存设置只保存发布参数，不创建小V猫任务。

### 3. 发布前检查

检查必须覆盖整批：

- 小V猫远程调试和MCP连接；
- 账号登录状态和账号ID；
- 视频文件是否存在；
- 地址对象是否是完整候选参数；
- 挂载剧集是否属于当前账号、来源是否一致、剧集是否可用；
- 标题、简介、话题、声明和封面参数；
- 每条实际发布时间是否有效、是否超过平台允许范围；
- 当前批次是否已经有对应的小V猫任务，防止重复提交。

检查失败时不创建任何新的小V猫任务。封面缺失属于允许继续的提示，不属于检查失败。

### 4. 第一次点击“发布”

- 使用当前发布设置创建一个新的发布批次。
- 每个视频复制份数生成一个独立发布条目。
- 每个条目提交成功后立即保存小V猫任务ID和提交参数快照。
- 新批次不复用其他批次的任务ID。
- 同一批次中，单条明确的参数拒绝、文件错误或挂载错误可以记录为该条失败，并继续后续条目。
- 账号登录失效、扫码验证、风控、权限不足、频控等账号级问题必须停止后续提交，已提交条目保留，尚未提交条目保持待处理。
- 提交响应中断、无法确定小V猫是否创建成功时，停止后续提交，先读取小V猫任务，禁止直接重复提交。

## 三、发布后的状态

### V3条目状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待提交 | V3已有条目，但还没有小V猫任务ID | 继续提交、排期重发或取消 |
| 已提交 | 小V猫已接收，等待执行 | 读取状态、暂停或取消 |
| 正在处理 | 小V猫正在处理 | 等待、读取状态或取消 |
| 本机定时等待 | 等待本机定时触发 | 保持小V猫和电脑运行，读取状态 |
| 成功 | 小V猫任务返回成功 | 是否官方公开仍需人工核实 |
| 失败 | 小V猫明确失败 | 重发或排期重发 |
| 暂停 | 小V猫或V3已暂停 | 重发、继续或取消 |
| 已取消 | 任务已取消或V3本地取消 | 排期重发或重新发布 |
| 结果待核对 | 提交结果不明确或任务无法读取 | 先读取小V猫，禁止直接重试 |
| 已废弃 | 旧批次被重新发布替换 | 只保留历史，不再操作 |

“小V猫任务成功”不等于“官方后台已经公开”。成片区可以显示小V猫确认的提交状态、挂载和发布位置，但不能把它写成平台公开结果。

## 四、四种异常层级

### 1. 提交前异常

账号、视频文件、地址、挂载、文案或时间检查失败：整批不创建新任务，修正设置后重新检查。

### 2. 单条条目异常

只有某条文件、参数或挂载错误：该条标记失败，其他条目继续提交。修正后可以针对该条使用重发或排期重发。

### 3. 账号级异常

扫码验证、账号风控、登录失效、权限或频控问题：停止后续新提交。已经提交的条目继续由小V猫处理，未提交条目保留待处理。账号问题处理后：

- 原时间仍有效：可以继续提交待提交条目，或重发明确失败条目；
- 原时间已经过去：使用排期重发；
- 结果不明确：先读取小V猫，不能直接重建任务。

### 4. 官方后台已上传但V3结果异常

如果官方账号后台已经出现视频，即使V3显示失败，也不能直接当成普通失败重发。先人工确认是否需要删除官方视频；确认不删除时，不自动补发同一视频。

## 五、操作规则

### 1. 继续提交

只处理当前批次中“没有小V猫任务ID”的待提交条目。它沿用当前批次参数，不改变任务身份和发布时间。原时间已经过期时，不使用继续提交，改用排期重发。

### 2. 重发

用于小V猫已有任务、但任务处于失败、暂停或取消状态，且原定时间仍然有效的情况。重发复用原小V猫任务，不修改地址、挂载、文案、封面和时间，不创建新的任务ID。

如果原时间已经过去，重发不再适用，改用排期重发。

### 3. 排期重发

用于账号问题导致部分成功、部分失败，或者原定时间已经过去的情况。

- 成功条目默认不选择；
- 失败、暂停、取消、未提交条目默认进入候选；
- 结果待核对条目不能自动进入候选，先人工确认；
- 原失败的小V猫任务不要求删除，也不再强行处理；
- 新批次沿用原参数，只重新计算发布时间和间隔；
- 新条目产生新的小V猫任务ID；
- 原批次和原失败任务保留历史记录；
- 已成功条目不自动补发。

### 4. 重新发布

重新发布表示“当前整批作废后重新来一遍”，不是普通重发。

使用场景：发现账号、地址、挂载、封面、文案、时间或其他整体参数错误，需要整批推倒重来。

执行顺序必须是：

1. 停止V3后续提交；
2. 请求取消小V猫中仍可取消的旧任务；
3. 人工进入对应账号官方后台，删除已经上传成功的视频；
4. 人工确认旧批次不再需要；
5. V3将旧批次标记为“已废弃”，只保留历史关系；
6. 用户修改自动发布设置；
7. 创建一批全新的小V猫任务。

如果旧任务仍在小V猫中待发布、正在处理或无法确认取消结果，不能直接创建新批次。小V猫任务历史不能通过MCP删除；V3不得伪装成已经删除。

重新发布可以包含原批次已经成功的视频，因为它代表用户已经决定放弃旧批次并人工处理官方后台结果。

## 六、成片区域与发布工作台的关系

- 成片区域只显示当前有效发布批次；旧批次显示在历史记录中。
- 发布批次未创建前，成片显示“未提交”。
- 有小V猫任务ID后，才显示挂载、位置、发布时间和任务编号。
- 重新发布后，成片区域切换到新批次，旧批次不再和新批次混合统计。
- 排期重发后，成片区域显示新任务的结果，同时保留原失败条目的历史关系。
- 取消、失败、结果待核对不能显示为成功。
- 平台最终是否公开，需要官方账号后台人工核验。

## 七、插件挂载

插件方式只生成小V猫本地草稿，不进入真实发布批次。插件草稿有独立的执行记录和状态，不参与真实发布的继续提交、重发、排期重发和重新发布流程。

## 八、代码比对顺序

后续代码审查必须按以下顺序进行：

1. 成片完成和自动发布入口；
2. 发布设置保存与参数检查；
3. 首次发布批次和条目创建；
4. 小V猫任务ID与参数快照保存；
5. 提交过程中的单条异常、账号级异常和结果不明；
6. 状态同步和成片区域投影；
7. 继续提交、重发、取消、排期重发；
8. 重新发布的作废、人工删除确认和新批次创建；
9. 插件草稿分支；
10. 历史记录、重复提交保护和跨电脑时间规则。

在这份规则与代码逐条对齐前，不制作新的发布升级包。

## 九、代码比对初步结果（只读）

当前代码与本规则的只读对照结果如下：

1. 已补上重新发布的准备、取消旧任务、人工确认和`abandoned`历史状态；官方后台视频删除仍只能由人工确认，不能由MCP自动完成。
2. 已从排期重发默认候选中排除 `uncertain`/结果待核对条目。
3. 已在继续提交入口拦截过期时间，提示改用排期重发。
4. 账号级明确拒绝已与结果不明分开；明确拒绝会停止后续提交并允许账号修复后继续提交，结果不明仍禁止盲重试。
5. 成片区新旧批次的真实视觉切换、真实小V猫取消返回和官方后台删除结果仍待验收。

以上差异只代表代码现状，不代表规则需要迁就现有实现；后续以本文件规则为准逐项调整。
