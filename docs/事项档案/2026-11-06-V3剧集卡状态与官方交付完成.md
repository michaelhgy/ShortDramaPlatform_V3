# V3 剧集卡状态与官方交付完成

## 目标与最终规则

日期：2026-11-06。用户要求整理剪映时代的状态遗留，并保持现有生产中心布局。

1. 剧集卡不再显示模板处理中／模板异常，移除旧剪映导出监听提示。保留实际模板选用、公共模板制作和管理功能。
2. 异常使用现有简短标签，不添加卡片补充说明行；单份任务原有错误详情仍可查看。
3. “全部／未完成／逾期”是一组，“已完成”独立成组，默认仍选全部。普通组均排除已完成；未完成维持包含逾期子集的原含义。
4. 已完成只显示已经成功交付官方、过程文件尚未清理的剧集卡；过程清理后退出生产列表，不新增历史归档入口。业务与分析记录继续保留。
5. 官方后台已经接受整批作品即为生产发布完成。官方接受的平台定时显示“官方已定时”；立即或混合方式显示“发布完成”。无需等定时公开。
6. 本机定时等待、上传中、失败、取消、结果不明或仅本地草稿都不算完成。小V猫本地发布草稿不是剪映制作草稿，插件方式继续保留。

## 完成证据与清理起点

- 逐条核对小V猫成功结果、账号 UID、本地任务编号、发布方式，以及可取得的实际参数核对结果。
- 官方作品 ID 可以来自成功日志，或来自已经唯一匹配本地条目的作品记录。后者兼容当前真实数据中“成功日志无作品 ID、作品历史已有 ID、公开时间为空”的情况。
- 整批所有当前条目满足才完成；同一账号同一作品不能用于满足两个发布份数。任意一份不满足仍为未完成。
- 卡片索引同步和现有后台跟踪均能根据已保存证据确认完成，不要求逐个点开卡片，不创建或恢复外部发布任务。
- 清理期限从整批最后一条小V猫上传发布结束时间 `postEndTime` 起算。可靠结束时间缺失时从首次核实交付的时间起算，不使用任务创建时间、上传开始时间或定时公开时间。
- 新增 `production_tasks.delivery_completed_at`，默认空字符串；升级为幂等增加字段，不清库、不重写已有记录。
- `actual_release_time` 继续保留实际发布时间语义，其在旧收益日期匹配中的用途不变。作品公开状态及时间继续独立保存，不把交付完成误写成已经公开；之后整批实际公开时间齐全时再补齐原实际发布时间，不重算清理期限。
- 过程文件默认24小时、原素材默认7天，服从现有设置。已保存的清理到期时间不因刷新或改设置而重算；旧记录可沿用原实际发布时间兜底。
- 清理仍复用原来的任务归属、运行任务阻止、失败重试和分阶段删除逻辑。交付完成本身不立即删除文件。
