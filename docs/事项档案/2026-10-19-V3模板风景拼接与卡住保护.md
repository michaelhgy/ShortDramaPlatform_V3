# V3 模板风景拼接与卡住保护

## 目标、授权与现场

用户正在制作模板，认为耗时过长。只读检查确认卡住后，用户明确同意“暂停后续模板，只停止当前卡住的FFmpeg，保留现场；只修改V3，修复风景拼接和无进度保护，用同一份配方在独立目录验证”。

- 当前任务：`703b1f54ce76410cbea696e6da892b92`，模板1019-003，180秒、1080×2400、30fps，共5400帧。
- 先暂停模板队列，再核对进程命令和父进程，只停止PID35980。应用主进程没有停止或重启。
- 该任务随后由原执行器自然登记失败，总计598秒；下一条模板1019-004保持等待，队列保持暂停。没有重试正式任务。
- 现场配方、日志及中间文件保留在真实任务目录；文本证据与修改前源码副本保存至`local-test-output/v3-template-stall-20261019/`。V2、原片、正式缓存、已生成模板没有改动。

## 已确认原因

1. 单段风景本身输出了预期帧数，但拼接通过`setpts=N`再次编码。来源色彩范围不同，FFmpeg反复重置滤镜，帧计数时间戳也重置，产生大量丢帧。
2. 计划上下各5400帧，旧上轨只剩1860帧/62秒，下轨3227帧/107.566667秒。旧上轨日志记录`drop=3618`及多次`yuvj420p(tv/pc)`重配置。
3. 特效切换段2685—2715帧读取89.5秒位置，上风景已没有该时段。有限空输入与循环蒙版/贴纸组合，使FFmpeg持续占用CPU而没有第一帧输出。缓存文件0字节、进度文件为空。
4. 当时已经配置h264_nvenc。问题发生在送到编码器之前，不能靠切换显卡编码解决。

## 实施

- `server/ffmpeg_templates/renderer.py`：风景统一实际有限色彩范围；同一素材同一长度只处理一次，末尾不足整段的部分单独处理；重复排列改为复制已处理视频流，省去上下整轨二次编码。
- MP4画面与容器时间刻度设为30000，使30fps的非整秒片段保持精确帧长。真实长配方初次验收拦截了默认毫秒刻度累计误差，修正后重新完整验证，前次结果保留在`full-recipe/`。
- 拼接后立即检查尺寸、30fps、精确5400帧并完整解码。少帧、解码错误不能进入特效缓存制作。
- `server/ffmpeg_process.py`及`server/ffmpeg_finals/pipeline.py`：非阻塞读取FFmpeg进度；连续120秒无新增帧时停止自己创建的子进程并保留日志。零帧卡住、相同帧心跳也受保护。异常或调用方取消时回收子进程，不处理应用主进程或其他FFmpeg。
- 原随机配方、蒙版、羽化、贴纸布局动画、特效切换、边条及编码质量设定保留。新模板的风景解码图像不会再经历拼接时的二次有损编码。
