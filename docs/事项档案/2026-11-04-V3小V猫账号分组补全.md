# V3从小V猫获取账号：分组名称补全

日期：2026-11-04

## 目标与已确认原因

修复资料中心 → 账号管理 → 获取账号中已有“小V分组”字段获取不完整的问题，不新增字段。真实只读查询确认小V猫有31个视频号账号：默认分组23个、兔子4个、咩咩4个。MCP账号列表将23个默认分组的groupName返回为空，原链路直接透传，界面因而显示“—”。原始分组编号均为0；荷花、垃圾场为0账号分组，不对应账号行。

## 实际改动

- `server/publishing/vcat.py`：账号读取增加按需补齐分组名的选项，只在账号导入预览启用；空名称时仅返回账号平台、ID、分组编号，编号0补为默认分组，其他编号按只读分组列表映射。未知或冲突归属报错，避免误分组。分组列表加入只读许可，不开放分组修改。
- `server/account_import.py`：现有账号预览启用分组补全，沿用现有展示和搜索字段；不改账号新增规则或数据库结构。
- `server/tests/test_vcat_account_groups.py`：12项定向检查覆盖默认/自定义分组、分页、同ID不同平台、未知/冲突/不完整来源和只读权限。
- `server/tests/test_account_import.py`：新增预览保留已补齐名称且不写账号的检查；更新隔离模拟客户端接口。
- `tools/account_import_fixture.py`：同步隔离页面验收模拟客户端接口。
- 功能档案、项目控制台及本事项记录按本次结果更新。

## 后续：增加分组筛选（2026-11-04）

用户要求在同一获取账号窗口增加小V分组筛选。已在搜索框右侧、匹配筛选之前增加下拉框，默认“全部小V分组”；选项来自本次完整账号预览，按实际名称去重排序，含默认及自定义分组，不依赖当前分页或其他筛选结果。没有账号的分组不出现。

分组采用名称精确匹配，与关键词、匹配状态、登录状态同时生效；切换回第一页，沿用现有跨页选择语义。全选只作用于当前组合筛选后的待新增账号，切换分组保留已勾选账号及昵称/剧场编辑。重新获取后保留仍存在的分组；原分组已消失时回到全部分组。

实际代码仅修改 `src/components/assets/modals/AccountFetchModal.tsx`，没有修改后端、账号新增接口或数据库。功能规则和控制台同步更新。
