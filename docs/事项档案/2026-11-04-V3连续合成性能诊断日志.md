# V3 连续合成性能诊断日志

日期：2026-11-04。状态：源码完成，定向自动检查及隔离真实媒体检查通过。未重启正式软件、未修改真实业务数据或媒体、未打包、未更新安装版；其他会话继续开发，最后统一打包及版本收口。

## 目标与范围

针对用户反馈的“连续合成久了越来越慢、进展难以判断”，本次先补齐可定位原因的证据。原有日志虽有 FFmpeg 命令、阶段结束耗时和帧进度，但缺少任务切换、保存文件、数据库等待、运行中资源趋势和无输出时的记录。

本次不改画面效果、编码参数、任务顺序、暂停方式、成品重新生成规则、历史文件清理策略或界面进度算法。数据库结构不变，不增加第三方依赖。未确认本次变慢的唯一根因，不把最小进程检查或短视频检查当成长时间批量验收。

## 已接入的证据

- 每次尝试记录任务/素材/模板编号、素材指纹、输出路径、视频帧数和时长、插片概况、进程会话及连续序号、软件版本与实际运行模块指纹。
- 领取任务耗时、候选任务数/配方字符数、距上一条结束的间隔、自动排队耗时；批次准备另有开始/结束边界，包含模板配方检查、素材探测、素材散列计算。间隔包含正常空闲、暂停或排队准备，不自动当成故障。
- 分开记录素材校验、编码能力检查、素材信息/插片校验、模板检查、每个 FFmpeg 合成分段、拼接、完整解码、结果散列、复制、复制件散列、改名、任务完成写入和业务状态同步。
- FFmpeg 记录子进程 PID、实际帧、fps、speed、输出媒体时间、输出大小、补帧/丢帧、距上次新增帧的时长、退出码、异常及 traceback。子进程不输出进度时仍更新内部心跳；资源采样独立运行，无首帧停滞也留证。
- 每5秒在后台采样主程序/当前FFmpeg的内存、CPU累计时间与区间用量、句柄、进程逻辑读写；系统可用内存/CPU、本地物理磁盘吞吐、队列与传输延迟、相关本地盘剩余容量。NVIDIA采样每15秒更新，含型号、驱动、显存、温度、频率、功耗、利用率及驱动支持时的时钟限制掩码。记录掩码不等于已判定热降频。
- 画面CPU/GPU路径、编码器、源视频原始格式/帧率、硬件失败后的CPU回退；不再只能从“NVENC编码正常”推测整条处理使用GPU。
- 进度数据库写入的次数、累计/最大耗时，超过1秒记录单次慢写。生产摘要/任务快照记录慢读取（至少1秒）及每分钟一次正常基线，避免每3秒重复写完整快照。
- 指标不可用、计数器预热、驱动工具缺失、采样失败、日志写入失败明确记录，不用0代替未知。日志故障不改变合成业务的成功/失败结果。

## 文件和生命周期

以当前配置的数据盘为准，默认位置：

- `D:\短剧推广运营系统\系统数据\fg\任务编号前12位\a尝试次数\diagnostics.jsonl`：阶段事件、回退、错误、资源采样时间线。
- 同目录 `performance-summary.json`：定期原子更新的摘要，成功/失败时收口。程序被强制结束时可能保持 running，需结合最后更新时间及事件判断，不自动声称仍在处理。
- `fg\diagnostics\composition-history.jsonl`：已收口尝试的跨任务摘要。
- `fg\diagnostics\scheduler-events.jsonl`：排队前准备的开始/结束事件。
- `fg\diagnostics\runtime-observations.jsonl`：生产摘要与任务中心读取耗时。
- 原有 `check.json`、`progress.jsonl`、命令和FFmpeg日志保留。

新增JSONL达到8MiB轮转，保留当前及最多3个后缀备份，只操作本功能同名诊断日志，不删除视频、旧任务目录或其他历史证据。单任务日志沿用原任务目录的既有生命周期，跨任务摘要保留于独立diagnostics目录。

采样在后台进行，正常间隔5秒；NVIDIA查询超时受限并显式记录失败。共享盘不主动反复查询容量以免断线阻塞，本地物理磁盘计数器不代表远端存储服务器状态。CPU进程百分比按“单逻辑核心为100%”记录，系统CPU按整机百分比记录；进程逻辑I/O不等于物理盘吞吐；整机GPU数据包含其他软件。

- 输出中文报告与只含诊断文件的ZIP，不包含MP4、素材、数据库或任务plan.json；包内列出文件清单和读取失败信息。

- 旧版运行没有这些指标时无法补回。源码运行需在下一次正常启动加载；现有安装包不自动包含本次改动。
