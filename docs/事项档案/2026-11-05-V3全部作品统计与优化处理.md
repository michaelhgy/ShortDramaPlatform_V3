# V3 全部作品统计与优化处理

日期：2026-11-05。状态：源码、定向自动检查及隔离页面完成；正式桌面、真实动作和用户验收待做。未打包、未提交或推送，未变更产品版本。

## 用户目标与界面

驾驶舱原全局搜索框替换为“全部作品／仅看软件”，默认全部。发布数量、优化数量/比例及作品范围跟随切换；账号区间播放/收益保持账号日口径。账号优化页标题栏日期左侧放“优化设置”，设置处理方式、独立处理范围、播放保护和置顶保护，默认自动处理关闭。

## 实际实现

- 新增 `server/work_history.py` 保存官方发布历史、全部优化通知、秒级精确关联、独立处理策略与防重处理日志。采集和增量迁移写入，看板GET只读。
- 改造新旧优化采集入口：先保留全部通知，再查作品与官方详情；没有软件发布记录也收录。历史待查通知退出近期名单后继续补查。
- 匹配不使用相似ID。必须同账号、通知/作品/官方详情时间一致、完整作品采集覆盖发布时间且唯一候选。同秒冲突、缺字段或歧义保持待查；已验证关联在作品消失后继续保留。
- 软件发布历史保留原结构与发布确认/生产清理门禁。账号排行及优化分母使用所选发布历史；待查记录影响对应账号和日期区间的比例完整性。
- MCP增加受限优化动作能力，普通只读连接仍不能删除/隐藏，不修改小V猫原生自动设置。只对本次成功主动检测仍返回的已关联异常发送动作；每条动作前在线重读其发布日期作品，检查播放、身份和置顶保护。
- 门槛相等或超过均保留；缺失/过期播放、歧义、未知置顶状态等跳过。设置每条执行前再读，任务可在请求之间停止。动作意图先落盘，结果不明不自动重发，接口返回不当作平台最终状态。
- 数据库由12增量升13，保留12升级入口，不清理业务记录。原缓存回填历史，旧关联不能伪造为官方详情时间证据。本轮没有启动或迁移正式库。

## 未验证事项与业务限制

没有重启正式窗口、调用真实删除/隐藏、启用真实自动处理或发布安装包。实际使用需要程序加载新代码后，采集账号作品与优化通知，确认看板范围与实际账号一致；真实动作需在用户选定方式、范围、门槛并启用后另行验收。

单条MCP删除/隐藏接口不提供原子播放门槛。实现已在每条提交前重新查询和保护，但查询与提交之间存在时间差。接口调用返回仍需平台最终状态核实；当前日志保留待核实状态，不自动重试或宣称已完成平台处理。


## 追加：发布后时限与完整处理记录分页（2026-11-05）

用户要求增加发布后一定小时内才处理，以及确认处理记录的显示、条数、翻页与长弹窗可用性。

实现：增加 `post_publish_hours`，默认10小时，正数与小数小时均可。按执行时作品距实际发布的时长判断，刚满时限允许、超过时限跳过，缺失/未来时间也跳过；在线查询前后再次检查，不因查询延时处理过期作品。只限制动作，不删历史或通知。保留旧开关及其他策略。本次字段落在已有设置JSON，无新增表、无再次升级schema、未触碰正式库。

弹窗分处理设置/处理记录页签，最大90dvh，固定标题与底部保存/分页按钮，中间独立滚动。记录每页10条、显示总数/页数及首页/前后页/末页，使用新增只读记录接口读取全部历史；翻页保持同一批记录，新记录点击刷新后纳入。每条显示账号、标题/作品ID、发布时间、处理时间、操作、处理前播放、可展开优化原因和结果待核实状态。记录保护跳过的区别明确：没有发送处理请求的作品不产生处理请求记录。

验证：104项相关后端检查通过，含10小时边界、小数时限、查询跨界、旧设置兼容、123条完整分页、同秒排序、新增记录时翻页不偏移、空页、错误参数及真实HTTP处理函数路由。类型检查及驾驶舱隔离构建通过，浏览器模拟API验证保存10/8.5小时、非法0、123条13页/末页3条、超过100条可查、刷新/失败重试/空记录，以及1024×768和1280×600下固定页脚、内部滚动、长原因展开。未执行真实外部动作、未重启正式窗口、未打包。
