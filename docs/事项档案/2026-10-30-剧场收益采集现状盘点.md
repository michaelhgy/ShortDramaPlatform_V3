## 二、源码中已经存在的四个采集器

### 1. 青柠剧场：按天 HTML 表格，支持视频明细

查询地址：

```text
https://vd.xingvan.com/duangg.html
```

请求方式是 `POST application/x-www-form-urlencoded`，参数为：

| 参数 | 含义 |
|---|---|
| `startgdate` | 开始日期 |
| `endgdate` | 结束日期；当前采集器按单日传入 |
| `spfindid` | 账号 ID/视频号 ID |
| `spvideoid` | 视频筛选，当前为空 |
| `p` | 页码 |

当前解析的返回内容不是 JSON，而是 HTML：表格行第 1 列是排名，第 3 列是平台视频 ID，第 4 列是剧名，第 5 列是视频播放量，第 6 列是剧集播放量，第 7 列是收益金额；页面文字 `共 N 条记录` 是记录数，分页链接参数 `p` 是页数，含“总计”的行最后一列是页面总金额，“暂时还没有数据”表示明确无数据。

写入结果：账号日收益 + 视频收益明细。当前字段为：

```text
rank
source_video_id
source_drama_name
video_views
drama_views
gross_revenue
```

采集器会校验页面声明记录数、抓到的视频 ID 数量和页面总计；对不上时整次查询失败，不写明细。

### 2. 顶好剧场：JSON 接口，按天查询账号金额

接口地址：

```text
https://zyu.wozhangwan.com/api/api/order/getVideoAdIncome
```

请求方式是 `POST application/json`，当前发送：

```json
{
  "income_date_start": "YYYY-MM-DD",
  "income_date_end": "YYYY-MM-DD 23:59:59",
  "advertiser_id": "账号ID",
  "channel_name": "",
  "drama_name": ""
}
```

当前实际使用的返回字段只有 `status_code`、`msg` 和 `data.amount`。代码没有保存 `data` 下的其他字段，因此目前不能确认接口是否还返回剧名、视频或其他统计字段。返回 `0.00` 时当前按“不确定”处理，不当作真实零收益。

### 3. 触摸剧场：公开查询页 + 动态 sqcode + 结果 HTML，返回累计金额

入口页面：

```text
https://c3andggd.yichafen.com/qz/167SsX4Q2t
```

流程是 GET 入口页面、提取动态 `sqcode`、POST 到 `/public/verifycondition/sqcode/{sqcode}/from_device/mobile.html`，请求字段为 `s_shipinhaoid=账号ID`，读取 JSON 的 `status`、`errNo`、`info`，成功后 GET `/public/queryresult/from_device/mobile.html`，再从结果 HTML 中匹配“广告收益”后的金额。

当前采集器只保存一个金额，没有日期、剧名、视频 ID 或明细。业务口径是账号累计金额，旧采集记录标记为 `monthly_cumulative`。

### 4. 花生剧场：飞书多维表单接口，返回账号累计金额

入口页面：

```text
https://scnrzu35lckk.feishu.cn/share/base/query/shrcnCXYADPz9wc4apC1pZ6Fvvb
```

根据分享地址生成 API 根路径：

```text
https://scnrzu35lckk.feishu.cn/space/api/bitable/form/external/
```

流程是调用 `get_share` 校验分享令牌，再调用 `list_records`，用字段 ID `fld3P2QILX` 按账号 ID contains 筛选，从记录字段 `fld4Za6Nvm` 读取金额并累加。返回容器兼容 `data.recordMap`、`data.records`、`data.items`；金额字段兼容普通值、对象的 `value`、数组元素的 `text`/`value`。

当前只保存累计金额，不保存日期、剧名、视频明细或原始字段结构。

## 四、当前代码覆盖边界

现有 `collect_supported_theaters()` 的硬编码范围是：

```text
青柠剧场 → qingning
顶好剧场 → dinghao
触摸剧场 → touch
花生剧场 → huasheng
```

它只按这四个剧场的精确名称筛选账号。数据库中的添翼剧场和爱看剧场即使状态为“启用”，当前也不会进入采集单元估算和采集循环。

另外，前端当前的收益采集请求仍调用 `collectV2QingningRevenue()`，后端入口虽然接收剧场范围，但实际需要继续核对“全部/按剧场/按账号”是否真正走统一的四剧场采集器。

## 五、适配器扩展时需要保持的统一字段

每个剧场的原始字段名称可以不同，但进入新收益底座时统一为：

| 统一字段 | 含义 |
|---|---|
| `theater_id` | V3 剧场 |
| `adapter_key` | 具体适配器 |
| `account_id` | V3 账号 |
| `account_external_id` | 查询网站需要的账号 ID |
| `period_type` | `day`、`date_range`、`month_cumulative`、`unknown` |
| `period_start` / `period_end` | 能确认时填写 |
| `amount` | 金额 |
| `has_detail` | 是否有视频/剧目明细 |
| `data_state` | 成功、明确零、无数据、失败、不确定 |
| `raw_result_json` | 原始解析结果或脱敏字段 |
| `source_collected_at` | 实际查询时间 |

青柠进入明细表；顶好若确认只有 `data.amount`，进入账号周期金额表；触摸和花生进入月累计金额表。没有日期的返回结果不补造日期。
