# V3酷匠四类收益采集器

日期：2026-11-04。用户要求：适配酷匠查单，并明确四种类型分开做采集器。

## 实际结果与入口

新增四个软件内置采集器：酷匠-IAA、酷匠-自营、酷匠-绿泡泡、酷匠-端+漫剧，编号分别为 `kujiang_iaa`、`kujiang_self`、`kujiang_lpp`、`kujiang_native`。

- 资料中心 → 查单管理：四行独立显示，分别管理链接、启停、只读试查与历史修订。
- 资料中心 → 业务资料 → 剧场管理：名称匹配推荐后人工确认对应采集器。
- 账号管理：在所属剧场已关联的采集器中选择一项；账号列表可直接切换。
- 运营驾驶舱 → 数据采集 / 刷新：统一收益流程沿固定编号调用，不按剧场名称猜业务，也不要求平台登录。

## 来源与金额规则

入口 `http://api.data.djff.asia/query/find.html`，页面列出四种精确业务名。原查询接口为 `POST /data/external/find`，字段 `tn/vid/sd/ed/pageNum/pageSize`；查询跨度最多31天，本实现单次只查询一个日期。业务名固定跟随采集器编号。

核对账号、业务、日期、分页与汇总，所有页完整且金额一致才返回账号日合计。不保存视频明细，不重复累计顶部汇总。正常空数据不伪造0；网络/格式错误不推进正常空日边界。首次连续7天明确无收益停止，成功日期不重复查询。

页面警告部分单日金额可能包含区间收益。本实现沿来源记录日期入账并展示该提醒，不将其说成已还原真实逐日收益，不均摊到猜测日期。当前来源属于按记录日期查询，不用累计差额方式处理。

候选链接必须仍属于同一适配网站及页面类型。试查先检查候选页面对应的API，再查金额；成功令牌、修订及确认规则沿用现有机制。更换到其他网站或接口结构变化仍需适配，不自动转发ID到跳转地址。HTTP例外仅限此来源，其他既有来源约束保持。
