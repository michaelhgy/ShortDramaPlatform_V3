# V3收益延迟出数复查与累计入账

日期：2026-11-05。

## 目标与确认规则

用户指出青柠海南灯笼椒酱11月4日实际已有收益，但程序仍根据早先空结果显示完成并跳过。正常无数据只证明当时查询为空，不能代表最终没有收益。

按日来源保存成功后跳过；最近7天正常空结果仍待复查，默认最短间隔1小时，可由内置采集器定义分别调整。失败与待更新继续重试，不补0。连续7天空/零停止历史倒查的规则保留；历史补齐和近期出数状态分别判断。复查窗口过期不把空结果改成0，已有明确成功日期不反复查询。

月累计首次总额全部归实际查询日；后续只增加相同月份的差额，同日更新合并当天收益，漏日增量归恢复查询日，新月份独立基准。当前累计最短间隔后允许再次查询；历史月份成功可复用，正常无数据不能永久封存。金额下降仍拒绝入账并保留原基准。

## 实际修改

- `server/revenue_collection_state.py`：增加统一复查窗口和间隔判断；近期空记录到期不再作为执行缓存，保留成功结果及历史空结果。
- `server/revenue_queue.py`：账号状态、执行前跳过和执行后覆盖检查共用相同时间点。近期空结果显示暂无数据/待复查；间隔内可跳过请求，但账号仍待更新。任务结果携带待复查数量，前端既有样式显示来源待更新。
- `server/v2_revenue_service.py`：累计当日允许间隔后刷新；旧定时单日入口也补查近期已知未完成日期，任务预估与实际范围一致。累计任务金额修正为本次增量，日收益表仍写当天合计。累计首次归属原本正确，本轮保留并验证。
- 增加12项延迟出数/累计入账场景；更新旧测试中已失效的近期空记录永久完成及累计任务金额断言。前端生产代码、视觉样式不变，增加待复查状态的前端模型检查。
