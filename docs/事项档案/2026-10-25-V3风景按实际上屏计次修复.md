# V3 风景按实际播放计次修复

日期：2026-10-25。状态：源码及正式前端完成，自动检查、隔离浏览器及真实模板制作通过；等待用户使用验收。本次不重新打包，2026.10.25.1安装包尚未包含。

## 目标与问题

用户要求：只对实际播到的风景计次，没播到的不占次数，参数说明和文档一起更新，先改源码版。

原实现先抽取配置数量的风景候选，再分成上下两组，分别排到模板时长。最后一条按剩余帧数截断，因此部分候选可能从未出现在播放时间轴。但预留、重试、文件检查及成功记账使用完整候选集合，导致未播到的风景也占用额度，甚至用满后被自动删除。

## 当前有效规则

- 候选抽取数量、上下初始分组时长差、随机种子、保存配方、播放顺序、循环和最后一段截断均保持原规则；画面处理方式不变。
- 只取保存时间轴中帧数大于0的风景身份，按内容身份去重。一个素材在同一模板内循环多次或只播部分，均在模板成功后计1次。
- 创建批次仅为实际排入时间轴的风景预留，失败重试也只重新取得这些名额；未播到的候选不预留、不计次，不因本模板触发用满删除。
- 参数改称“上下合计风景候选条数”，说明数量是抽取候选数，实际出现数受素材时长与排布影响。设置20仍需创建时有20条可用候选，不保证20条全部出现。
- 文件依赖校验只检查实际播放素材。未播到候选被其他任务正常用满、删除，或文件变化，不影响当前模板；实际播放素材变化仍报错并保留配方。
- 成功结算再次从时间轴取身份，忽略旧任务多余预留；若实际播放素材缺少预留/已结算记录，报错并保留已发布结果，重试不覆盖既有预览、不重复记账。
- 失败、取消或中断释放预留，不记成功用量。用满清理沿用原保护、内容核对与占用检查。
- 源码启动初始化时，自动释放旧等待任务中未播到候选的多余预留，保留原配方。历史已完成用量不追溯改写；以前已删除的文件不会自动恢复。
- 真人图片计次、公共模板按剧集计次等其他规则保持原实现。

示例：模板60秒、候选20条，如果上下时间轴实际只排入6条，只有6条预留并各计1次，其余14条不占本模板次数。
