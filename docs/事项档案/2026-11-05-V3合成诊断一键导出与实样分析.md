## 用户入口与输出

全局任务中心 → 成片合成 → 标题右侧“导出合成诊断”（用户截图红框位置）。仅完整成片队列显示，监控小窗及模板/风景页签不显示。

点击后读取当前配置数据目录的 `系统数据/fg`，在当前工作区 `诊断输出/YYYYMMDD-HHMMSS-微秒/` 新建文件夹，生成 `合成诊断报告.md` 和 `合成诊断日志.zip`，然后尝试用 Windows 文件管理器打开。按本机当前 D: 配置，正常输出为 `D:\短剧推广运营系统\诊断输出\时间文件夹`。不写死源码目录或盘符。

按钮导出期间禁用重复提交，页面保留尝试数、文件数及可选择的完整保存路径。打开文件夹失败时导出仍算成功，显示手动打开提示。无新版日志也导出明确标注为空的报告及带清单的ZIP；部分记录读取失败会同时显示页面提醒、报告错误和ZIP清单。导出失败明确报错并保留已生成文件；可写时追加“导出失败.txt”，不误报为完整输出。

后端入口 `POST /api/v3/final-composition/diagnostics/export` 使用服务端配置路径，忽略客户端传入的目录。只读诊断数据，不初始化合成器、恢复任务、访问业务数据库、领取任务、暂停队列或持有合成锁。独立导出锁防止并发重复导出；每次独立目录保护历史证据。ZIP延续原白名单及单文件8MiB尾部限制，不包含视频、素材、计划或数据库。

运行中可导出，但报告和ZIP按顺序读取，属于当时已写出的记录，可能略有时间差；未结束记录不能判为失败。现有进度百分比算法及SAR兼容门槛本次未调整。

## 实样分析：20261105-180037

输入为用户给出的 `D:\ShortDramaPlatform_V3\诊断输出\20261105-180037`，内有41380字节报告及605808字节ZIP。读取到21条尝试，20条完成、1条仍在运行。

- 可比的同会话、模板、源规格、加速方式6条完成任务：前3条中位速度332.3帧/秒，后3条330.4帧/秒，变化-0.6%。该组未显示连续GPU合成逐步降速；不能把不同源规格、短视频和CPU路径混在一起判断。
- 视频15与20切为CPU画面合成，分别172.6与166.7帧/秒；仍可用NVENC编码，不能由编码器正常推出整条链路都在GPU。加速拒绝原因为 `source_format`。源码 `gpu_transfer.supports` 要求像素宽高比SAR为1:1或0:1；这两条分别为334:333与960:961，确实不满足该门槛。视频22在导出时仍运行，SAR缺失，也走CPU路径。
- 视频15后的视频16恢复330.4帧/秒，视频19达到346.8帧/秒，支持“部分素材切换路径明显降速”的解释，不支持“所有后续视频必然持续变慢”的结论。视频17、18、21等短片不能直接和长片平均速度比较。
- 后段进度写入调用耗时明显增加：视频19累计16.781秒/69次，20累计27.194秒/115次，21累计5.359秒/20次，22截至导出累计17.593秒/69次；早期多为0.06至1.3秒量级。已记录到实际写入调用耗时增加，但尚不能确认锁竞争来自哪个写入方，也不能将累计调用时长等同于额外总墙钟耗时（子进程编码可能同时进行）。

建议后续优化优先审查非常规/缺失SAR下能否保持画面一致地走GPU，以及降低/合并高频进度持久化并细分数据库锁等候与提交耗时。本事项完成诊断入口，不直接放宽兼容条件或修改合成效果。

## 同日范围修订：先设置条件，默认有限详细日志

用户确认不应每次收集几百个任务全部详细日志，要求点击后先弹窗设置。本修订替代最初的直接全量导出行为，右侧按钮位置保留。

默认“最近一轮运行”，按最近一条合成日志的会话识别本轮，不初始化当前合成器查询会话；弹窗读取候选摘要后固定所显示的会话，确认时不自动切换到其他会话。该轮摘要表及趋势保留，详细日志默认最近30条、可设1至200条，优先包含运行任务。默认附前段同条件正常样本：同会话/模板/输入规格/加速方式，每组最多3条，合计最多额外12条，不扩到其他条件。重试单独一条。

提供“指定任务”（名称搜索、20条一页、跨页勾选，选1至200条）及“全部历史”（主动选择并确认，提示可能较大）。指定模式摘要和详情仅取选定/对照；最近模式保留本轮全摘要但仅附所选详情。关闭、取消或读取失败不发导出请求；导出中禁用重复提交及关闭，Esc不关闭底层任务中心。导出失败保留原条件。空范围仍可生成明确为空的报告，错误条件或失效指定记录拒绝导出，不创建输出目录或悄悄扩大为全量。

新增 `server/ffmpeg_finals/diagnostic_selection.py`：候选、条件校验、记录键、会话/详情/对照筛选及公共事件过滤；不读业务库。新增只读 `GET /api/v3/final-composition/diagnostics/catalog`；既有POST透传条件，未传条件也使用默认有限范围。前端新增 `CompositionDiagnosticsModal.tsx`，接口类型与队列调用同步更新。原离线CLI不传范围时保留历史显式全量工具行为，GUI不会执行tools脚本。

有限导出从所选尝试目录读取详细日志，不遍历读取其他任务详细文件。ZIP公共摘要重建为本范围记录，公共运行/排队/读取事件按相关会话或时间范围保留，并保留匹配操作的开始/结束对。`export-selection.json`和ZIP清单记录范围/记录键/数量/缺失详细记录，报告说明哪些只保留摘要；全历史保留原始公共日志，不重复写入同名ZIP条目。归属已变化的旧尝试仅附摘要并提示，不能混入新会话同路径详情。损坏摘要无法识别任务时，默认空记录范围最多附3份原文并明确提示；不任意夹带未选任务详情。

每个原始日志仍取最近8MiB，公共筛选后生成的摘要/清单不按原文件尾部截断。默认通过限制详细记录数量减小信息量，不承诺ZIP固定总大小；主动全历史可能较大。本次不删除源日志、不改轮转或业务数据，不修改合成算法与性能路径。
