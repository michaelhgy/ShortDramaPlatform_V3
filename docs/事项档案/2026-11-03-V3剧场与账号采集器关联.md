# V3 剧场与账号采集器关联

日期：2026-11-03。状态：源码、隔离检查与浏览器组件联调完成；正式桌面与真实剧场采集待验收。

## 用户确认的目标

采集器属于软件内置能力，用户自己新建剧场。进入剧场管理时按名称/登记别名推荐，人工复核修改并保存确认。账号在所属剧场范围内选择准确的采集器；账号列表支持像状态一样直接修改。账号界面移除报白时间、注册时间。

## 实际实现

- 新增软件目录 `server/revenue_collectors.py`，原四个实现仍为青柠 `qingning`、顶好 `dinghao`、触摸 `touch`、花生 `huasheng`。实现可登记自己的显示名与别名，允许同一剧场匹配多个来源。没有新增子诗采集实现，不展示虚构选项。
- `GET /api/v2/revenue/collectors` 增加 `definitions`，即使没有用户剧场也能取得软件目录；原库存字段保留。
- 数据库只新增三张关联/确认表：`v3_theater_revenue_collectors`、`v3_account_revenue_collectors`、`v3_theater_revenue_collector_settings`。不存实现代码、URL或能力定义，不按剧场名称自动写入或迁移旧账号。不删除已有业务数据，不修改旧日期列。
- 剧场管理新增收益采集器列；按名称/别名显示待复核状态，编辑里多选。自动建议仅在尚未人工确认时生效，勾选修改后保留用户选择，保存后正式关联；人工确认空集合不会下次又被自动勾回。
- 账号编辑使用剧场固定ID筛选，去掉旧的假默认ID；只列所属剧场已关联的采集器。可暂留空，不自动替用户选择第一项。编辑已有停用剧场账号保留当前归属选项。
- 账号列表新增收益采集器下拉，使用只提交 `revenue_collector_id` 的局部更新，服务端复核归属。剧场改名保留固定编号；切换剧场清空旧选择；移除剧场关联会清空受影响账号选择，已有收益与尝试记录保留。
- 正式采集、预计任务量和青柠兼容入口按账号选定编号分派；未配置账号返回待配置失败、金额为空，不请求外部平台、不写零。来源读取列表不再由四个固定剧场名称限制。
- 两个日期从账号列表、编辑、批量样例及预览移除；当前界面不再提交。批量导入改六列：昵称、账号ID、剧场、子剧场、状态、备注；带旧表头的八列继续识别，忽略日期并保留备注，无表头旧格式按日期列形态兼容。批量账号导入不自动选采集器。
- 既有首次倒查七天、续采、累计增量归采集日、青柠默认不存明细规则沿用。
