# 按青柠历史样本调整V3模拟数据

## 目标与授权

用户同意依据已讨论的最早10个青柠剧场账号历史记录修改现有模拟数据，只参考视频播放量和收益，不使用剧集播放量。当前业务数据库内直接调整开发数据，用户自行验收，不操作桌面、不触发外部采集或发布。

## 样本与规则

- 只读参考造数前备份 `D:\短剧推广运营系统\系统数据\database\v2_system.db.before-recent-operations-20261101-110759-978215`，筛选2026年10月前录入的青柠账号，使用5923个视频编号、22830条视频日明细。
- 收益与视频播放量作为同一条观察成组抽样；每条模拟视频使用一个历史视频的连续观察序列，保留观察日之间的间隔，采用同一个适度幅度系数缩放播放和收益。多数无收益、少数高峰、播放与收益不严格成比例的组合来自样本。
- 没有观察的间隔补为模拟零值，观察序列结束后最多补7天少量零星播放，不伪称真实记录。模拟发布时间不是历史实际发布时间，来源元信息保留参考账号、视频编号、首次观察日和缩放系数。
- 保留现有2400条作品和账号/封面关联，按账号分配不同的活跃日期、疏密和空档；停用账号安排较早的模拟停更期。保留39个真实账号的主档状态与所属剧场。
- 互动、粉丝、完播率缺少这些账号的可靠样本，明确标为未经校准的合成指标；原有347条开发风险通知只同步日期，数量和原因保持，不根据低播放推定受罚。原始平台处罚不变。
- 忽略剧集播放量，开发明细该兼容字段置0并注明未使用。触摸继续只生成月累计收益；其他剧场的开发数据沿用此近似样本，不代表真实接入或精确核账。
- 开发场景中，当月与上月暂未结算以支持月初查看近7/14/30天；更早月设已结算，不改变真实采集的结算状态。

## 实现与保护

新增显式CLI `tools/reprofile_operations_samples.py`，先读样本并准备结果，写库前备份，事务内只替换开发来源的8张统计表、开发收益采集记录及其日汇总。账号、剧场、剧集、头像和封面路径以全行摘要保护；非开发统计、原始采集记录和视频收益明细同样校验未变。发现变化、新外键错误或作品/账号分日播放不能对上时回滚。

新增 `server/tests/test_operations_reprofile.py`，临时库检查配对/日历间隔、忽略剧集播放、原始记录与主档保护、播放与收益汇总、重复执行不膨胀及异常回滚。
