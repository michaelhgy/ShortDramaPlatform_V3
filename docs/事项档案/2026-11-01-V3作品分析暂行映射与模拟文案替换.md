# V3作品分析暂行映射与模拟文案替换

## 最终用户口径

用户提供5组暂行作品分析原文及内部标签，明确当前不是完整分类、原文将来还会按实际获取结果修订，本轮不处理获取方式。用户要求沿用截图配色，并最终明确：同质化优化率指“原创优化”，不是“多次发布”，两种优化性质不同，不合并计数。

| 内部标签 | 颜色 | 计入同质化优化率 |
| --- | --- | --- |
| 多次发布 | 蓝 #3B82F6 | 否 |
| 引导优化 | 橙 #F59E0B | 否 |
| 羊头链接 | 红 #DC2626 | 否 |
| 未挂链接 | 粉 #EC4899 | 否 |
| 原创优化 | 紫 #8B5CF6 | 是 |
| 待归类 | 灰 #64748B | 否 |

五条完整正文保存在`src/data/optimizationNoticeRules.json`，版本`user-provisional-2026-11-01`。表中的“作品分析：”作为字段标题，模拟记录保存正文；已有原文是否带前缀不影响匹配，但已有原文字符串不被重写。

## 实现

- `src/types/optimizationNotices.ts`集中提供规则、颜色、计数模板及匹配函数；`shortDramaOps.ts`兼容导出旧接口名称。旧名`OFFICIAL_OPTIMIZATION_DEFINITIONS`仅为内部兼容名，不再表示官方完整分类。
- 仅忽略“作品分析:”/“作品分析：”标题及排版空白做完整正文匹配，不用宽泛关键词猜类别，不信任旧`simplifiedReason`代替原文；未匹配/缺失原文显示待归类，仍计入整体优化量。匹配派生标签，原始`notice`字段独立保留。
- 总览图表、账号优化分类/原因、作品标签、两类详情及导出预览共用新标签与配色。分类区标为“作品分析标签”“暂行规则”，展示5条对应正文及待归类，不继续声称7类真实/完整官方标准。
- 删除旧模拟推断出的严重/中度/轻微和固定限流处置。暂行规则不附加级别或影响结果；只有原始记录确有相应字段时才展示，缺失时不造“降权/仅主页可见”等结论。无优化记录也不宣称音画合规、留存达标或正常推流。
- 同质化率=原创优化作品数÷同账号/当前范围全部发片数。多次发布独立统计，未知类别不计入分子。顶部说明注明原创优化数量；分类筛选不改变分母，零发片仍0%。现有健康20%/50%边界、流量等级、收益等级和分页规则保持。
- 更新开发数据生成器，使后续模拟通知直接使用同一JSON配置，避免重建后重新出现旧七类和“开发场景”占位文案。旧未挂载原型只作必要类型兼容调整，不重新挂回首页。

`tools/replace_optimization_demo_notices.py`默认只读预览；仅选择有明确模拟来源及标记的旧占位通知。非占位的人工改写文本、非模拟来源、已完成本版本的记录均跳过。执行需指定新备份路径和预期数量；备份一致性校验通过后，事务中复核计划未变化，再更新。
