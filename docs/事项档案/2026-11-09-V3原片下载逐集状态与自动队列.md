# V3 原片下载逐集状态与自动队列

日期：2026-11-09。范围：完善现有 V3 的“资料中心 → 短剧原片下载”；不制作独立 EXE，不修改打包或发布编号。本事项承接原片下载流程审查及实时动作日志事项。

## 用户操作与完成规则

1. 用户在主微信第一条置顶聊天发送 `#剧名`，紧接对应分享卡片。软件处理最后一组完整任务；最新组不完整时停止，不退回处理前一组。剧目须在 V3 资料中唯一关联剧场。
2. 软件先判断当前界面是否属于已确认的主微信聊天；可沿用时直接读取，否则重启主微信用户0，重新进入第一条置顶。采集阶段沿用读取到的卡片位置，不再自行重启另读任务。
3. 点击卡片、免费剧集、选集并核对“第n集”，按分享图标采集。每条链接对应明确集数。复制失败、不同集复制到相同链接、集数未确认时停止并保留已采成果。
4. 电脑后台按尚未校验的集数解析和下载。解析返回集数不符不保存为目标集；名称没有集数时，必须有手机已核对集数的依据。只对错集或未确认链接补采，连续段内滑动，跳段才重新选集，例如2、3、7、8、9选2和7。
5. 通过轨道、时长、文件身份与完整集号集合检查后，才允许清理当前卡片和剧名。总集数未知或手机/资料库总数冲突不宣告整剧完成。清理失败停止队列，成功后重新读下一部。少量验证模式保留消息，不执行清理或下一部。

## V3 保存位置与续跑

- 下载目录取 V3 设置，默认 `Z:\04短剧原片`，结构为“根目录 / 剧场 / 剧名 / 分集.mp4”；根目录不可访问时明确停止。共享盘断开不切换到其他目录。
- V3 系统数据下 `drama-download/tasks/` 按下载根、剧场和剧名保存各集链接、解析名称、确认依据、视频路径、校验指纹与失败原因。现有 `采集表.txt`、`分享链接.json` 保留为导出/兼容文件。
- 已有有效凭据且文件未变化的视频可复用；链接变化使旧凭据失效。无法确认来源的同名视频保留并报冲突，不因文件存在就当作完成。
- 新视频先写 `.mp4.part`，传输和视频检查通过后才落正式文件。仅本软件明确归属且证实损坏的下载允许修复，替换前另存原字节备份。已有成功视频不重新覆盖。
- 原片列表优先扫描当前设置目录；每部完成或任务停止后刷新。临时下载和修复备份不计入分集数。

## 进展与停止

四阶段维持读取、采集、后台解析下载、视频校验。实际执行阶段自动展开，历史可手动查看；补采回到第二阶段时按真实状态显示，不把后面的阶段提前标成完成。动作注明查找/选集/复制第几集、解析返回名称、实际下载字节、正在校验的集数，等待期间显示已等待秒数。逐集结果即时更新并保存，异常线程统一进入失败状态。停止请求终止当前脚本并保留成果。

清理必须核对聊天和本次任务身份。删除卡片后还须重新看到对应剧名、确认卡片区域消失，再删剧名；不能用一次OCR失败冒充卡片已删除。删剧名后连续确认回到本次聊天且标签减少。清理中断保留恢复标记，不能据此删除其他任务。

## 尚未验证与生效边界

当前桌面进程是本轮修改前启动的 V3 实例；本轮没有重启桌面，隔离构建没有替换运行用dist。需正常关闭后由根目录 `启动V3开发版.bat` 重新加载，再做手机与后台接口联合验收。没有另开端口、修改正式业务库、操作真实微信消息、提交或推送。

以下保留为实际界面验收项：分页是否读全总集数、11集文字与画面重叠时能否确认集号、平台广告期间的推进、真实聊天中卡片与标签清理、共享盘长时间写入、真实解析凭据是否有效以及完整整剧续跑。视频检查目前确认容器、轨道与正时长，尚非完整解码或实际播放验收。无法确认来源的旧视频需保留，不能宣称任意旧目录均可无条件续跑。

正式代码位于 V3 的 `server/drama_download_reader.py`、`server/drama_download_state.py`、`server/v2_file_service.py`、`tools/short_drama_downloader_lab/`及现有资料中心组件。自动检查工具不属于用户操作入口。
