# UI 迁移规则

## UI 职责

AI Studio 的页面视觉和交互方案可以作为 V2 的 UI 基础，但不能把示例数据、虚构业务状态或未确认按钮动作一并迁入真实运行模式。

## 组件规则

页面与组件禁止：

- 直接导入 `*MockData.ts`、`mockData.ts` 或任何模拟数据常量。
- 在组件内创建账号、收益、任务、剧集、文件路径或剪映状态等业务数据。
- 绕过 service（服务层）直接调用 API。
- 将 V1 的失败、无数据、待核对或未知状态显示为零、成功或已完成。

页面只能负责：

- 用户操作与页面本地 UI 状态。
- 调用对应模块 service。
- 根据 service 返回的 V2 展示模型渲染加载、空、错误和成功状态。

## 未接入状态

V1 模式下未完成迁移的页面统一使用“暂无真实数据”状态。不得保留 AI Studio 示例卡片、排行榜、时间线、任务或收益数字。

Mock 模式仅供显式开发调试。Mock 数据可保留在 `src/*MockData.ts`，并只能经 `src/services/mockServices.ts` 或模块 service 暴露。

## 桌面适配

- V2 当前导航为顶部导航；不得在未获设计授权时改成左侧导航。
- Windows 桌面测试使用 `tools/run_v2_desktop_test.py`，窗口基线为 `1440x920`，最小为 `1100x720`。
- 涉及布局的改动需检查 100%、125%、150% Windows 显示缩放，以及主页面、弹窗和抽屉的独立滚动行为。

## 新界面的实现方式（2026-09-17 用户口述）

**新增界面/按钮时，必须用项目现有的 UI 元素与风格拼装，不得自创一套新的 UI 体系。**

具体要求：

- 复用现有组件与样式（现有弹窗、抽屉、表单控件、按钮、卡片、Toast 等），**不引入新的组件库、新的设计语言或另起一套配色与间距规则**。
- 新增入口放在**已有页面 / 已有操作流**里（如生产中心、设置页），不新建独立页面体系或新导航。
- 与现有同类界面保持一致的交互习惯（确认/取消、加载态、空态、错误提示）。
- 视觉参照现成的同类界面：`src/components/assets/modals/`（各类弹窗）、`src/components/settings/SettingsView.tsx`（设置表单）。

**原因**：用户不希望在已有软件之外出现"看起来像另一个软件"的部分；一致性优先于新造样式。
