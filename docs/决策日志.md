## 2026-09-19（任务中心「账号×剧集优先级卡」：进度口径改造 + 手动调整排序）

### 用户提的（原话）

> "软件的全局任务中心，有个任务优先级。这里需要调整，进度的显示和逻辑，改成跟生产中心的一样。"

### 只读核查发现（等级 1 读代码 / 等级 3 读真实生产库，**未改任何代码**）

1. **同一件事存在三套排序**：优先级看板卡（按发布时间，符合用户规则）、任务中心卡片列表（**状态分层**优先）、
   生产中心左侧列表（未完成优先 + 发布时间）。实测差异：状态分层让计划 **20:00** 的《稻花香里庆余年》
   排到了计划 **08:00** 的《神农宝库》前面 —— 这就是用户"感觉不符合规则"的来源。
2. **进度口径两处不一致**：生产中心分母 = 素材实扫条数；任务中心分母 = 成片任务记录数 + 有模板算 1，
   分子 = 草稿就绪。实例：《神农宝库》显示「11/11 已就绪」，而其 10 条视频**实际已全部导出完成**。
3. **两处任务数量不一致**：生产中心 9 张卡、任务中心 7 张（两条"有素材但未开工"的任务被过滤掉）。
4. **存量缺陷**：任务中心「今日已完成 N 个」实为全部历史完成数（`TaskCenterModal.tsx:109`），无日期过滤。

### 用户拍板（2026-09-19）

|---|---|---|
| 1 | 优先级卡进度口径 | **完全照生产中心**：视频 / 草稿 / 素材 三个数字 + 三色轨道；异常单独显示 |
| 2 | 未扫描新素材 | **不计入分母**，另标「新素材 +N」（与生产中心一致） |
| 3 | 手动排序效力 | **= 最高调度优先**，三个执行器真的先做它 |

### ⚠️ 一次判断失误（必须记住）

上一轮把 P2 说成"**这是'刷新有问题'的结构性根源**"，并给 `resource_changed` 补了对象编号。
用户追问"这个记录是不是拿来匹配爆款素材的、还有没有别的用"之后，**顺着调用链一查**才发现：

> **整条变更事件通知链已经死了。**
> 前端**零调用** `GET /api/v2/change-events`（全前端搜 `change-events`/`latest_id`/`after_id` 无结果，
> `dataChangeFeed.ts` 文件本身已在"刷新大修"里删除）。31 个触发器仍在每次写入时插事件，
> **通知的是一个不存在的前端**。唯一活着的读者是 `runtime_guard._recent_change()`——
> 只读最后一行，用于"写锁卡住时指认是谁在写"。

**失误性质**：**改一个数据通道之前没有先查调用链**（"谁在读它"）。
P2 改的虽对，**却不产生用户可感知的收益，原文定性是夸大的**。

**与 §12E 的教训同源**：在没查清上下游之前就动手，等于赌。
**今后规矩**：动任何"事件 / 消息 / 通知 / 触发器"之前，**先搜谁在读它**，搜不到就别改。

### 用户决定（2026-09-19）

**保留这条链**。理由不是性能（开销微秒级、不可感知），
而是 **`runtime_guard` 的诊断能力有价值**——删掉就丢失"写锁卡住时指认是谁在写"的能力。
**前端"定向刷新"不做了**：它要服务的通路已死，做了没有收益。

### 顺带回答了用户一个长期疑问

**"变更事件是不是用来匹配爆款素材的？"** —— **不是。**
爆款匹配走**磁盘**：素材在 `爆款/账号日/` 目录，模板生成时按种子选剧、抽 10 张剧照

而且还是系统性的归纳，好比说随便提一个功能，马上能找到这个功能的详细说明，不至于每次都要翻聊天记录或者我给你完整口述。"**

→ **这与 Engramory 不是同一个需求**：Engramory 是"给 AI 的记忆"（一条一个事实、只写结论、索引硬上限 200 行/25KB、故意不进 git）；
用户要的是"给人读的**功能档案**"（一个功能一份详细说明、成体系、要能查、要进 git 有历史）。
Engramory 自己的说明书把后者叫 knowledge base 并声明**故意不提供工具**（"就是一个地方 + 一套标准"）。

### 三、建立"功能档案"体系（用户 2026-09-19 拍板："那先按照这个来"）

- **判断轴**：按"**软件的部件**"分，不按"哪次干的活"分（部件有限且稳定，事情无限）。
- **18 份 / 4 组**：`01-界面`（工作台、生产中心、任务中心、数据分析、资料中心、参数中心、设置）；
  `02-执行器`（模板生成器、成片生成器、视频导出器）；`03-后台机制`（清理系统、收益采集、资源扫描、写锁与护栏）；
  `04-跨模块规则`（数据与刷新、文件与资源生命周期、三层状态、命名与术语）。
- **归档判断规则（三步）**：① 时间性的（进度/排查/决定）→ 决策日志或待做清单，**不进档案**；
  ② 有"自己的入口"（界面点得进去 / 后台自己跑）→ 才单独立档，否则**追加进所属档案对应段落**；
  ③ 多部件共用 → 只在 `04-跨模块规则` 写全，别处只放链接。
- **四条护栏**：默认追加不默认新建；总数上限 ~25 份；一件事只写一处；时间性内容不进档案。
- **每份档案固定 7 段**（段号不变）：这是什么 / 怎么用 / 规则与逻辑 / 可调参数 / 代码在哪 / 已知问题 / 变更记录。
