## 1. 这门生意（2026-09-18 **用户口述**，已落盘）

**一句话**：在**微信视频号**发短剧视频，视频挂载**剧场小程序**；观众点进去看短剧、
在剧里看到**广告**，账号就有**广告流水**，用户拿其中的 **40%~50%**。

> ⚠️ **关键：收益来自"广告流水分成"** —— 不是播放量、不是拉新注册、不是充值分成。
>
> 🧭 **角色定位（用户 2026-09-18 当场纠正，务必记住）**：
> **用户是"做短剧推广的"（推广方 / 分发侧），不是"做短剧的"（版权方 / 做剧侧）。**
> → 凡是看到「机构授权」「自营账号」「版权方」「小程序开发者」这些词，**都不是用户的位置**。
> → 三种角色的对照表见 `docs/视频号算法与短剧分发机制.md` §0。
> → 这条是 AI 讲错一次之后用户明确纠正的，**不要再搞混**。

### 1.1 完整链路

```
【准备·一次性】开通视频号 → 实名认证 → 报白（剧场-小程序）→ 小程序里有可挂载的短剧
【选品】选剧 → 找素材 → 把素材传进软件
【生产】素材入库 → 做模板 → 模板 + 原素材 合成 → 剪映导出成片
【发布】小v猫（外部软件，别人做的）批量发布到视频号     ← ⚠️ 不在本软件里
【收钱】观众刷到 → 点链接看短剧 → 剧中插广告 → 广告流水 → 分用户 40%~50%
```

> **注（2026-09-18 用户说明）**："模板 + 原视频合成成片"是**简化说法**，
> **具体怎么合成，以「成片草稿生成器」的代码为准**（AI 正在补查，补完写进 §4）。

### 1.2 能挂哪些剧 + 挂链接 / 不挂链接

#### 能挂哪些剧 = **小程序说了算**（重要上游限制）

- 报白（剧场-小程序）之后，**小程序提供了一批可挂载的剧**。
- 发视频挂载剧集时，**只能在这批里选** —— **不是想挂哪部就挂哪部**。
- → 所以"选剧"分两层：**小程序给了一批** → 用户从这批里挑。
  **改任何跟"选剧 / 剧集清单"有关的功能，都要记得这个上游限制。**

#### 同一个剧，可能挂链接也可能不挂

同一个剧集，发布时**可能一半挂链接、一半不挂**，也可能全挂——**不固定**。

| 类型 | 怎么引导观众 |
|---|---|
| **挂链接的** | 直接点进小程序看剧 |
| **不挂链接的** | 靠**封面 / 简介 / 话题**引导观众去"**主页置顶**"看剧 |

- ⚠️ 用户原话：不挂链接的那类，**内容有可能不是这部剧**，但封面和话题仍用这部剧
  （用户自述"挂羊头卖狗肉"）。
- → **这是刻意的经营策略**。以后改功能时**不要"顺手纠正"它**，也不要拿它做"数据一致性"的理由去改。

## 3. 核心链路：软件一天在干什么

```
①爆款素材  →  ②模板草稿  →  ③成片草稿  →  ④剪映导出  →  ⑤小v猫发布  →  ⑥收益采集
  素材库       生成剪映草稿     +原素材合成     模拟键鼠/UIA    外部软件      定时抓取
```

| 环节 | 软件里的位置 | 干什么 | 硬规矩 |
|---|---|---|---|
| ① 素材 | `素材扫描` / `materials` | 把爆款素材扫进库、算特征 | 扫进"已使用"目录的素材**不要搬回去** |
| ② 模板 | `template_engine` | 生成剪映草稿（轨道 T01/T02/T03/T09/T10/T11） | 总时长**固定 180 秒**，代码强校验；规则见 `docs/V2模板草稿轨道规则.md` |
| ③ 成片 | `final_engine` | **模板 + 原素材** 合成 | 结构只有 4 种插片组合；"一爆款一成片" |
| ④ 导出 | `v2_exporter` + `windows_automation` | 模拟键鼠操作剪映导出 | ⚠️ **高危区**，也是**产能瓶颈**（1~2 分钟/条）。有防误触保护（输入租约 + 双 ESC）；不可变 Export Attempt |
| ⑤ 发布 | **小v猫**（外部软件） | 批量发到视频号 | ⚠️ **不在本软件里**；本软件只登记结果（`publish_records`）。发布前 vs 发布后，清理规则不同（见 §5） |
| ⑥ 收益 | `v2_revenue_service` | 定时采集四个平台收益 | ⚠️ **抓公开网页，站点改版即失效**（长期风险） |

**人工检查**：成片要**人看过才算数**（`awaiting_human_check`）。这是流程里的正式一环，不是可选动作。

### 3.1 「模板 → 成片」到底怎么合的（2026-09-18 读代码确认，等级 1）

> ⚠️ **先说结论：用户说的"模板 + 原视频合成成片"是准确的**，不是外行话。
> AI 一度以为"模板和成片是两条互不相干的产线"，**那是错的**。以后不许再怀疑这条。

**一句话：模板当"外框"铺满全片，中间挖个洞，把爆款塞进去。**

```
① 模板草稿（180 秒，T01 决定中央窗口的位置和大小）
      ↓ 剪映导出
② 模板 mp4   ← 落在「模板目录\日期-账号-剧集-模板.mp4」
      ↓
③ 成片草稿生成器（final_engine）：
   · 把模板 mp4【循环铺满】整个成片（音量 0）
   · 用反转蒙版在【中央挖掉一条整宽横带】
   · 把【爆款】放进挖出来的窗口
   · 加中插 / 尾插
   · 加 6 张真人图片（2×3 排布，透明度 0.02，肉眼几乎看不见）
   · 加 2 个画面特效 + 调色 + 账号名 + 两条合规提示 + BGM
      ↓ 剪映导出
④ 成片 mp4   ← 这才是拿去发布的
```

**防跑偏要点**：

1. **模板 = 包装外框。** 它自带的**照片墙、贴纸、祝福语/引导语**，最后是**以像素形式**留在成片的**上下两条边**里的
   —— 成片**不会重建这些轨道**，只是把模板那段 mp4 当图层铺上去。
2. → 所以 **改照片墙 / 改贴纸 / 改文案 = 改「模板」，不是改「成片」**。
3. 模板中央窗口里原本的内容，在成片里**看不见**（那条横带被整宽挖空）。
4. **成片自己的文字只有 3 条**：账号名、"影视效果请勿模仿"、"内容由AI制作"。
5. **缺模板 mp4 直接报错** —— 模板是成片的**硬前置**，不是可选项。
6. **两步产物**：先出**剪映草稿**（引擎自己**不渲染 mp4**），再由导出队列驱动剪映导出 mp4。
   （`render_finished_video_ffmpeg.py` 那个 ffmpeg 直渲脚本**不在生产链路**里，别被它误导。）

> ⚠️ **未实证（❓ 等级 1）**：以上全部是从代码读出来的，**没有人肉眼核对过成片草稿**。
> 建议做一次"生成成片草稿 → 在剪映里看一眼"的目视验收 → 升级到等级 3。

## 5. 硬规矩（不能破的）

1. **状态由后端算，前端只显示。** 前端不许自己判断任务是什么状态。
2. **数据只有一个来源。** 不许界面直连示例数据 / 绕过 service 层。（⚠️ 现状仍有违反，属技术债）
3. **成片必须经过人工检查**才算数。
4. **文件清理看"发没发布"**：删除剧集（未发布）vs 立即清理（已发布），保留期 24 小时 / 7 天 / 永久三档。详见 `docs/V2文件系统与资源生命周期规则.md`。
5. **改数据库结构必须把 `SCHEMA_VERSION` 加 1**（否则老库升不上来）。
6. **新的界面元素必须复用现有的**，不许自创 UI 体系。详见 `docs/UI迁移规则.md`。
7. **一次只开一个 V2。** 打包版和源码版**用同一个数据库**，双开不会报错但会互相打架（已装守卫）。
8. **改代码必须同步改文档**，同一个提交。（这条是对 AI 的，也是对项目的）

### 剪映那套（重点，也是已知没跑通的）
