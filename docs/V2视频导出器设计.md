# V2 视频导出器设计

状态：第二阶段真实导出主链已接入，尚待选定真实草稿进行 Windows/剪映现场验收。本文取代此前未落地的 V2 导出器草案；V1 仅提供已验证的低层事实，不是 V2 的流程或状态机模板。

## 已确认业务规则

- V2 每次导出创建不可变的 `Export Attempt`（导出尝试）；重试和重新导出从头开始，不在旧尝试中恢复。
- 双击 `Esc`（退出键）是当前尝试的紧急终止：立即释放键鼠，当前尝试按普通失败处理，记录“用户双 ESC 紧急终止”，不提供 Resume（继续）或场景恢复。
- 成片可启用人工检查模式：自动打开正确草稿后释放键鼠，等待用户在剪映中检查并按 Enter（回车键）；Enter 后重新接管并直接进入导出步骤，不回首页、不重复搜索草稿。此等待可用双 ESC 终止。
- 最终导出提交后，V2 不再自动控制剪映。即使用户自行取消、修改草稿并手工重新提交，系统仍只观察第一次记录的原始输出路径、文件基线和统一超时。
- 只有新源视频出现、相对提交前基线发生变化、文件稳定、`ffprobe`（媒体探测工具）验证通过、原子替换/移动成功且数据库收口成功，才是完成。正式目标存在时允许在新视频验收后替换；不得先删除旧文件。
- 连续失败/超时计数属于全局任务中心的执行器管理层。视频导出器达到连续 3 次才暂停；人工重启后清零。软件重启中的活跃尝试直接记失败，不自动恢复。

## 模块边界

```text
V2 Exporter
├─ ExportRepository       任务、尝试和事件的唯一持久化来源
├─ AttemptCoordinator     单次尝试状态转换；不拥有剪映 UI 细节
├─ InputLease             键鼠接管接口与释放边界
├─ SceneGateway           页面识别、已知页面恢复与高风险动作接口
├─ OutputObserver         提交前基线、文件出现/变化和稳定采样
├─ MediaVerifier          ffprobe 媒体合同
└─ OutputFinalizer        安全替换/剪切移动和数据库收口
```

全局任务中心的 `ExecutorManager`（执行器管理器，在 `server/executor_management.py`）独立记录三个执行器的结果、连续失败数与暂停状态。Exporter 只报告某一次 Attempt 成功、失败或超时，不决定连续三次后的暂停，也不负责人工重新启动。

第二阶段由 `server/v2_exporter/runner.py` 负责一次真实 Attempt：它领取 V2 Job，调用 V1 已验证的 Windows 剪映进程发现、键鼠独占和剪映 5.9 UIA 原语，但不导入 `V1ExportWorker`、V1 导出队列状态机或 ExportSession。提交完成后不再调用剪映，只被动观察记录下来的原始路径；媒体通过后用同目录临时文件安全替换正式目标，再删除原始剪映文件。

真实测试入口为 `tools/run_v2_real_export.py`，或 V2 文件服务的 `POST /api/v2/exporter/jobs` 与 `POST /api/v2/exporter/jobs/{job_id}/start`。该入口只接受用户明确指定的 V2 生产任务和已存在的真实草稿目录；它不会凭空生成生产任务或选择草稿。

## 状态与不可恢复边界

`queued → preparing → awaiting_human_check? → submitting → observing_output → finalizing → completed`

普通失败、超时和双 ESC 均进入 `failed`；它们是终态。仅业务层创建新 Attempt 才能再次导出。未知页面、最终提交是否已生效无法确认等情形也必须结束当前尝试，不允许重复点击最终导出。
