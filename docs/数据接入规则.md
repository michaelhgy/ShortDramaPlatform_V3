# 数据接入规则

## 固定数据流

```text
页面
  ↓
service（服务层）
  ↓
adapter（适配层）
  ↓
api（接口层）
  ↓
V1 backend（后端）
  ↓
SQLite / 文件系统 / 剪映
```

页面不得跳过其中任一层直接访问 V1 API 或本机资源。

## 分层职责

- `src/api/client.ts`：唯一的 HTTP 请求、超时和错误处理入口。
- `src/api/*.ts`：按业务域声明 V1 API 请求；不放页面计算与展示文案。
- `src/adapters/*.ts`：将 V1 返回结构转换为 V2 展示模型；不修改 V1 返回值。
- `src/services/*.ts`：选择 V1 或 Mock、编排多个 API 与 adapter，并向页面提供稳定的功能数据。
- 页面组件：只消费 service 结果。

## 数据语义

- V1 返回格式不是 V2 页面合同；必须通过 adapter 隔离。
- 不存在的数据字段保持未提供，不补造数值。
- 收益无记录、采集失败、`no_data`、`indeterminate` 与零收益不是同一含义。
- 未知状态保留原始值，并在 V2 标记为待核对或未知状态。
- V1 的绝对路径、文件生命周期和剪映路径均不可由 V2 改写。

## 连接方式

- 生产桌面环境使用同源 `/api/v1/...`。
- 独立开发时 Vite 默认代理 `/api` 至 `http://127.0.0.1:8765`。
- 每次新增接入先验证 `GET /api/v1/health`，再验证所需只读 API；写接口须得到任务范围内的明确授权。

## 接入完成条件

一个页面只有在具备以下内容后才能标记“已接入 V1”：

1. API 类型与调用文件。
2. V1 到 V2 的 adapter。
3. 模块 service。
4. 加载、错误、空数据和真实数据状态。
5. 最小接口与页面验证证据。
