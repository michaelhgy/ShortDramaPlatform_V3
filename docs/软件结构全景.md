## 三、每一页的数据从哪来（速查）

| 页面 | 数据来源 | 关键点 |
|---|---|---|
| **顶栏** | `GET /task-center`、`/revenue/daily-account-summary`、`/production-resources`、`/accounts`、`/production-task-summaries` | 5 个接口；资源那路有 **10 秒防抖**（防自激）；**全部静默失败**；读不到就整块不渲染 |
| **生产中心** | `productionService.loadProductionSummary()` → `/production-task-summaries`（失败降级到 `/production-tasks`）；明细 `/production-tasks/{id}/details`；另直接调 `v2Production`/`v2Catalog`/`v2TaskCenter` | **有三层缓存**；⚠️ "更新于"不可信 |
| **任务中心** | `taskCenterService.loadSharedTaskCenter()` → `/task-center` | **和顶栏、生产中心共用同一份快照**；写死的"剪映 IPC 在线(端口49152)"和"三执行器就绪"**永远不变** |
| **资料中心** | `assetsCenterService.loadAssetsCenterSeed()` → **并行 6 个接口** | 收到变更事件时：带编号→只刷那一项；`resource_changed`→只刷资源；**其他→6 个接口全量重取** |
| **数据分析** | `revenueAnalyticsService` → `/revenue/source-data` + `/collection-logs` + `/daily-account-summary`（+明细 `/video-details`） | **单例请求变量与筛选条件无关** → 切时间范围可能拿到上一段的数据 |

| **参数中心** | `/engine-parameters` + `/production-resources` | 挂载读一次；**不订阅任何刷新** |
| **设置页** | `/settings`、`/drives`、`/local-vision-ai/status` | 挂载读一次；**不订阅** |
| **工作台两版** | 假数据（`mockData.ts` / `exploreMockData.ts`） | 按用户口径**不算 bug** |

## 四、结构上的 6 个根本问题

### 问题 1：**"切页签"就是现在最主要的刷新手段**（最重要）

`App.tsx:242-336` 是一串条件渲染 —— **只渲染当前页签，切走就卸载**（组件内 state、定时器、订阅全部销毁），切回来**重新挂载**（所有"挂载时加载"再跑一遍）。

→ **用户"切来切去"，其实是在手动刷新。**
→ **任何"缓存页签"的改动都会顺手拿掉这个隐式刷新，必须补上显式刷新。**

### 问题 2：**统一刷新机制只覆盖了一半**

只有 5 个组件订阅；**工作台两版、参数中心、设置页、微信指数**都没接。
它们靠"挂载读一次 + 手动按钮"，所以**改完东西别的页面不知道**。

### 问题 3：**同一份数据被多处重复拿，还各存一份**

- 任务快照：**顶栏 + 任务中心 + 生产中心**三处各拿
- 生产中心摘要：`productionService` 和组件**各存一份内存副本 + 写同一个 localStorage key**
- 缓存一共 **5 套**，互不知道对方

### 问题 4：**8 套计时器各跑各的**（见 §2 总表）

### 问题 5：**"看起来对，其实是写死的"**

| 位置 | 写死的东西 |
|---|---|
| 任务中心 | "剪映 IPC 通信：在线 (端口 49152)"、"三个执行器：就绪"、详情抽屉里的监听端口 |
| 设置页 | "目录状态：正常"（setter **从未被调用**）、诊断报告里的 `SQLite 3.42 / Latency 3ms`、自检**无条件**报"全部通过"、日志目录指向 `C:\Users\Administrator\...` |
| 生产中心 | "更新于 HH:mm:ss" |
| 任务中心空态 | "未找到匹配的任务卡片 / 请尝试切换筛选条件"（实际是后端没起来） |

### 问题 6：**`settings_changed` 事件"发了没人听"**

`dataChangeEvents.ts:63-75` 的区域白名单里**没有这个类型**。所以参数中心保存完，设置页不会更新，反之亦然。

## 六、给"应该怎么做"的输入

结构已经清楚，方案（`docs/刷新大修-方案.md`）需要据此校正这几点：

1. **切页签重建这件事必须正面处理** —— 要么保留它当刷新手段并明确声明，要么改成缓存页签 + 补显式刷新（**不能含糊**）。
2. **统一层必须覆盖全部 8 个页面**，不能只覆盖 5 个。
3. **缓存要收成一套**，并引入"新鲜度"概念（现在 5 套都没有过期时间）。
4. **写死的状态文案要清掉**（它们和"状态一律以后端为准"直接矛盾）。
5. **"还没实现"的不要混进"坏了"里一起去修** —— 分开排期。
